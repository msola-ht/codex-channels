# Codex WebUI 前端

`codexc webui` 的本地指标与低风险设置前端。Vite + React 19 + TypeScript，UI 组件全部来自
shadcn（`npx shadcn@latest add` 安装），业务层只做组件组合与数据编排。

## 开发

```bash
npm install
npm run dev        # Vite dev server（API 走 /api/v1，需同时运行 codexc webui）
npm run build      # 产出 webui/dist，由 codexc webui 托管
npm run lint       # oxlint
```

## 结构

```text

.npmignore  覆盖本目录的 Git 忽略规则，确保构建后的 dist 进入 npm tarball
src/
  lib/         API 客户端、令牌存取、共享类型转出与格式化；api-polling.ts 管理请求结束后的刷新计时、页面可见性和设置页恢复事件的延后补查，server-time.ts 管理服务端时钟推进与恢复页面后的校准调度，format.ts 统一服务端时区展示，trend.ts 按服务端日期补齐日图表并呈现单日小时统计；metrics-query.ts 统一查询参数和逐层跳转地址，overview-state.ts 保证控制台快照属于当前加载批次，account-refresh-state.ts 投影 OpenAI 当前周额度、Credits 余额和重置券到期明细，并管理有界手动查询失败记录、有界并发查询、逐账户结果交付、观测时间合并及 DS、OCG、CCG、Cline Pass 账户快照时效，traffic-state.ts 隔离不同转储查询的结果并生成精确关联地址，i18n/ 存放中英文界面文案字典与取值函数
  hooks/       数据 hook（useApi 统一 loading/error/refetch，支持按当前状态更新和账户观测时间合并，useApiPolling 复用自动刷新调度，use-dashboard 整批加载概览、趋势和热力图，use-server-time 在页面呈现前初始化服务端时区，并通过上下文共享已校准时间基准）、use-metrics-query（URL 筛选/排序/分页）、use-traffic-query（调用详情页 URL 提供商、批次筛选、独立明细提供商/批次与分页）、use-metrics-export（可取消请求导出）、use-traffic（转储列表与明细）、Relay 服务管理 use-relay-service-management（统一手动、页面恢复及任务完成刷新）、Relay Key 管理 use-relay-management（复用确认 Hook）、use-relay-queue（队列页面挂载期间的 SSE 推送与有界快照刷新），设置管理（共用版本化预览/确认状态机，use-settings-draft 按字段保留未提交草稿）、全局货币上下文与 use-translation（按当前显示语言翻译界面文案）
  pages/       relay-queue-page 独立实时请求队列页；thread-subagents-page 组合全部子代理和所属会话的关联子代理独立页；model-management-page 组合提供商、账户与凭据、模型配置、上下文与压缩四个独立路由，channels-page 组合渠道配置和消息展示，settings-page 组合常规、权限、网络、数据、服务五个子页；概览、会话、会话详情、请求、错误、调用详情、渠道投递队列、模型转发（独立 Key 管理，中文用途名称及居中弹窗，手动刷新运行状态）、设置（只负责组合设置域组件）
  App.tsx      路由布局与页面级懒加载，通过轻量配置读取共享调用采集开关以控制转储入口，数据设置保存后主动刷新开关，保留页面切换间的控制台已应用范围及有界账户手动查询失败记录（不保存账户快照）（令牌登录由 AuthGate 与 main.tsx 启动入口协作）
```

令牌登录：服务端配置访问令牌时，API 返回 401 会显示令牌输入页；令牌存入浏览器
`localStorage`，重新打开浏览器仍可复用，也可用 `?token=` 查询参数（放在 `#` 前或 HashRouter 路径中均可）打开页面自动登录。
该令牌同时用于指标读取和设置页的低风险预览/修改。
持久存储不可用时尝试会话存储；两者均不可用或写入后仍只能读到旧令牌时，登录页明确报错，不刷新页面。
查询参数中的令牌先从当前 URL 清除，保存失败同样回到登录页。手动验证限时 30 秒，离开登录界面会取消请求；401/403 与服务故障分别提示。

`components/layout/page-recovery.tsx` 提供非法地址与页面渲染失败的恢复入口；`App.tsx` 在会话路径解码边界拦截非法编码，并按路由重置页面错误边界。

全局深色/浅色主题默认深色，右上角按钮切换，选择存入浏览器 `localStorage`
（`next-themes`），刷新后保持。

API 响应类型不是前端手写镜像：`src/lib/types.ts` 只转出
`scripts/webui-api.ts` 的共享声明，服务端与前端使用同一份类型。

概览错误组保留后端的来源与错误码，使用与请求列表相同的原因解释，React 标识包含全部分组维度。失败阶段在读取接口中为稳定标识，由 `formatTrafficFailureStage` 按当前语言解释；原始诊断保留标识本身。

`src/lib/request-failure.ts` 统一请求列表、错误列表与调用详情的错误分类：优先使用受控错误码，再使用实际 HTTP 状态（含 408 超时），不从上游原始文本推断主原因。原生代理指标还包含上游错误字段，除本地传输失败分类外，先使用实际 HTTP 错误，再解释上游标识。生成完成后的交付异常单独解释；`format.ts` 复用分类生成短标签，调用详情使用同一分类的详细说明。原始诊断保留在详情中。

版本化设置 Hook 保留写入结果的生效方式、审计降级和回读一致性，设置页、模型配置页与渠道显示页用共享反馈组件展示双语提示。写入后读取权威快照，不把操作返回值合并到当前值；读取失败时保留已有数据及操作警告并阻止继续修改，刷新成功后恢复。未知写入结果先提示核对配置，不自动重试写入。
提供商编辑取消保存预览时保留包括新输入 API Key 在内的内存草稿；明确退出编辑或保存成功后清除 Key，取消确认不会把替换凭据改成保留旧凭据。

模型默认档位按后端投影的 `fastEnabled`、`ultrafastEnabled` 与精确模型目录分别生成选项；原始配置中的禁用档位保留为不可选显示，Standard 始终可用于退出加速。预览和确认都由后端重新读取对应开关与受管策略，不由前端推断功能默认值。

模型配置页的 `components/settings/openai-model-catalog-card.tsx` 展示 `$CODEX_HOME/models_cache.json` 中的 OpenAI 模型目录，
名称仅显示 `display_name`；内部操作仍按模型 ID 定位。展示当前上下文／最大上下文、思考等级（悬浮查看所有等级）、加速等级和自动审批（任一审批模式有非空提示文本显示声明，否则未声明，悬浮查看各模式），列表不展示审批正文或将其当作已启用状态或当前权限。缺失值显示未知，实际可用性以账户为准。
缓存记录时间位于标题栏右侧，客户端版本以标题旁的标签展示；窄屏允许换行。两者仅代表文件元数据，不代表运行中服务的实际生效状态，加载或读取失败时隐藏旧元数据。
模型目录数字列右对齐并使用等宽数字，模型名称与表头对齐；操作按钮使用「调整上下文」区分工具能力标签。悬浮标签通过 Base UI `render` 直接组合 Badge，保留键盘焦点样式；版本与时间说明统一使用 Tooltip。上下文选择使用 FieldSet／FieldLegend 和 ToggleGroup，自定义值使用独立 Field，预设显示实际 Token 数值；页脚按钮与说明在宽屏同排、窄屏纵向展示。
`components/settings/openai-model-details.tsx` 提供点击模型名称打开的只读侧栏，按四组展示白名单能力字段，「使用指引」和「运行特性」默认折叠。25 项白名单字段中的输入类型、有效上下文比例、工具搜索支持状态和补丁工具类型在模型列表展示，侧栏不重复；「特性」列分别显示工具搜索与文件编辑的名称和支持状态，网页搜索类型仅在侧栏展示。原始字段和值通过悬浮展示，缺失与 false 分开。详情绑定缓存范围和模型 ID，读取失败或模型消失不复用旧数据；刷新对比复用该组件直接显示全部变化字段，不隐藏已移至列表的字段。加速列从目录说明中提取明确的 `Nx speed` 倍率，只展示档位和倍率，不提供悬浮备注或下划线，不推断费用或实际性能。
侧栏的「模型提示词」页由 `components/settings/openai-model-prompts.tsx` 通过独立管理 GET 接口按模型与缓存修订加载，在九个用途分组中逐条展开纯文本。切换模型、修订或关闭详情时卸载并取消读取；缓存变化后要求重新读取目录，缺失字段不冒充内置默认提示词，正文不进入列表、刷新对比或浏览器持久存储。
`hooks/use-openai-model-catalog.ts` 通过共享 API 类型读取 `/api/v1/management/models/official`，编辑仅提交选中模型的 `context_window`，
复用版本化预览、确认、备份和写后回读。“刷新当前配置目录”是唯一目录刷新入口，确认后运行 `codex debug models`，让上游自行管理缓存；不在预览阶段执行，也不将可能回退的 stdout 覆盖缓存。执行后展示可见字段的前后对比，明确区分文件变化与远程成功，并提示输出的可见模型信息与缓存不一致。
页面顶部刷新仍只重新读取。所有写入共用互斥状态，编辑草稿和待确认期间暂停页面自动刷新；加载时隐藏旧目录，读取失败清除旧数据并提供独立重试。
保存结果说明备份、回读未知、审计降级与运行中服务不会立即更新，官方后续刷新可能覆盖手动修改。
`lib/openai-model-cache-edits.ts` 仅在本标签页 `sessionStorage` 保存至多 20 条已确认编辑的缓存范围、模型 ID 和上下文数值；
再次读取同范围发现值变化或模型消失时提示可能被官方刷新覆盖；刷新目录后保留该范围跟踪。
未知版本、畸形记录或存储不可用时提示跟踪不可用，保留原存储，不影响缓存编辑；不同标签页不共享跟踪。

`components/settings/model-catalog-columns.tsx` 将 OpenAI 和第三方目录放在一张表中，共用一个表头和横向滚动容器，各提供商用表内分组行区分。仅模型名称列固定为 18rem，其他列自动分配宽度，表格占满容器，窄屏在容器内横向滚动。长名称省略但保留完整无障碍名称与详情入口。名称旁不显示默认模型标签，默认模型的移除保护保留。数值右对齐，加速不使用悬浮说明。「特性」列用两行纯文字显示「工具搜索：状态」「文件编辑：状态」：读取 `supports_search_tool` 和 `apply_patch_tool_type`，不使用标签；补丁类型仍可悬浮查看；网页搜索类型 `web_search_tool_type` 保留在侧栏。OpenAI 刷新和自定义目录编辑入口放在对应分组标题中，状态与结果保留在所属分组。模型行操作统一收进「操作」下拉菜单；第三方目录提供调整上下文、更新模板和移除模型，OpenAI 目录提供调整上下文。保留原有禁用和确认流程，移除受限原因直接显示在菜单项内；模板和上下文弹窗关闭后焦点返回行内菜单按钮，取消预览确认则返回编辑弹窗。
官方目录按缓存展示声明；自定义目录额外读取 `declaredCapabilities`，思考、图片、工具搜索和 `apply_patch` 区分未知、支持与不支持，未声明的能力显示未知，不把编译后的安全禁用值冒充显式不支持。
模型页要求提供统一目录渲染回调；第三方操作错误与保存反馈放在目录下方，避免误归入托管默认值设置。
第三方模型区展示 `modelCatalogs` 派生的启用目录，每个 Provider ID 的账户目录分别作为操作目标，
点击模型名称复用能力详情侧栏；精确模型 ID 在侧栏展示，账户范围在目录标题展示。
详情按提供商、精确模型 ID 和目录修订绑定，目录修订变化、读取失败或模型消失时不复用旧详情。
第三方提示词通过 `/api/v1/management/provider-model-prompts` 独立读取，复用纯文本分组展示；模板来源和采样参数仅在此响应提供时展示，不进入列表或浏览器持久存储。
`components/settings/provider-model-template-dialog.tsx` 提供账户单模型的来源选择、提示词／能力范围和前后差异确认。确认期间保留编辑会话，取消不重置草稿或重新获取候选；保存回读后恢复模型入口焦点。`/api/v1/management/provider-model-templates` 获取有期限的候选，`model.template.update` 复用 Provider 设置的预览、一次性确认与写后回读。旧模型无关联时不自动选择来源；官方共享目录不开放该操作，候选正文不持久化到浏览器。
旧修订提示重新读取目录；该入口只读取本地目录。账户模型上下文通过模型表格的“调整上下文”入口编辑，详情侧栏保持只读。
本地移除复用 `management.mutate/confirm`，
确认页将模型名称、ID 与影响账户和简短提醒分区展示，以分隔线和留白区分，不折叠说明；
提醒保留共享 Relay 授权、CLP Relay 独立目录、历史引用、备份和手动重启要求，具体重启命令在保存结果中展示；
默认模型、最后一个模型以及不支持裁剪的来源在界面禁用，并由后端锁内复核。
自定义模型编辑复用既有能力表单，通过 `model.custom.save` 仅提交模型定义与默认值，
不提交连接或凭据；已有模型不可在编辑中隐式删除或重命名，移除走独立预览。
新增模型先读取 `/api/v1/management/provider-model-drafts` 选择模板，默认固定 OpenAI 底座，可选 DeepSeek；失败时须重新读取，关闭编辑取消读取。模板仅作为下一次添加的起点，四项能力从未知开始，高级参数默认折叠，预览显示来源、三态声明及实际指令。模板提示词和采样字段保留在草稿中；切换新增候选不覆盖已填写或已有模型。
CCG/OCG 的添加、模板和选择，以及 CLP 的显式联网更新继续指向 `codexc setup`。
独立上下文路由只管理 Codex 全局窗口与自动压缩，账户模型窗口在模型表格内预览并确认保存。

## UI 组件规范

- 组件使用官方 `base-nova` 样式和 `@base-ui/react`，类名合并统一使用 `cn` 包。组合触发器使用 `render`，Select 显式提供 `items` 的值与显示标签，ToggleGroup 的受控值使用数组；不保留 Radix 调用接口。
- `components/ui/toast.tsx` 提供 Base UI 通知容器，`toast-manager.ts` 提供共享通知管理器；`App.tsx` 挂载容器，默认 3 秒关闭并本地化关闭按钮。成功通知短暂显示，错误及需要处理的警告仍保留在操作区域。

- 基础 UI 组件放在 `components/ui/`，只通过 `npx shadcn@latest add` 安装或升级，
  不手写基础组件（按钮、卡片、表格、弹层等）；
- 业务组件按领域分目录组合：`components/layout/`（布局与鉴权）、
  `components/overview/`、`components/threads/`、`components/metrics/`（指标区块），
  `components/requests/`（请求明细数据表格），只做组件组合与数据编排，不直接发请求；
- 数据获取统一走 `hooks/`（`useApi` 系列，集中 loading/error/refetch；`use-model-traffic-settings` 共享布局的调用采集开关及转储可见性，自动刷新不探测服务状态；设置变更共用版本化预览/确认 Hook），组件不直接
  `fetch`（唯一例外：`AuthGate` 在提交令牌前用原始请求验证一次）；API 路径统一从
  `src/lib/api.ts` 的 `API_PREFIX` 拼接；
- 类型从 `src/lib/types.ts` 转出，格式化（Token/时间）放 `src/lib/format.ts`；已本地化的时间预设标签放 `src/lib/i18n/messages.ts`，
  控制台与各查询页复用 `components/metrics/range-selector.tsx` 的时间及日期控件；
  `use-metrics-query` 读取 Provider 筛选选项并保留多选 URL 参数，`query-filters` 使用勾选下拉；
- 界面翻译通过 `hooks/use-translation.ts` 接入，字典与取值函数位于 `lib/i18n/`，语言状态由
  `hooks/language-context.ts` 与 `language-provider.tsx` 管理。翻译约定、UI 文案参数、覆盖阶段及验收统一见
  [本目录国际化维护约定](#国际化维护)。
- 页面（`pages/`）只负责组合区块与路由参数，业务规则不写进页面；
- 遵守 oxlint 规则：Hooks 必须在组件顶层调用，文件默认只导出组件
  （`react/only-export-components`）。

详细行为见 `docs/webui.md`。

`pages/logs-page.tsx` 组合「调用监控 → 服务日志」（`#/logs`）；`components/service-logs/service-logs.tsx` 使用官方 `components/ui/tabs.tsx` 切换服务，搜索与行数、级别和刷新设置同排展示；`log-results.tsx` 组合撑满页面剩余高度的结构化表格、详情和阅读时的快照保留，日志在表格区域内滚动；`lib/service-logs.ts` 解析已脱敏的 Pino/tracing 日志及 journald 白名单元数据、合并来源并筛选，不猜测未知级别。`hooks/use-service-logs.ts` 复用统一请求与可见页面刷新调度，切换查询隔离旧结果，离开页面取消读取。

`pages/delivery-page.tsx` 组合渠道投递队列独立页面，由左侧「消息渠道 → 渠道投递队列」进入 `#/delivery`；`components/delivery/delivery-queue.tsx` 提供精简表格列表、状态计数筛选、行内内容摘要、游标分页和勾选批量重试/忽略确认；`hooks/use-delivery-queue.ts` 复用管理确认 Hook 与 `hooks/use-queue-events.ts` 的 SSE 变化订阅，筛选或翻页时重建当前查询，离开页面时取消请求。

控制台、请求与错误列表区分首次加载和后台刷新：`loading` 仅用于当前查询没有结果时的占位，`refreshing` 用于刷新按钮和操作限制；同查询刷新保留内容，切换查询不展示旧范围结果。管理任务的 `notificationError` 独立于读取错误，通知中断不阻止已成功读取的终态触发关联刷新。

## 自定义模型能力设置

`components/settings/provider-settings-management.tsx` 按模型提供图片、思考、`apply_patch` 与
`tool_search` 的手动声明；思考支持开关控制既有思考等级与默认值。新增模型不会预选补丁或搜索工具，
切换 Chat Completions 也不会改变模型的工具声明。
统一模型表格为 OpenAI、受管与自定义模型提供行内上下文编辑入口，官方共享目录保持只读。
`components/settings/model-context-window-fields.tsx` 复用窗口表单，提供 272K、372K、500K、最大值及自定义输入；
K 按十进制 1000 Token 展示，超过模型上限的预设不可选。`lib/model-context-window.ts` 负责共用预设选择与整数校验，

携带当前目录 revision 进行窄更新，复用预览确认；整组自定义模型高级编辑入口保留。
独立上下文页面只保留 Codex 全局窗口与自动压缩设置。
预览、确认写入和回读保持精确 Token 数，不按整数百分比换算。模型选择以 Provider ID 与模型 ID 联合定位，同名模型不会选中其他账户；默认模型、思考等级、上下文和本地移除均按账户目录独立保存。

`components/settings/custom-model-details.tsx` 复用共享 API 的模型元素类型，组合基本响应参数与可展开的高级参数。
基本区编辑模型描述、最大窗口、各思考等级说明、图片 original 细节、verbosity 与默认值，以及独立的思考摘要参数。
Chat Completions 同样开放全部能力选择与保存；切换接口保留已有声明，并说明当前请求转换对 original、verbosity 和摘要参数的限制。
关闭图片输入同时关闭 original；编辑等级文本时保留说明草稿，在提交预览时按最终等级清理对应说明，避免逐字输入造成丢失。DS 模板副本的当前与最大窗口独立编辑，不再提供上下文跟随。高级区保留 instructions 原文，
编辑有效窗口比例、可留空的自动压缩阈值，以及可恢复默认的 tokens/bytes 截断策略。
确认弹窗逐模型展示这些参数与 instructions 全文，缺省值明确说明；所有文案均提供中英文。

每个模型分别提供 `apply_patch` 和 `tool_search` 检测按钮，不运行整套能力检测。
`hooks/use-custom-model-capability-probe.ts` 将单项请求及结果绑定当前草稿，草稿变化、取消或关闭编辑时
中止请求并阻止旧结果覆盖。检测使用手填的默认思考等级，未声明时使用 `none`；每次最多 3 个上游短请求，
服务端总限时 45 秒，客户端限时 50 秒。请求可能产生费用，必须由用户主动点击。

明确支持或不支持的结果可以回填对应的工具字段及连接凭证；未确定或取消的结果不能回填。
其他模型能力保留手动值，保存继续使用版本化预览与确认。`lib/custom-model-probe.ts` 只将固定原因映射为
`lib/i18n/messages.ts` 的中英文文案，不展示未经指定的上游响应。

## 国际化维护

当前页面覆盖与剩余验收见 [WebUI 指南](../docs/webui.md)。


界面语言在重新加载后恢复偏好；不改变服务端时区、统计、查询、权限、确认或导出数据。
CLI、渠道消息、Codex 协议和用户内容不在本地化范围内。不翻译模型/提供商 ID、Thread/Turn ID、
配置键、API 参数、日志、调用转储和用户输入。网关返回的原始账户数据保持原样。

中文普通标签使用“提供商”“会话”“轮次”，英文使用 Provider、Thread、Turn；
ID 的标签跟随语言，实际值不变。`Turn State`、`X-Codex-Turn-State` 等协议名称保持原样。

### 翻译维护顺序

中文是源文案。后续获授权的页面或文案变更按以下顺序执行：

1. 提取中文、键、占位符及场景，复用已有键，覆盖加载、空态、失败、重试和可访问名称。
2. 执行者直接生成英文候选并复核，不调用外部翻译服务；中文变更时同步检查既有英文。
3. 经复核后接入字典和组件；不复制中文充当英文、不放宽键或占位符门禁。
4. 验证中英文切换、偏好恢复、英文布局和交互状态保持，记录本批实际覆盖与缺口。

CI 只校验字典，不自动生成、翻译或回写文案；本地差异报告按需使用。
语言切换不得重新提交操作、清空草稿、关闭待确认操作或改变授权范围。

### 本地翻译工具与 CI 校验

以下工具已实现并经本地验证：

- [`webui/i18n-glossary.json`](i18n-glossary.json)：中文术语、英文建议、原样保留项与翻译规则。
- [`scripts/webui-i18n.mjs`](../scripts/webui-i18n.mjs)：使用现有 TypeScript 解析器静态读取字典对象，
  不导入或执行字典模块。仅支持对象和字符串字面量，拒绝展开、计算属性与动态值。
- `npm run i18n:check`：检查空文案、中英文键与占位符；进入本地提交和 CI 共用的 `verify:commit`。
- CI 仅通过共用门禁校验字典，不自动生成报告、调用翻译服务或回写译文。

在仓库根目录运行：

```bash
npm run i18n:check
npm run --silent i18n:report -- --base main > /tmp/webui-i18n-report.json
```

`--base` 必须是本地可解析的 Git 提交或引用。第一次引入字典时，基线文件不存在会将所有源键列为新增；
逐批审查可指定上一批提交，避免把此前已完成的文案重复列入。报告读取当前工作区，可用于审查未提交修改。

报告条目包含 `new`、`source_changed`、`translation_changed`、`missing_translation`、`removed`，
保留前后中文和英文值，以及 `needsTranslation` / `needsReview`。中文变化即使已有英文也标记待复核；
报告不能判断译文质量，不能把英文“存在”视为翻译已完成。结构问题单列在 `issues`，由检查命令阻止提交。

报告仅供本地按需审查。

### 实现约定

- 复用现有 React 语言上下文，内部值保持 `zh` / `en`，页面 `lang` 分别为 `zh-CN` / `en-US`。
  默认中文，偏好写入浏览器 `localStorage` 的 `codex-webui:language`；非法值或读取失败时使用中文，
  写入失败不妨碍本次页面内切换。此偏好不是 Gateway 配置，不写入 TOML 或数据库。
- 字典位于 [`messages.ts`](src/lib/i18n/messages.ts)，中文为键结构基准，英文通过类型检查
  保持同一结构。组件使用 [`useTranslation`](src/hooks/use-translation.ts)，按业务区域组织键。
- 文案优先使用完整句子与 `{name}` 占位符，避免拼接会因语言顺序不同而失效的片段。
  当前数量说明采用不依赖英语单复数词形的表达；后续出现复数需求时补齐规则并核对展示。
  当前取值函数不支持 ICU 或自动复数选择，不得将这些能力视为已实现。
- 动态键必须来自明确的类型或映射，例如导航、日期范围和错误码。静态扫描未识别的键应人工核对，
  不能仅凭扫描结果判断其无用。未知内部错误使用本地化通用提示，不把原始异常直接当作翻译文案。
- 已显示的错误与状态保存结构化标识，在渲染时翻译，避免切换语言后残留旧语言。
  字典中的用户可见文案通过 React 文本渲染，不引入 HTML 翻译或字符串插入 DOM。
- 设置确认使用文案键和占位符保存字段标签，确认框渲染时再翻译；配置预览原值保持不变。
  工具访问设置按配置路径翻译固定标签，应用、站点、MCP 与插件标识保留原值。
- 日期与数字复用项目格式化函数，时间仍以服务端时区为准。后续调整格式时明确语言格式与时区的区别，
  验证日期边界、零值、缺失值与单位，不因翻译改变原始数据。
- 沿用现有 shadcn 组件。基础 UI 组件通过文案参数接收可访问名称，业务组件负责翻译，
  避免基础组件依赖应用语言上下文。Sidebar 的 `mobileTitle` / `mobileDescription` 和
  SheetContent 的 `closeLabel` 由调用方提供。英文文案更长时检查换行、截断、焦点和窄屏布局。

### 验证与交付

中文提取阶段先验证源文案、键设计、占位符和不翻译边界，并记录尚未接入的组件与缺失英文。
以下要求用于英文候选复核后的双语交付；候选来源按当前批次约定，不因门禁擅自改变翻译方式：

1. 中英文键结构、占位符名称与实际调用一致，动态键有明确来源；已覆盖区域没有遗漏的界面文案。
2. 实际切换语言后，已挂载组件、表头、错误和提示更新；偏好恢复、非法值及存储不可用行为正确。
3. 语言变化不改变数据请求语义、筛选值、分页、关联链接、输入草稿和操作确认状态。
4. 已知错误按结构化标识翻译，未知错误使用通用提示；原始内容保持边界，不误译用户数据。
5. 英文长文案、窄屏布局、关闭按钮、表单标签、焦点顺序和页面 `lang` 可用。

针对性验证入口：

```bash
npm run i18n:check
npm --prefix webui run build
npm --prefix webui run lint
npm run docs:check
```

实际交互、键盘焦点和视觉检查单独记录结果。
普通提交通过现有提交钩子执行按范围选择的 `verify:commit`，开发阶段按实际改动选择检查，不重复运行全量门禁。

`components/settings/relay-provider-models.tsx` 按提供商显示只读模型目录弹窗与目录更新入口。
`components/settings/relay-key-models.tsx` 在 Key 编辑弹窗按提供商分组勾选模型，并为每个所选模型提供跟随客户端、直接选择思考等级及关闭方式二级菜单；关闭菜单仅提供显式参数方式，已有自动映射值仍显示并保留。可跨多个提供商，独立目录更新不扩大 Key 权限。
`components/settings/relay-reasoning-probe.tsx` 在所选模型的检测弹窗中手动对比基线与八种关闭方式；打开弹窗不发请求，开始后最多依次发送 9 次固定短文本、每次请求最多 64 个输出 Token，明确可能计费且不证明内部推理关闭。双协议提供商可选协议，结果仅适用于所选协议；服务端 NDJSON 进度驱动已结束项数、当前方式及渐进表格，不推算虚假进度。缺失指标显示未知，运行时不可采用；仅完整检测中已完成且有可用响应的具体关闭方式可手动采用到该模型草稿，保存仍走原预览与确认流程。
`hooks/use-relay-reasoning-probe.ts` 通过 `/api/v1/management/relay/reasoning-probe` 维护单次检测，将请求绑定编辑 Key、配置版本、模型与协议；取消、关闭、卸载或上下文变化会中止请求并阻止迟到结果覆盖或采用。失败、取消和超时保留已收到的部分行供本次查看，但不可采用且不替换历史完整结果。缓存读写和采用时效统一使用现有服务端校准时钟，避免客户端时间偏差中断合法探测或提前清除记录。前端超时为 140 秒，服务端逐请求与整批预算见 Relay 管理接口。
`lib/relay-reasoning-probe-cache.ts` 仅将完整终态的有限元数据保存到本浏览器 `localStorage` 的 `codex-webui:relay-reasoning-probes:v1`：每个模型与协议一条、最多 20 条、7 天，总编码大小不超过 128 KiB，读取已知有效版本时裁剪过期项。仅存配置版本、模型、协议、开始时间及九种方式的状态、HTTP 状态和可观察指标，不存 Key、提示词或响应正文。读取严格验证版本、键、字段类型、长度、行顺序及数量；异常或未知版本不自动删除或覆盖，存储禁用仅提示且不阻断检测。弹窗重开或页面刷新展示历史时间，不自动请求；不同 Key 可共享同模型和协议的观察，同版本历史可明确标为历史后手动采用，旧版本只读。清除按钮仅删除本功能专用缓存，不影响其他浏览器存储或服务端数据。
`components/settings/relay-model-copy.tsx` 在 Key 列表中提供授权模型 ID 复制菜单、复制结果提示和剪贴板不可用时的手动复制入口。
`hooks/use-relay-catalog.ts` 管理目录下载、一次自动尝试、取消和审计反馈。
`hooks/use-relay-key-editor.ts` 管理 Key 草稿版本、逐模型思考设置、提交参数与一次性结果；移除模型同步清理草稿，新选模型默认跟随客户端。`components/settings/relay-key-table.tsx` 和 `relay-key-dialogs.tsx` 分别组合列表和编辑/逐模型确认/结果弹窗，`pages/relay-page.tsx` 保留页面组合和焦点恢复。
