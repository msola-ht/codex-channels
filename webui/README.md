# Codex WebUI 前端

“消息渠道 → 消息展示”的全局及每个范围提供显示预设：静默、紧凑、详细，以及不可保存的“自定义”识别值。复用 ManagedSelect、应用按钮和双语文案，描述显示管理读取的 computed `display.preset` / `scope.preset`；选择后按“预览并应用预设”进入确认，因此继承值已经匹配也可明确固定本层。确认摘要展示目标、本层支持的全部字段、继承来源及备份、pending 和回退提示。`display.preset` 经单次高风险预览确认与共享配置原子事务，保存后同源读回；取消和 no-op 不写，过期修订拒绝，不循环调用字段 writer。预设不新增 TOML 字段、不改变默认值，也不改日志或调用采集；单独修改字段后重新识别，仍保留逐字段继承。范围仅固定支持字段，微信三项、QQ 群不含 streaming；停用范围不可应用预设。源码尚未部署，浏览器交互与真实平台效果以实际验收记录为准。

常规通知复用既有 ManagedSelect、范围 supportedFields、中英文键与预览摘要，四渠道含微信和 QQ 群均支持。全局 kind `display.routine-notifications` 显式 set boolean/inherit，读取 `routineNotificationsEnabled` 与 `routineNotificationsOverride`（布尔值或 null），缺省开启且不物化；确认令牌、revision、私有备份、取消、未变化与读回沿共享事务。任一渠道启用时有效值改变要求重启 Gateway，否则 reload；隐式 true 与显式 true 互换只 reload，范围数组整体判定。关闭范围与异常、持久 Workspace 回执和 pending 保留边界以 docs/display.md 为准。回退旧版前清除全局及覆盖 routine_notifications，不自动迁移。

请求列表及详情从指标 API 读取 `activity`，与调用列表共用 `formatRequestActivity`，不额外请求调用转储。历史未采集显示“未记录”，有界采集不完整显示“部分可见”。

调用列表“请求行为”列消费 Reader 的 `activity` 摘要，展示本次回复、工具调用及工具结果续传，并保留明确用途分类；不在浏览器解析完整报文或扫描历史消息。未知与部分可见状态独立呈现，工具名只表示响应中的调用声明。

请求表的 `upstreamUrl` 列默认位于模型之后，复用长文本提示；详情读取同一快照。请求和调用列表的地址列限制为 10rem，超宽时省略尾部，悬停或聚焦显示完整值；详情保留完整地址并换行。字段为最后一次实际模型出站的规范地址，历史缺失显示“未记录”，不补查转储或当前提供商配置。表头提示多次调用只记录最后一次，地址只作文本展示。

请求与调用列表在请求方式列使用与“自动审批”相同的标签样式区分“图片生成”和“图片编辑”。调用依据已记录的 HTTP POST 路径识别，请求指标依据持久化的 `imageGeneration`/`imageEdit` 操作类型识别，不根据模型名称猜测。请求详情和操作筛选支持这两个类型；历史未采集的图片请求不补录。图片请求不填充文本 Token 或生成速度，模型名未采集时保持缺失。

`codexc webui` 的本地指标与低风险设置前端。Vite + React 19 + TypeScript，UI 组件全部来自
shadcn（`npx shadcn@latest add` 安装），业务层只做组件组合与数据编排。

“消息渠道 → 消息展示”管理全局与五层范围显示。操作详情新增仅失败或拒绝；子代理显示支持显式开启、关闭与恢复缺省（开启），关闭同时隐藏生命周期与子代理工具操作；完成通知支持关闭成功通知、精简、详细及恢复缺省。消息详情支持基础、详细及恢复缺省（基础），控制上线、完成、子代理与自动审批通过的摘要或明细，独立于日志、调用采集、任务、审批及完成通知开关。界面分别展示存储覆盖、有效值及来源，微信范围支持常规通知、完成通知和消息详情。全局 `display.completion`、`display.subagents`、`display.streaming`、`display.presentation-detail` 与范围修改复用确认令牌、配置修订、私有备份及读回事务；取消不写，缺省不物化。消息详情读取区分有效 `presentationDetail` 与本层 `presentationDetailOverride`，中英文摘要覆盖基础、详细、失败档位和布尔值。消息详情全局有效值改变且任一渠道启用时要求重启 Gateway，缺省基础和显式基础互换只 reload，范围数组整体保守判定。回退前按旧版能力显式清除新增 overrides、全局及覆盖 completion/subagents/streaming/commentary/routine_notifications/presentation_detail，将全局及覆盖 failures 改为旧版支持值，并核对后续修改。源码尚未部署，真实平台显示仍待验收。

流式显示缺省开启，只控制 Telegram、飞书及 QQ 单聊正文增量预览。全局读取返回 `streamingEnabled` 与 `streamingOverride`（布尔值或 null），`display.streaming` 接受显式 set boolean/inherit；微信和 QQ 群范围不显示该选项，QQ 群预览摘要也不宣称继承流式能力。共享 Schema 严拒微信和 QQ 群覆盖中的 true/false，QQ 渠道、账号级配置仅作用其单聊。全局有效值变化且任一 Telegram、飞书或 QQ 启用时要求重启 Gateway，否则 reload；隐式开启与显式开启互换只 reload。不改变上游模型流式、思考、完整正文、附件、授权及原窗口和交付义务。

过程说明使用可选 `display.commentary`，缺省开启且不物化；Telegram、飞书与 QQ（含已支持群）支持五层继承，微信范围严格拒绝并隐藏此字段。它只隐藏明确 phase=commentary 的新过程说明，独立于思考状态及原始推理；未知阶段完整正文保留，关闭时未知阶段增量先缓冲而不预览，待明确 final_answer 或完整 Item 再展示。已准入正文流与已有 Journal 内容继续按原义务收尾，正文、附件、审批、失败、任务和模型保留。全局管理使用 `display.commentary` 显式 set boolean/inherit，读取区分 `commentaryEnabled` 与 `commentaryOverride`（布尔值或 null），中英文预览分开显示存储覆盖、有效值和来源；复用确认令牌、修订保护、私有备份与读回，不确定不重试。有效值改变且任一 Telegram、飞书或 QQ 启用时重启 Gateway，否则 reload；隐式 true 与显式 true 互换只 reload，范围数组仍整体判定。回退前显式清除全局及覆盖 commentary 并核对后续修改。源码尚未部署，平台效果待验收。

`components/settings/provider-directory.tsx` 在 `#/models/providers` 统一展示 OpenAI、受管账户和自定义提供商，按平台筛选，新增入口选择平台；编辑、本平台默认账户、模型配置、联网搜索、切换主提供商和移除均收进行操作菜单，只显示适用操作。主提供商、本平台默认账户与默认模型分别管理，已配置不代表连接可用。模型配置入口携带精确 Provider ID，匹配共享目录时保留目录的账户影响范围；找不到目录时提供查看全部模型的入口。
`components/settings/account-settings-management.tsx` 保留账户草稿、凭据、预览确认及回读职责，`provider-settings-management.tsx` 保留提供商连接、主提供商切换及模型管理职责；目录只组合两者公开的行操作。OpenAI 登录和 CCG 账户仍通过终端配置，命令说明在弹窗中打开；`provider-channel-status.tsx` 保留渠道状态卡职责。

令牌登录：服务端配置访问令牌时，API 返回 401 会显示令牌输入页；令牌存入浏览器
`localStorage`，重新打开浏览器仍可复用，也可用 `?token=` 查询参数（放在 `#` 前或 HashRouter 路径中均可）打开页面自动登录。
该令牌同时用于指标读取和设置页的低风险预览/修改。
持久存储不可用时尝试会话存储；两者均不可用或写入后仍只能读到旧令牌时，登录页明确报错，不刷新页面。
查询参数中的令牌先从当前 URL 清除，保存失败同样回到登录页。手动验证限时 30 秒，离开登录界面会取消请求；401/403 与服务故障分别提示。

`components/layout/page-recovery.tsx` 提供非法地址与页面渲染失败的恢复入口；`App.tsx` 在会话路径解码边界拦截非法编码，并按路由重置页面错误边界。

全局深色/浅色主题默认深色，右上角按钮切换，选择存入浏览器 `localStorage`
（`next-themes`），刷新后保持。

API 响应类型不是前端手写镜像：`src/lib/types.ts` 只转出
`scripts/webui-api.ts` 的共享声明，服务端与前端使用同一份类型。

概览错误组保留后端的来源与错误码，使用与请求列表相同的原因解释，React 标识包含全部分组维度。失败阶段在读取接口中为稳定标识，由 `formatTrafficFailureStage` 按当前语言解释；原始诊断保留标识本身。

`src/lib/request-failure.ts` 统一请求列表、错误列表与调用详情的错误分类：优先使用受控错误码，再使用实际 HTTP 状态（含 408 超时），不从上游原始文本推断主原因。原生代理指标还包含上游错误字段，除本地传输失败分类外，先使用实际 HTTP 错误，再解释上游标识。生成完成后的交付异常单独解释；`format.ts` 复用分类生成短标签，调用详情使用同一分类的详细说明。原始诊断保留在详情中。

版本化设置 Hook 保留写入结果的生效方式、审计降级和回读一致性，设置页、模型配置页与渠道显示页用共享反馈组件展示双语提示。写入后读取权威快照，不把操作返回值合并到当前值；读取失败时保留已有数据及操作警告并阻止继续修改，刷新成功后恢复。未知写入结果先提示核对配置，不自动重试写入。
`hooks/use-management-readback.ts` 统一写入未知判定与快照回读门禁；成功的新快照解除门禁，不抹去历史未确认反馈。版本化设置始终使用它，通用确认 Hook 仅在原有 `trackReadback` 启用时登记写入。
提供商编辑取消保存预览时保留包括新输入 API Key 在内的内存草稿；明确退出编辑或保存成功后清除 Key，取消确认不会把替换凭据改成保留旧凭据。

模型默认档位按后端投影的 `fastEnabled`、`ultrafastEnabled` 与精确模型目录分别生成选项；原始配置中的禁用档位保留为不可选显示，Standard 始终可用于退出加速。预览和确认都由后端重新读取对应开关与受管策略，不由前端推断功能默认值。

模型配置页的 `components/settings/openai-model-catalog-card.tsx` 展示 `$CODEX_HOME/models_cache.json` 中的 OpenAI 模型目录，
名称仅显示 `display_name`；内部操作仍按模型 ID 定位。展示当前上下文／最大上下文、思考等级（悬浮查看所有等级）和加速等级，模型目录表格不展示自动审批列。审批提示词声明仍保留在刷新对比中，不代表已启用状态或当前权限。缺失值显示未知，实际可用性以账户为准。
第三方托管目录的模型行提供“编辑显示名称”，通过 `model.rename` 预览并确认名称与账户范围；只修改显示名称，保留模型 ID。自定义目录在“编辑”弹窗中修改名称。共享官方目录保持只读，目录修订变化时拒绝保存旧草稿。
模型目录以独立的“内置搜索”列只读显示保存的搜索设置：OpenAI 和使用主 config 的固定提供商读取全局 `web_search`（`source=global`），切换提供商读取各自 config 的顶层值（`source=provider`）。使用普通文本区分关闭、缓存、索引、实时，不提供下拉选择；全局缺省显示“跟随默认”，独立 config 缺省显示“跟随全局”。实际模式还受权限和提供商限制。共用目录的账户分别显示。搜索展示读取错误按账户返回脱敏状态；核心提供商配置校验仍失败关闭。刷新中与失败时隐藏旧搜索值，避免将过期值当作当前配置。
缓存记录时间位于标题栏右侧，客户端版本以标题旁的标签展示；窄屏允许换行。两者仅代表文件元数据，不代表运行中服务的实际生效状态，加载或读取失败时隐藏旧元数据。
模型目录数字列右对齐并使用等宽数字，模型名称与表头对齐；操作按钮使用「调整上下文」区分工具能力标签。悬浮标签通过 Base UI `render` 直接组合 Badge，保留键盘焦点样式；版本与时间说明统一使用 Tooltip。上下文选择使用 FieldSet／FieldLegend 和 ToggleGroup，自定义值使用独立 Field，预设显示实际 Token 数值；页脚按钮与说明在宽屏同排、窄屏纵向展示。
`components/settings/openai-model-details.tsx` 提供点击模型名称打开的只读侧栏，按四组展示白名单能力字段，「使用指引」和「运行特性」默认折叠。输入类型、有效上下文比例、工具搜索和补丁工具类型在模型列表展示，侧栏不重复；网页搜索类型 `web_search_tool_type` 仅在侧栏展示。原始字段和值通过悬浮展示，缺失与 false 分开。详情绑定缓存范围和模型 ID，读取失败或模型消失不复用旧数据；刷新对比复用该组件直接显示全部变化字段，不隐藏已移至列表的字段。加速列从目录说明中提取明确的 `Nx speed` 倍率，只展示档位和倍率，不提供悬浮备注或下划线，不推断费用或实际性能。
侧栏的「模型提示词」页由 `components/settings/openai-model-prompts.tsx` 通过独立管理 GET 接口按模型与缓存修订加载，在九个用途分组中逐条展开纯文本。切换模型、修订或关闭详情时卸载并取消读取；缓存变化后要求重新读取目录，缺失字段不冒充内置默认提示词，正文不进入列表、刷新对比或浏览器持久存储。
`hooks/use-openai-model-catalog.ts` 通过共享 API 类型读取 `/api/v1/management/models/official`，编辑仅提交选中模型的 `context_window`，
复用版本化预览、确认、备份和写后回读。“刷新当前配置目录”是唯一目录刷新入口，确认后运行 `codex debug models`，让上游自行管理缓存；不在预览阶段执行，也不将可能回退的 stdout 覆盖缓存。执行后展示可见字段的前后对比，明确区分文件变化与远程成功，并提示输出的可见模型信息与缓存不一致。
页面顶部刷新仍只重新读取。所有写入共用互斥状态，编辑草稿和待确认期间暂停页面自动刷新；加载时隐藏旧目录，读取失败清除旧数据并提供独立重试。
保存结果说明备份、回读未知、审计降级与运行中服务不会立即更新，官方后续刷新可能覆盖手动修改。上下文预览包含 `changed`；API 同值确认在修订复核后返回 `status=unchanged`，不备份、不替换缓存，反馈不显示保存或激活提醒，也不新增覆盖跟踪。普通界面仍禁用同值预览；实际变更返回 `status=saved`，仅确认保存的变更加入跟踪。
`lib/openai-model-cache-edits.ts` 仅在本标签页 `sessionStorage` 保存至多 20 条已确认编辑的缓存范围、模型 ID 和上下文数值；
再次读取同范围发现值变化或模型消失时提示可能被官方刷新覆盖；刷新目录后保留该范围跟踪。
未知版本、畸形记录或存储不可用时提示跟踪不可用，保留原存储，不影响缓存编辑；不同标签页不共享跟踪。

`components/settings/model-catalog-columns.tsx` 将 OpenAI 和第三方目录放在一张表中，共用一个表头和横向滚动容器，各提供商用表内分组行区分。仅模型名称列固定为 18rem，其他列自动分配宽度，表格占满容器，窄屏在容器内横向滚动。长名称省略但保留完整无障碍名称与详情入口。名称旁不显示默认模型标签，默认模型的移除保护保留。数值右对齐，加速不使用悬浮说明。「特性」列分别显示工具搜索和文件编辑状态，读取 `supports_search_tool` 和 `apply_patch_tool_type`；自定义目录优先使用定义声明，不从编译缺省值推断。补丁类型仍可悬浮查看，网页搜索类型 `web_search_tool_type` 保留在侧栏。OpenAI 刷新入口放在对应分组标题中，状态与结果保留在所属分组。模型行操作统一收进「操作」下拉菜单；自定义目录的“编辑”入口放在模型行菜单中，沿用所属提供商的模型与默认值编辑流程，名称也在该弹窗内修改，不再提供单独的编辑显示名称入口。第三方目录提供调整上下文、更新模板和移除模型，OpenAI 目录提供调整上下文。保留原有禁用和确认流程，移除受限原因直接显示在菜单项内；编辑弹窗关闭后焦点返回行内菜单按钮，取消预览确认则返回编辑弹窗。
官方目录按缓存展示声明；自定义目录额外读取 `declaredCapabilities`，思考、图片、工具搜索和 `apply_patch` 区分未知、支持与不支持，未声明的能力显示未知，不把编译后的安全禁用值冒充显式不支持。
内置搜索读取主配置文件的 `web_search` 及精确 Provider ID 的独立覆盖，不使用模型搜索能力元数据过滤请求；搜索是否执行仍取决于上游接口和模型。模型目录提供全局设置与提供商搜索设置入口；保存确认按实际值展示修改前后的模式，全局缺省显示“跟随默认”，账户缺省显示“跟随全局”。搜索诊断保留，不自动修改配置。
模型页要求提供统一目录渲染回调；第三方操作错误与保存反馈放在目录下方。目录标题以标签展示默认模型和思考等级，共用目录按账户分别标识；加载、读取失败或回读未确认时隐藏旧值。标题“操作”菜单提供受支持的“添加”和“编辑”：自定义目录复用模型编辑，托管目录编辑所选账户默认值，不再展示独立的托管提供商默认值卡片。Codex 默认值在目录上方的“Codex 主配置默认值”栏展示精确提供商与配置覆盖，通过关联入口进入全局设置；模型与思考等级一组预览，加速档位单独预览，不归属官方目录。第三方主配置仅展示默认值，官方目录刷新独立保留。
模型行操作及添加模型的弹窗复用 `settings-controls.tsx` 的尺寸样式；确认组件允许调用方指定同一尺寸，模型操作与全局设置分组使用该覆盖。添加模型及自定义编辑固定标题与底部操作，仅正文滚动。`components/settings/model-definition-fields.tsx` 为两者提供共同的身份及能力字段：宽屏并排放置 ID／名称和上下文／思考设置，三个能力分组使用同一组支持／不支持按钮，继承模式及窄屏单列。非预设窗口显示“自定义”，精确 Token 数保留在输入框。新增独立模型必须显式声明全部能力，自定义编辑保留未知、不支持和支持；未选择的能力标记未知，再次点击已选按钮可清除选择。名称、上下文与网页搜索保持单列流程，模板范围横向勾选；确认页短值左右对照，长提示词与 JSON 上下展示。沿用原有字段校验、候选、取消与保存流程。
自定义模型编辑显示精确提供商 ID，默认模型同时显示名称与 ID，已有模型 ID 只读。模型主体复用添加模型字段，不再嵌套卡片；多个模型以分隔线区分。思考等级使用多选下拉，选择后保持展开，已选项显示勾号；默认等级从已选项中选择，取消当前默认等级时回退到首个剩余等级，清空时取消默认值。上下文预设不显示重复副标题，保留无障碍标签。自定义目录将“未设置”和“关闭”合并到思考等级下拉框，与具体等级互斥；分别保留未知与不支持的定义，关闭或清空等级时清除默认等级。能力检测默认折叠，展开后只显示所选项的单行预算和计费按钮；切换项清除旧检测结果。`custom-model-details.tsx` 的高级参数默认折叠，采样数值按三列、响应与上下文管理按两列分组，描述和指令保持整行，窄屏单列。字段变更仍通过原有草稿 patch、预览和确认流程写入。
Codex 与托管目录的模型设置弹窗使用单列字段，标签位于选择框上方；默认模型、思考等级及加速档位选择框铺满可用宽度，长名称允许换行。
全局上下文窗口复用通用模型的 128K、256K、384K、512K、1M 预设（K = 1024 Token），使用可点击的单选按钮组，保留精确数值输入与自定义选择；“跟随模型默认值”只清除窗口覆盖，不改变自动压缩阈值。已有非预设数值按自定义显示，仍通过原有预览确认保存。
全局自动压缩提供 50%、60%、70%、80%、90% 比例预设，按当前全局窗口向下取整换算成精确 Token 阈值，保存合同不变；修改窗口不会隐式重算阈值，可重新点击比例。窗口缺失、无效或太小时禁用比例预设，仍允许直接输入阈值或清除覆盖；不以当前默认模型推测所有模型的窗口。读取已有阈值仅识别唯一精确匹配的预设，多个比例取整后相同时显示自定义，本次点击则保留所选比例；不按取整百分比改写原值。运行时仍受模型最大窗口及压缩阈值上限约束，比例预设不改变这些规则。
`lib/custom-model-validation.ts` 复用目录采样校验，为高级数值参数提供字段错误与提交前校验。模型身份与能力字段在原位展示重复 ID、无效上下文窗口的错误，并关联输入框与说明。切换托管默认模型时仅保留新模型支持的思考等级，否则采用该模型声明的默认等级；无有效等级时禁止提交。模型、提供商和账户编辑及压缩草稿修改期间暂停页面恢复可见时的自动刷新；目录保存等待管理快照与本地目录一致，再按精确提供商和模型恢复焦点，目标已移除时返回目录标题；加载失败与等待回读的原因在设置弹窗内展示。
长描述与模型指令使用限高、可调整高度的文本框，完整内容在框内滚动；确认页的指令也使用限高滚动区域，不裁剪或改写原文。
`components/settings/provider-model-catalogs.tsx` 组合独立本地目录与完整管理快照，在管理不可用或目录修订不一致时复用目录表格与详情展示只读模型。
第三方模型区展示 `modelCatalogs` 派生的启用目录，每个 Provider ID 的账户目录分别作为操作目标，
点击模型名称复用能力详情侧栏；精确模型 ID 在侧栏展示，账户范围在目录标题展示。
详情按提供商、精确模型 ID 和目录修订绑定，目录修订变化、读取失败或模型消失时不复用旧详情。
第三方提示词通过 `/api/v1/management/provider-model-prompts` 独立读取，复用纯文本分组展示；模板来源和采样参数仅在此响应提供时展示，不进入列表或浏览器持久存储。
`components/settings/provider-model-template-dialog.tsx` 提供账户单模型的来源选择和前后差异确认，按服务端 `availableSections` 展示受管提示词／能力／设置或自定义提示词／设置范围，默认仅选提示词。「压缩设置」仅含有效上下文比例、自动压缩阈值和截断策略；已有模型默认保留本地值，主动勾选并确认差异后才覆盖。当前上下文、默认思考等级、工具支持和采样始终保留；自定义模型还保留最大窗口与其他手设能力，受管能力更新可改变最大窗口。确认期间保留编辑会话，取消不重置草稿或重新获取候选；保存回读后恢复模型入口焦点。`/api/v1/management/provider-model-templates` 获取有期限的候选，`model.template.update` 复用 Provider 设置的预览、一次性确认与写后回读。旧模型无关联时不自动选择来源；官方共享目录不开放该操作，候选正文不持久化到浏览器。
旧修订提示重新读取目录；该入口只读取本地目录。账户模型上下文通过模型表格的“调整上下文”入口编辑，详情侧栏保持只读。
本地移除复用 `management.mutate/confirm`，
确认页将模型名称、ID 与影响账户和简短提醒分区展示，以分隔线和留白区分，不折叠说明；
提醒保留共享 Relay 授权、目录变更对在途请求的影响、历史引用、备份和手动重启要求，具体重启命令在保存结果中展示；
模型行使用共享业务层的 `removalBlockedReason` 禁用移除并显示原因，区分账户默认值、目录默认值、当前主提供商的 Gateway 显式默认值、最后一个模型和不支持裁剪的来源；`isDefault` 仍只表示账户选择。CLI 与 WebUI 共用该保护投影，后端执行时仍在锁内复核。
自定义模型编辑复用既有能力表单，通过 `model.custom.save` 仅提交模型定义与默认值，
不提交连接或凭据；已有模型不可在编辑中隐式删除或重命名，移除走独立预览。
自定义提供商初始模型使用共用通用编程草稿，能力由用户逐项声明；不再读取旧模板草稿接口。已配置的 CCG、OCG、CLP 和自定义目录从统一“添加模型”弹窗按 ID 新增，选择独立填写或继承已有模型；编辑窗口只编辑已保存模型和默认值。采样和高级参数仍可在已有模型编辑中修改，未改字段保持原值。
CCG、OCG 保留 DS 导入；CLP 的固定 DS 候选和模板更新只读取仓库模板，CLI 与 WebUI 均不再下载 Cline 官方目录。
独立上下文路由只管理 Codex 全局窗口与自动压缩，账户模型窗口在模型表格内预览并确认保存。

## UI 组件规范

- 组件使用官方 `base-nova` 样式和 `@base-ui/react`，类名合并统一使用 `cn` 包。组合触发器使用 `render`，Select 显式提供 `items` 的值与显示标签，ToggleGroup 的受控值使用数组；不保留 Radix 调用接口。
- `ManagedSelect` 在业务组合层约束字段与触发器宽度；普通选择随 FieldGroup 容器切换全宽/紧凑布局，不按浏览器视口提前收窄，长值保留截断，完整标签可在换行菜单中查看，`fullWidth` 保留多行展示。统计分组、账户等窄弹窗中的纵向选择与输入等宽；字段说明通过稳定 ID 与控件关联，多模型高级参数使用每实例 ID。
- WebUI 端口和指标存储按字段显示校验错误，错误关联被校验的草稿；更改对应输入后旧错误失效，整组校验通过才请求预览。共享确认按设置种类显示实际前后值及组合范围，令牌和代理另保存白名单非秘密操作意图，以区分替换、清除和生成；公开监听自动生成令牌须显示副作用，秘密不进入确认正文。原始请求、修订和确认令牌仍由既有版本化流程提交。
- `components/ui/toast.tsx` 提供 Base UI 通知容器，`toast-manager.ts` 提供共享通知管理器；`App.tsx` 挂载容器，默认 3 秒关闭并本地化关闭按钮。成功通知短暂显示，错误及需要处理的警告仍保留在操作区域。

- 基础 UI 组件放在 `components/ui/`，只通过 `npx shadcn@latest add` 安装或升级，
  不手写基础组件（按钮、卡片、表格、弹层等）；
- 业务组件按领域分目录组合：`components/layout/`（布局与鉴权）、
  `components/overview/`、`components/threads/`、`components/metrics/`（指标区块），
  `components/requests/`（请求明细数据表格），只做组件组合与数据编排，不直接发请求；
- 数据获取统一走 `hooks/`（`useApi` 系列，集中 loading/error/refetch；`use-model-traffic-settings` 共享布局的调用采集开关及转储可见性，自动刷新不探测服务状态；设置变更共用版本化预览/确认 Hook），组件不直接
  `fetch`（唯一例外：`AuthGate` 在提交令牌前用原始请求验证一次）；API 路径统一从
  `src/lib/api.ts` 的 `API_PREFIX` 拼接；
- 类型从 `src/lib/types.ts` 转出，格式化（Token/时间）放 `src/lib/format.ts`；已本地化的时间预设标签放 `src/lib/i18n/messages.ts`，
  控制台与各查询页复用 `components/metrics/range-selector.tsx` 的时间及日期控件；
  `use-metrics-query` 读取 Provider 筛选选项并保留多选 URL 参数，`query-filters` 使用勾选下拉；
- 界面翻译通过 `hooks/use-translation.ts` 接入，字典与取值函数位于 `lib/i18n/`，语言状态由
  `hooks/language-context.ts` 与 `language-provider.tsx` 管理。翻译约定、UI 文案参数、覆盖阶段及验收统一见
  [本目录国际化维护约定](#国际化维护)。
- 页面（`pages/`）只负责组合区块与路由参数，业务规则不写进页面；
- 遵守 oxlint 规则：Hooks 必须在组件顶层调用，文件默认只导出组件
  （`react/only-export-components`）。

详细行为见 `docs/webui.md`。

`pages/logs-page.tsx` 组合「调用监控 → 服务日志」（`#/logs`）；`components/service-logs/service-logs.tsx` 使用官方 `components/ui/tabs.tsx` 切换服务，搜索与行数、级别和刷新设置同排展示；`log-results.tsx` 组合撑满页面剩余高度的结构化表格、详情和阅读时的快照保留，日志在表格区域内滚动；`lib/service-logs.ts` 解析已脱敏的 Pino/tracing 日志及 journald 白名单元数据、合并来源并筛选，不猜测未知级别。`hooks/use-service-logs.ts` 复用统一请求与可见页面刷新调度，切换查询隔离旧结果，离开页面取消读取。

`pages/delivery-page.tsx` 组合渠道投递队列独立页面，由左侧「消息渠道 → 渠道投递队列」进入 `#/delivery`；`components/delivery/delivery-queue.tsx` 提供精简表格列表、状态计数筛选、行内内容摘要、游标分页和勾选批量重试/忽略确认；`hooks/use-delivery-queue.ts` 复用管理确认 Hook 与 `hooks/use-queue-events.ts` 的 SSE 变化订阅，筛选或翻页时重建当前查询，离开页面时取消请求。

`hooks/use-reset-credits.ts` 组合重置券读取、预览、确认、账户刷新和取消，同步操作锁防止重入，卸载取消并阻止迟到结果触发刷新回调；结果不确定时保留既有禁止盲目重试语义。

`hooks/use-range-refresh.ts` 与 `lib/range-refresh.ts` 为指标页面补充时间范围失效调度：按服务端时区跨日更新今天、昨天及控制台热力图，滚动范围按最后成功请求的开始时间，每 5 分钟校准；后台、离线、历史分页、加载或错误期间不发起时间驱动读取。`components/metrics/refresh-status.tsx` 展示指标及调用页面的通知状态、最后成功读取时间和陈旧提示；跨日调度以成功请求的开始时间为基准，避免零点前读取、零点后返回的旧范围延迟一天才刷新。`useApi` 的成功完成时间用于展示，只随成功结果更新，失败保留内容时保留原时间，取消的请求不能更新时间。

控制台、请求与错误列表区分首次加载和后台刷新：`loading` 仅用于当前查询没有结果时的占位，`refreshing` 用于刷新按钮和操作限制；同查询刷新保留内容，切换查询不展示旧范围结果。管理任务的 `notificationError` 独立于读取错误，通知中断不阻止已成功读取的终态触发关联刷新。

## 自定义模型能力设置

提供商页面通过搜索状态或行操作菜单打开联网搜索弹窗，按后端返回的独立 Provider ID 配置具有独立 config 的第三方账户；OpenAI 和使用主 config 的固定提供商进入全局设置的行为与偏好分组修改全局值。

`components/settings/settings-navigation-guard.tsx` 统一全局设置、提供商及模型页面的草稿离开确认与提交期间导航保护；各页面负责提供自己的编辑与事务状态，读取不锁定导航。
`components/settings/provider-web-search-settings.tsx` 提供跟随全局、关闭、缓存、索引和实时五种选择，
通过 `provider.web-search` 携带资源修订进行预览、确认及权威回读；跟随全局只移除账户覆盖。

保存直接修改对应 config 的顶层 `web_search`，不再保存独立搜索覆盖文件。
保存不改变运行中的会话，安全应用配置或重建对应 App Server 后，新建或冷恢复会话才采用新设置。
模型目录的内置搜索列保持只读，显示相同账户覆盖，空覆盖显示跟随全局；全局设置中的空搜索值仍显示跟随默认。提供商搜索弹窗提供全局搜索快捷入口，预览确认及写入期间禁用。

`components/settings/provider-model-addition-dialog.tsx` 为 CCG、OCG、CLP 和自定义目录共用按 ID 添加、独立填写／继承和完整字段确认，默认独立填写。继承来源限同一提供商目录，不自动选择，不提交隐藏的独立能力草稿，不复制凭据或模板关联；CLP 还明确展示请求格式及可选请求改写。受管提供商可追加内置 DS 模型，已有条目保持原值。候选与保存分离，复用修订校验、一次性确认和回读；取消确认保留草稿，切换目标或失效时隔离旧结果。
`components/settings/provider-model-request-options-dialog.tsx` 为 CLP 模型提供 `providerOptions` JSON 编辑、DeepSeek 路由预设、客户端格式检查和确认差异；读取与保存分别绑定模型目录修订，`{}` 清除模型级覆盖，关闭确认保留草稿。
`hooks/use-provider-model-addition-options.ts` 拥有用户触发的候选读取、加载与受控错误、选择和取消；目标或修订变化、目录失效及卸载会取消旧读取并隔离迟到结果。进入确认只隐藏编辑弹窗并保留候选与输入草稿，取消确认不重新读取；不自动发现或探测上游。

`components/settings/provider-settings-management.tsx` 按模型提供图片、思考、`apply_patch` 与
`tool_search` 的手动声明；思考等级下拉框统一提供未设置、关闭及具体等级，并同步约束默认等级。新增模型不会预选补丁或搜索工具，
切换 Chat Completions 也不会改变模型的工具声明。
独立起点草稿使用项目通用编程提示词与两项本地工具声明，不按模型名称推断能力或自动绑定模板；当前上下文必须填写，最大上下文省略时等于手填当前值。已有模型沿用已保存的模板来源与上下文管理设置，继承新增则按用户选定的模型复制。图片支持时表格显示“文本”“图片”两类输入，未知和不支持保持明确区分。
统一模型表格为 OpenAI、受管与自定义模型提供行内上下文编辑入口，官方共享目录保持只读。
`components/settings/model-context-window-fields.tsx` 按提供商类型复用窗口表单：OpenAI 专用 272K、372K、500K（K = 1000 Token）；第三方与 CLI、自定义模型新增／编辑共用 128K、256K、384K、512K、1M（K = 1024 Token）。两组均保留最大值及自定义输入。
超过模型上限的预设不可选。`lib/model-context-window.ts` 要求调用方明确预设组，负责预设选择与整数校验，
OpenAI 保留正整数边界，受管与自定义模型最低为 1024 Token。受管与自定义模型通过 `model.context`
携带当前目录 revision 进行窄更新，复用预览确认；整组自定义模型高级编辑入口保留。
独立上下文页面只保留 Codex 全局窗口与自动压缩设置。
预览、确认写入和回读保持精确 Token 数，不按整数百分比换算。模型选择以 Provider ID 与模型 ID 联合定位，同名模型不会选中其他账户；账户默认模型选择按精确提供商保存，受管模型的默认思考等级、目录定义与上下文由同一家族账户共享，修改与移除的实际影响范围以预览为准。

`components/settings/custom-model-details.tsx` 复用共享 API 的模型元素类型，组合基本响应参数与可展开的高级参数。
基本区编辑模型描述、最大窗口、各思考等级说明、图片 original 细节、verbosity 与默认值，以及独立的思考摘要参数。
Chat Completions 同样开放全部能力选择与保存；切换接口保留已有声明，并说明当前请求转换对 original、verbosity 和摘要参数的限制。
清除图片支持或选择不支持时同时清理 original；取消勾选等级时清理对应说明，取消默认等级后转到剩余首项，全部取消则清空默认值。DS 模板副本的当前与最大窗口独立编辑，不再提供上下文跟随。高级区保留 instructions 原文，
编辑有效窗口比例、可留空的自动压缩阈值，以及可恢复默认的 tokens/bytes 截断策略。默认采样参数提供六项逐模型编辑、恢复项目固定模板和全部清空；独立新增草稿不预填采样参数，可在高级设置中主动恢复项目固定值；继承新增与已有模型保留保存值，请求显式参数优先。
确认弹窗逐模型展示这些参数与 instructions 全文，缺省值明确说明；所有文案均提供中英文。

每个模型的可选检测区先选择文件编辑、工具搜索或网页搜索，再点击计费提示按钮发起单项检测，不运行整套能力检测。
`hooks/use-scoped-probe-request.ts` 统一草稿检测和已配置网页搜索检测的单请求归属：作用域变化、禁用或卸载时取消，取消先释放归属，迟到回调与 finally 不能影响新请求。业务 Hook 继续负责结果格式、错误映射与回填权限。
`hooks/use-custom-model-capability-probe.ts` 将单项请求及结果绑定当前草稿，草稿变化、取消或关闭编辑时
中止请求并阻止旧结果覆盖。检测使用手填的默认思考等级，未声明时使用 `none`；两种工具每次最多 3 个上游短请求，
服务端总限时 45 秒，客户端限时 50 秒。请求可能产生费用，必须由用户主动点击。

明确支持或不支持的结果可以回填对应的工具字段及连接凭证；未确定或取消的结果不能回填。
其他模型能力保留手动值，保存继续使用版本化预览与确认。`lib/custom-model-probe.ts` 只将固定原因映射为
`lib/i18n/messages.ts` 的中英文文案，不展示未经指定的上游响应。

并列的「检测原生网页搜索」按钮使用 `webSearch` 发起可选诊断，最多一次真实 `web_search` 请求，
沿用相同的思考等级、超时及取消管理。界面提示模型和搜索费用；只有完整、可验证的 `web_search_call`
搜索完成事件才能确认支持，请求成功或自称已搜索不能冒充搜索执行证据。结果仅供诊断，不携带保存绑定令牌、
不提供自动回填、不修改联网搜索开关或 `tool_search`；可参考诊断证据另行手动声明，再预览保存。

已配置模型也可从模型目录行的「操作 → 检测原生网页搜索」进入诊断，覆盖 OpenAI 官方、托管账户、
共享官方目录及自定义目录。`components/settings/provider-web-search-probe-dialog.tsx` 复用统一诊断弹窗；
共享目录存在多个账号时必须明确选择一个，只向该账号发送一次请求。客户端仅提交提供商 ID、模型 ID 和
目录修订，地址、凭据、协议和上游模型映射由服务端从当前配置解析；第三方沿用模型默认思考等级，
官方不额外指定思考等级。凭据无法读取时明确失败。
`hooks/use-provider-web-search-probe.ts` 将请求与结果绑定所选账号、模型及修订，关闭或取消、账号切换、
目录或配置失效均中止请求并阻止旧结果覆盖；进行中拒绝重复发起。弹窗关闭后焦点返回行内菜单按钮。
此入口同样提示费用，仅显示诊断结果，不保存配置、不修改目录声明或策略，也不产生回填绑定令牌。

## 国际化维护

当前页面覆盖与剩余验收见 [WebUI 指南](../docs/webui.md)。


界面语言在重新加载后恢复偏好；不改变服务端时区、统计、查询、权限、确认或导出数据。
CLI、渠道消息、Codex 协议和用户内容不在本地化范围内。不翻译模型/提供商 ID、Thread/Turn ID、
配置键、API 参数、日志、调用转储和用户输入。网关返回的原始账户数据保持原样。

中文普通标签使用“提供商”“会话”“轮次”，英文使用 Provider、Thread、Turn；
ID 的标签跟随语言，实际值不变。`Turn State`、`X-Codex-Turn-State` 等协议名称保持原样。

### 翻译维护顺序

中文是源文案。后续获授权的页面或文案变更按以下顺序执行：

1. 提取中文、键、占位符及场景，复用已有键，覆盖加载、空态、失败、重试和可访问名称。
2. 执行者直接生成英文候选并复核，不调用外部翻译服务；中文变更时同步检查既有英文。
3. 经复核后接入字典和组件；不复制中文充当英文、不放宽键或占位符门禁。
4. 验证中英文切换、偏好恢复、英文布局和交互状态保持，记录本批实际覆盖与缺口。

CI 只校验字典，不自动生成、翻译或回写文案；本地差异报告按需使用。
语言切换不得重新提交操作、清空草稿、关闭待确认操作或改变授权范围。

### 本地翻译工具与 CI 校验

以下工具已实现并经本地验证：

- [`webui/i18n-glossary.json`](i18n-glossary.json)：中文术语、英文建议、原样保留项与翻译规则。
- [`scripts/webui-i18n.mjs`](../scripts/webui-i18n.mjs)：使用现有 TypeScript 解析器静态读取字典对象，
  不导入或执行字典模块。仅支持对象和字符串字面量，拒绝展开、计算属性与动态值。
- `npm run i18n:check`：检查空文案、中英文键与占位符；进入本地提交和 CI 共用的 `verify:commit`。
- CI 仅通过共用门禁校验字典，不自动生成报告、调用翻译服务或回写译文。

在仓库根目录运行：

```bash
npm run i18n:check
npm run --silent i18n:report -- --base main > /tmp/webui-i18n-report.json
```

`--base` 必须是本地可解析的 Git 提交或引用。第一次引入字典时，基线文件不存在会将所有源键列为新增；
逐批审查可指定上一批提交，避免把此前已完成的文案重复列入。报告读取当前工作区，可用于审查未提交修改。

报告条目包含 `new`、`source_changed`、`translation_changed`、`missing_translation`、`removed`，
保留前后中文和英文值，以及 `needsTranslation` / `needsReview`。中文变化即使已有英文也标记待复核；
报告不能判断译文质量，不能把英文“存在”视为翻译已完成。结构问题单列在 `issues`，由检查命令阻止提交。

报告仅供本地按需审查。

### 实现约定

- 复用现有 React 语言上下文，内部值保持 `zh` / `en`，页面 `lang` 分别为 `zh-CN` / `en-US`。
  默认中文，偏好写入浏览器 `localStorage` 的 `codex-webui:language`；非法值或读取失败时使用中文，
  写入失败不妨碍本次页面内切换。此偏好不是 Gateway 配置，不写入 TOML 或数据库。
- 字典位于 [`messages.ts`](src/lib/i18n/messages.ts)，中文为键结构基准，英文通过类型检查
  保持同一结构。组件使用 [`useTranslation`](src/hooks/use-translation.ts)，按业务区域组织键。
- 文案优先使用完整句子与 `{name}` 占位符，避免拼接会因语言顺序不同而失效的片段。
  当前数量说明采用不依赖英语单复数词形的表达；后续出现复数需求时补齐规则并核对展示。
  当前取值函数不支持 ICU 或自动复数选择，不得将这些能力视为已实现。
- 动态键必须来自明确的类型或映射，例如导航、日期范围和错误码。静态扫描未识别的键应人工核对，
  不能仅凭扫描结果判断其无用。未知内部错误使用本地化通用提示，不把原始异常直接当作翻译文案。
- 已显示的错误与状态保存结构化标识，在渲染时翻译，避免切换语言后残留旧语言。
  字典中的用户可见文案通过 React 文本渲染，不引入 HTML 翻译或字符串插入 DOM。
- 设置确认使用文案键和占位符保存字段标签，确认框渲染时再翻译；配置预览原值保持不变。
  工具访问设置按配置路径翻译固定标签，应用、站点、MCP 与插件标识保留原值。
- 日期与数字复用项目格式化函数，时间仍以服务端时区为准。后续调整格式时明确语言格式与时区的区别，
  验证日期边界、零值、缺失值与单位，不因翻译改变原始数据。
- 沿用现有 shadcn 组件。基础 UI 组件通过文案参数接收可访问名称，业务组件负责翻译，
  避免基础组件依赖应用语言上下文。Sidebar 的 `mobileTitle` / `mobileDescription` 和
  SheetContent 的 `closeLabel` 由调用方提供。英文文案更长时检查换行、截断、焦点和窄屏布局。

### 验证与交付

中文提取阶段先验证源文案、键设计、占位符和不翻译边界，并记录尚未接入的组件与缺失英文。
以下要求用于英文候选复核后的双语交付；候选来源按当前批次约定，不因门禁擅自改变翻译方式：

1. 中英文键结构、占位符名称与实际调用一致，动态键有明确来源；已覆盖区域没有遗漏的界面文案。
2. 实际切换语言后，已挂载组件、表头、错误和提示更新；偏好恢复、非法值及存储不可用行为正确。
3. 语言变化不改变数据请求语义、筛选值、分页、关联链接、输入草稿和操作确认状态。
4. 已知错误按结构化标识翻译，未知错误使用通用提示；原始内容保持边界，不误译用户数据。
5. 英文长文案、窄屏布局、关闭按钮、表单标签、焦点顺序和页面 `lang` 可用。

针对性验证入口：

```bash
npm run i18n:check
npm --prefix webui run build
npm --prefix webui run lint
npm run docs:check
```

实际交互、键盘焦点和视觉检查单独记录结果。
普通提交通过现有提交钩子执行按范围选择的 `verify:commit`，开发阶段按实际改动选择检查，不重复运行全量门禁。

`components/settings/relay-provider-models.tsx` 按提供商显示只读模型目录弹窗，读取失败时可刷新快照；目录与账户管理入口位于模型管理页。
`components/settings/relay-key-models.tsx` 在 Key 编辑弹窗按提供商分组勾选模型，并为每个所选模型提供跟随客户端、直接选择思考等级及关闭方式二级菜单；关闭菜单仅提供显式参数方式，已有自动映射值仍显示并保留。可跨多个提供商，目录新增模型不会自动扩大 Key 权限。
`components/settings/relay-reasoning-probe.tsx` 在所选模型的检测弹窗中手动对比基线与八种关闭方式；打开弹窗不发请求，开始后最多依次发送 9 次固定短文本、每次请求最多 64 个输出 Token，明确可能计费且不证明内部推理关闭。双协议提供商可选协议，结果仅适用于所选协议；服务端 NDJSON 进度驱动已结束项数、当前方式及渐进表格，不推算虚假进度。缺失指标显示未知，运行时不可采用；仅完整检测中已完成且有可用响应的具体关闭方式可手动采用到该模型草稿，保存仍走原预览与确认流程。
`hooks/use-relay-reasoning-probe.ts` 通过 `/api/v1/management/relay/reasoning-probe` 维护单次检测，将请求绑定编辑 Key、配置版本、模型与协议；取消、关闭、卸载或上下文变化会中止请求并阻止迟到结果覆盖或采用。失败、取消和超时保留已收到的部分行供本次查看，但不可采用且不替换历史完整结果。缓存读写和采用时效统一使用现有服务端校准时钟，避免客户端时间偏差中断合法探测或提前清除记录。前端超时为 140 秒，服务端逐请求与整批预算见 Relay 管理接口。
`lib/relay-reasoning-probe-cache.ts` 仅将完整终态的有限元数据保存到本浏览器 `localStorage` 的 `codex-webui:relay-reasoning-probes:v1`：每个模型与协议一条、最多 20 条、7 天，总编码大小不超过 128 KiB，读取已知有效版本时裁剪过期项。仅存配置版本、模型、协议、开始时间及九种方式的状态、HTTP 状态和可观察指标，不存 Key、提示词或响应正文。读取严格验证版本、键、字段类型、长度、行顺序及数量；异常或未知版本不自动删除或覆盖，存储禁用仅提示且不阻断检测。弹窗重开或页面刷新展示历史时间，不自动请求；不同 Key 可共享同模型和协议的观察，同版本历史可明确标为历史后手动采用，旧版本只读。清除按钮仅删除本功能专用缓存，不影响其他浏览器存储或服务端数据。
`components/settings/relay-model-copy.tsx` 在 Key 列表中提供授权模型 ID 复制菜单、复制结果提示和剪贴板不可用时的手动复制入口。
`hooks/use-relay-key-editor.ts` 管理 Key 草稿版本、逐模型思考设置、提交参数与一次性结果；移除模型同步清理草稿，新选模型默认跟随客户端。`components/settings/relay-key-table.tsx` 和 `relay-key-dialogs.tsx` 分别组合列表和编辑/逐模型确认/结果弹窗，`pages/relay-page.tsx` 保留页面组合和焦点恢复。
