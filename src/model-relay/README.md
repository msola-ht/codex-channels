# Model Relay

独立模型 API 入口的身份、准入和请求生命周期模块，不依赖 App Server、Thread、Turn 或数据库。
由 Runtime 的独立服务入口组合；生产运行验收与跨平台实机验收仍需单独完成。

- `index.ts`：公开模块能力。
- `admission.ts`：内存身份快照、常数时间秘密哈希比较、全局令牌桶与并发许可、有界上传/等待预算及按 Key 公平调度、撤销和关闭。
- `server.ts`：默认回环、可显式 IPv4 局域网监听的 HTTP、异步准备后的出站复核、Key 多提供商模型授权、公共 ID 到精确上游 ID 映射及 Key 思考策略选择、CLP 精确 DeepSeek 模型的上游限定（复用 Provider Proxy 公共投影）、原生 Chat/Responses JSON/SSE 交付、请求关闭及一次性指标生成（含实际出站 User-Agent，缺失不推断）；错误响应提供受控原因、阶段、上游状态与指标关联编号。
- `metrics-sender.ts`：有界单次指标发送、四类确认结果、零重试与限时关闭。

Runtime 注入已验证的配置、Provider 材料与网络目标；本模块不解析账户文件或凭据路径。
协议验证通过 `model-api` 公共入口，网络能力通过 `provider-proxy` 公共入口。指标仅通过注入端口
送往 Gateway 单写者，不生成 Core 事件或渠道输出。

等待队列仅在内存中：上传/等待最多 32 个、正文预算 16 MiB、排队最多 30 秒；取消/撤销/关闭
释放等待资源，不自动重放。等待不占执行许可，不生成上游指标；diagnostics 提供无正文的计数；queueSnapshot 只读返回最多 64 个当前已鉴权模型请求的身份、Provider、模型、入站思考等级、协议、阶段和耗时，完成、失败、取消或关闭后移除，不保存正文和历史。思考等级从已验证请求投影，保留 1–64 字符且不含控制字符的字符串，缺失、尚未解析或形状不可展示时为 null，不推断默认值或后续 Key 策略结果。`queueChanged` 注入端口在请求加入、阶段切换和移除时通知服务组合层，不等待网络订阅者。

`ModelRelayServer` 可注入按协议选择的独立采集器，由服务组合层按全局设置选择采集级别，提供入站快照和实际交付观测；异步初始化接收请求取消信号，完成后仍在实际出站前复核授权；未启用时不采集正文；请求指标仍独立采集上游返回的受限诊断摘要，V2 定位只在转储存在时附带。Chat JSON/SSE 保存路由及结束原因，Chat/Responses 保存有证据的错误阶段和内层错误；客户端交付失败及请求取消不冒充上游错误阶段。
旁路脱敏、容量与文件生命周期归 provider-proxy 公共能力，Relay 不操作指标数据库。

运行时诊断通过准入队列的 `oldestWaitMs` 和 `timedOut` 暴露等待时长及当前进程超时累计，不保存排队请求历史或正文；取消与撤销不计为超时。

删除身份由持久历史摘要覆盖后，准入器释放其旧凭据快照；摘要只保留身份与代次用于禁止复活，不授予调用权限。摘要移除或代次倒退会拒绝热应用；没有持久摘要覆盖的删除仍保留原内存撤销保护。
