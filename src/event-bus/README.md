# Event Bus

本目录提供进程内有界事件传递，隔离 App Server Reader 与 Telegram 等慢速消费者。

## 文件

- `index.ts`：本模块的公开导出入口。
- `bounded-queue.ts`：支持非关键事件容量限制、关键事件保护、优先交互、关闭和异步消费的队列；优先项
  排在所有既有关键项之后、尚未执行的非关键项之前，两类既有项各自保持原顺序；
  `hasPendingKey` 查询可原位替换的等待项，`replacementFor` 预览同键替换或关键项淘汰的旧载荷，供外层按实际增量检查硬预算；`remove` 按值身份移除被明确取消的排队项，保留其他项的顺序与容量计数；入队时可携带合并键，
  仍在等待执行的同键条目就地替换为最新载荷，保持原队列位置、容量计数与等待时间，已开始执行
  或被淘汰的条目不再参与合并；替换可通过队列构造时传入的观察回调记录，便于判断平台变慢时的
  积压来源。可选丢弃观察回调区分同键合并与容量替换，供渠道按投递标识记录中间输出去向。
- `event-bus.ts`：管理订阅者及其独立队列，并隔离消费者异常；关闭后拒绝新订阅，并发关闭等待
  同一批消费者，默认最多等待 5 秒。`drain()` 在保留发布入口的同时等待已接收事件处理完成，最多 5 秒，超时明确失败，供派生生产者在关闭前结算终态。`close({ requireDrained: true })` 在未排空时拒绝关闭结果，供组合根报告持久接收缺口；不无限等待消费者。消费者第三个参数提供本订阅的排队耗时（单调时钟毫秒），不包含处理器执行时间。
  可由组合根注入类型化合并键选择器，发布时计算键，各订阅独立合并等待项；总线不解析业务事件。
  出站总线与 Surface 路由复用 Surface 的有界分段策略，入站协议通知不采用输出快照合并。
  `observe` 只供组合根同步执行有界准入，不执行磁盘或平台 I/O。可选共享预算跨订阅计数在途条数与逻辑字节，合并、拒绝和消费结束均释放额度；生产入站通知与输出总线分别有硬预算，关键预算耗尽时停止继续接收并调用组合根故障处理，不继续扩大溢出区。入站只拒绝超限并停止 Gateway，不合并协议通知。

队列过载时可以合并或丢弃非关键中间事件，但不得丢弃审批、错误、Item 完成或 Turn 完成事件；关键事件可进入单队列软容量的受保护溢出区，但仍受外层共享硬预算限制；硬预算耗尽时明确报告接收缺口并停止继续接收，不承诺无限缓冲。首次溢出及积压数量翻倍时记录队列容量、积压数量和最老事件等待时间，
回落到容量内后重新启用首次告警；EventBus 与 Surface 输出队列均记录该告警。按秒刷新的可合并关键状态（例如思考状态）
仍保持关键级别并进入溢出区，但只保留同键的最新一份，避免平台变慢时按秒堆积。新增后台消费者时必须保留取消和关闭路径。
