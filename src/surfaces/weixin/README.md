# 微信 Surface

组合根经 `factory.ts`、`surface.ts` 向 Outbox 注入目标显示回调，微信消费其中的完成通知 `completion` 和常规通知 `routineNotificationsEnabled`。成功隐藏只完成本地收尾，不调用发送接口、不消费或删除原 Conversation 回复上下文；失败、停止和权威缺正文回执保留。已入箱记录继续原投递义务，其他过程显示设置继续不适用于微信。

常规通知缺省开启；新事件保留和瞬态展示复用共享判定，只在微信既有回复窗口范围内生效，普通配置成功通知按收件目标过滤。持久 Workspace 配置通知和 Gateway 上线摘要继续投递，鉴权或连通告警也保留完整摘要。平台 `notifyStart` / `notifyStop` 在线状态对账独立执行，不受该开关影响。

当前实现单账号私聊文本、图片、视频附件、语音转写与 UTF-8 文本文件 Surface：独立安全凭据边界、运行时窄协议 Client、私有游标检查点、
私聊输入 Adapter、完整命令 Adapter、加密重启上线通知、受回复窗口约束的 Turn 生命周期与文本 Outbox、
一次性精确文本审批、用户输入与 MCP 交互端口和目录内部完整 `SurfaceAdapter`；严格运行配置显式启用时由 Bootstrap 注册，
未新增 SQLite Schema。

可靠输出把原归属授权保存在回执中，每次实际请求和有限重试前重新复核。文本的原归属及收件人守卫经凭据包装器透传至 HTTP，凭据等待支持取消，等待期间撤权后不再发送；普通命令及通知的有限重试同样复核当前收件人授权。长正文的完整答案附件将同一守卫传至上传地址申请、CDN 上传和最终消息发送，撤权后不再发送文件或降级正文；预览确认不代表全文确认。带守卫附件沿用既有协议策略：CDN 内部上传最多一次，外层对明确 API/429 拒绝的有限重试仍保留。此路径不开放微信持久生成图片输出。

显式 `channel send-file` 已接共享 CLI/spool/绑定链路：file/video 最多 25 MiB，video 仅 MP4，原生 voice 明确拒绝（锁定上游无发送实现），音频可由调用方显式选 file。原长正文文件上限 1,000,000 字节不变。协议共用 AES/CDN 上传，视频使用 media_type=2、type=5 与密文 video_size，文件仍为 media_type=3/type=4。显式图片/文件固定原 Thread 和入队时回复上下文，透传停止信号并在每次 HTTP 前复核，120 秒总预算内执行，不自动重传 CDN 或消息。这些新增路径尚未部署或真实客户端验收。

- `credential-store.ts`：严格校验版本 1 微信 Bot 凭据；macOS 使用独立 Keychain Service，
  Linux 使用独立 `credentials/weixin` AES-256-GCM 私有目录，Windows 使用当前用户 DPAPI 主密钥
  保护的 AES-256-GCM 私有目录。
- `credential-client.ts`：首次协议调用时从安全存储读取并缓存当前进程的凭据 Client；缺失或
  损坏凭据失败关闭，不把 Token 提升到 Bootstrap 配置或日志。显式媒体的原 Thread 守卫继续传到协议层；等待凭据可随调用方取消结束，迟到凭据不触发原发送。提供进程内凭据变更检查，
  配置重载时只返回未变化、已变化或读取失败，供 Bootstrap 重启同账号的新连接。
  读取失败记录微信故障，不阻止其他渠道启动和重载；启动时不可读的凭据恢复可读后要求重建连接。
- `factory.ts`：接收 Bootstrap 已决策的精确凭据、游标、回复上下文和上传目录，组合微信固定的
  协议 Client、存储与媒体实现，并把同一个代理感知 Fetch 注入 JSON API、CDN 上传和下载；
  一级 Surface 出口只提供组合入口及 Bootstrap 凭据变更检查所需的窄接口。
- `updates-cursor-store.ts`：在 `data/weixin-updates` 下按账号 SHA-256 文件名保存严格版本 1
  `get_updates_buf`；目录 `0700`、文件 `0600`，临时文件原子替换，损坏、未知版本和符号链接
  失败关闭。只读诊断使用 `inspect` 复用载荷校验，不修复目录或文件权限。
- `protocol-client.ts`：实现固定 `v2.4.9` 的 `getupdates`、`sendmessage` 和 `getuploadurl`
  HTTP 合同，并按官方 AES-128-ECB、CDN 二进制 `POST` 与
  双层 key 编码发送生成图片和受限内存文件；图片与文件复用同一媒体上传管线，只在验证和
  最终消息项结构处区分；成功长轮询响应给出的下一轮建议超时只在
  1 至 120 秒边界内采用，越界响应失败关闭；出站文本限制为已验证的 4000 个 UTF-16 码元。固定 JSON API 端点拒绝 HTTP 重定向，不将首次选中的代理出口沿跳转复用。
- `inbound-message-parser.ts`：在 JSON 数字转换前保留精确 `message_id`、`msg_id` 和 `svr_id`，只输出文本、带可选说明文字的最多 4 张图片引用、
  单个一般文件引用、单个语音引用、带可选说明文字的单个视频引用或带原因的忽略事件；视频项目的原生引用沿用现有引用解析和精确消息匹配边界。受约束的引用标题、正文、局部选取信息与 ID
  独立输出，`svr_id` 优先于内嵌 `msg_id`；
  混入其他媒体、重复文本或超过图片数量上限时失败关闭；同条消息中的独立文本与音频无论先后顺序均作为unsupported-content忽略，不提交部分内容。voice_item内的转写仍属于独立语音消息，不视为额外文本项目。
- `quoted-reference.ts`：授权后组合平台正文、当前进程缓存和摘要；依据官方局部引用位置与可选
  `quotemd5` 校验选中文字，无法还原或缓存未命中时明确提示，不用整段原文代替所选片段。
  引用正文或不可用提示优先于摘要，避免摘要占满共享引用长度预算。
- `protocol-types.ts`：保存协议稳定错误类型、入站消息可辨识联合和媒体引用结构；内部消费方
  直接引用该边界，公开类型由 `index.ts` 统一导出。
- `response-validation.ts`：复用 JSON 对象、数组、受限字符串、整数与微信 API 返回码校验；只产生
  稳定 `WeixinProtocolError`，不保留上游响应正文。
- `request-abort.ts`：统一微信 JSON API、CDN 下载与二进制上传的请求超时、外部取消、监听器清理
  和 Abort 原因分类；回调拥有正文消费范围，作用域结束时终止剩余传输，覆盖非成功响应和上传仅消费响应头的分支。协议 Client 仍负责按具体操作映射稳定错误码与中文文案，资源收尾不改写先前结果。
- `fetch-body.ts`：统一微信 Fetch 响应的 Content-Length 校验、流式累计、超限取消与 Reader
  清理；直接监听请求作用域取消并终止 Reader，在读取前后复核信号，不能把取消产生的流结束当作完整正文。拒绝正文时发起取消但不等待其 Promise，避免底层取消卡住错误返回和请求作用域收尾。JSON API 将有界 Buffer 解码为文本，CDN 下载保留二进制。
- `cdn-download.ts`：统一校验固定官方 CDN 地址，并执行禁止重定向、30 秒超时和有界响应下载；
  图片与文件复用该传输边界，各自保留解密、大小、内容与完整性校验。
- `media-crypto.ts`：统一解析媒体 Base64 AES Key 并执行 AES-128-ECB 解密；图片专属 Hex Key
  入口与文件完整性校验仍留在各自边界。
- `image-store.ts`：只接受固定官方微信 CDN，按 `image_item.aeskey` 或 `media.aes_key`
  执行 AES-128-ECB 解密；复用共享 10 MiB、PNG/JPEG/WebP/非动画 GIF 签名、`0700/0600` 私有暂存和过期清理，
  CDN 地址、查询参数、key 与响应正文不进入日志或用户消息。
- `audio-store.ts`：有官方转写时由会话 Adapter 优先提交转写文本；无转写时只下载并验证
  Codex CLI 可直接读取的 MP3/OGG，最长 5 分钟、最大 20 MiB，使用一小时私有临时文件。
  常见 SILK 在未引入额外解码依赖前明确拒绝，不伪装为 WAV。
  转写文本和音频下载均在等待前序输入前登记附件取消作用域，下载前固定工作区与 Thread，`/stop`、关闭或授权变化后拒绝提交；图片与音频的 CDN 下载、解密和完整落盘共享 30 秒预算，关闭取消在途请求与写流。
- `video-store.ts`：接收官方 type 5 视频，以及文件消息中的 MP4/WebM；复用固定 CDN、AES 解密和可取消的 30 秒下载。原生视频必须有密钥，`video_size` 只校验密文字节数，不把未知单位的 `play_length` 当作时长限制。文件形式继续校验明文长度与 MD5。下载后复核授权，提交共享视频暂存器生成的单文件引用，不提交视频封面或文件路径，不直接调用 MCP。内容容器、64 MiB、24 小时有效期及容量由共享层校验；下载传递已授权会话与 Actor 供共享层去重，提交后 retain，失败 discard 不删除复用旧附件。关闭取消下载，失败或迟到的新附件清理。配置和使用见[视频分析 MCP](../../../docs/video-analysis-mcp.md)。
- `file-input.ts`：只接受固定官方微信 CDN，按 `media.aes_key` 执行 AES-128-ECB 内存解密，
  先按原始内容校验可选声明长度与 MD5，再清理常见终端转义序列并拒绝残留的不支持控制字符；生产边界只接受最多 1,000,000 字节的 UTF-8
  文本；清理后至多 32 KiB 内联，更大文本私有暂存 24 小时，路径作为用户文本交给会话 Adapter，由 Codex 工具在当前权限下按需读取。文件名、地址、查询参数、key、正文与底层异常
  不进入日志或下载错误。
- `outbound-image.ts`：读取 App Server `imageGeneration.savedPath` 映射的绝对路径或
  渠道 spool（`codexc channel send-image`）提交的图片；使用无符号链接文件句柄，限制为
  普通文件、10 MiB 和 PNG/JPEG 内容签名，不把路径或正文写入日志。
  回复窗口仍忽略原生 `imageGeneration` 操作事件，包括只有 `fileId` 的完成结果；不新增引用下载或状态通知。
- `updates-monitor.ts`：组合协议 Client 与游标 Store；按原始消息 ID 去重，普通消息在同一会话内保持
  顺序，不同会话可并行；交互回复命令使用独立的会话顺序通道，精确 `/stop` 绕过两类等待，
  均进入 Input Adapter 的既有授权边界。
  音视频在监控器等待前序消息之前，通过Input Adapter鉴权并登记接收取消范围，覆盖回复上下文持久化及会话Adapter的第二层等待。stop按接收次序取消旧范围，后续附件等待此前停止处理结束；重复消息不重复登记，结束或关闭时释放。
  轮询最多预读八个未提交批次（解析边界每批最多 100 条），达到上限后背压等待；读取游标只在内存
  前进，持久游标按批次顺序等待全部处理成功，失败不越过未完成批次。处理中消息也去重，成功消息 ID
  在本次 Surface 生命周期内保留，独立重试从失败消息继续。网络、HTTP 429 与 5xx 瞬时故障先按 2 秒重试，连续 3 次失败后
  进入 30 秒退避并继续轮询，不拖停其他 Surface；官方 `-14` Bot Token 失效返回码会暂停该账号
  一小时并记录重新 Setup 提示。未知 API 或协议错误仍失败关闭。该顺序提供至少一次处理语义：
  如果进程在 Application 已接受消息、游标原子替换尚未完成时退出，重启会从旧游标重放；
  进程内消息 ID 去重不跨重启。固定 App Server 的 `clientUserMessageId` 只形成用户消息
  `client_id`，不会按该值拒绝重复 Turn。
- `polling-health.ts`：只在当前进程内归约轮询中、短重试、退避、Token 失效暂停和停止状态，
  按 Gateway 本地时间显示当前消息到达前上一次后台成功轮询时间，并记录连续失败次数及预计恢复
  时间；不保存消息、游标、Token 或上游响应。
- `doctor.ts`：为微信内 `/wx doctor` 提供只读诊断；严格读取 Bot 凭据、当前私聊回复上下文
  和后台游标后立即降维为可用性状态，并组合进程内轮询健康与 Token 失效状态。诊断不显示或返回
  Token、`context_token`、游标正文及底层存储错误。
  渠道与 CLI Doctor 都通过游标 `inspect` 窄接口只读检查；宽权限或损坏时报告不可用，不调用运行时 `get` 的权限修复路径。
- `input-adapter.ts`：拥有单账号监控器生命周期；按微信账号和私聊 Actor 构造目标，授权后记录
  Actor、更新内存回复上下文并把文本、UTF-8 文本文件、图文或最多 4 张图片交给目录内会话 Adapter。协议边界
  兼容同一更新携带文字和多图，但微信客户端实际按单图、单文字消息发送；这些独立消息不等待、
  不按到达时间合并。图片只在
  授权后下载，整批成功后才通过共享输入批处理器转换为 PNG/JPEG/WebP/非动画 GIF Data URL 提交，不向 App Server
  传递本地路径；每张最多 10 MiB、整批最多 20 MiB。已授权用户文本按会话和精确消息 ID 进入最多 1000 条的进程内引用缓存；平台引用只在
  精确命中时补充原文，每条只缓存前 8000 个 Unicode 字符并单独记录截断状态，展示省略号不参与局部引用匹配。
  机器人消息、重启后或淘汰后的未命中引用附带正文不可用提示，消息正文不持久化。
  停止会清空引用缓存、取消长轮询，并对输入批处理器关闭及接收任务一起有限等待；媒体下载迟到时
  检查取消信号，不再提交输入。接收任务意外结束后释放本次运行状态，使 Bootstrap
  可只重启该微信账号的监控器。处理失败不推进游标，只向生命周期所有者报告稳定错误码。
- `conversation-adapter.ts`：复用 Bootstrap 注入的 Application 命令执行器和完整共享命令
  目录（包括显式启用后的 Gateway `/schedule <自然语言>` 确认预览与计划任务管理），并保留微信本地 `/start`、`/help`、
  `/whoami`、`/wx doctor`；共享解析器把
  `/h`、`/work`、`/r` 显式规范化为
  `/help`、`/workspace`、`/resume`；同一 Conversation 的普通消息处理链保持顺序，不同
  Conversation 可并行；授权且精确匹配的 `/stop` 绕过普通消息顺序器，直接进入现有共享命令
  和交互停止边界；音视频继承Input Adapter接收范围，等待此前停止处理结束后建立Application提交作用域，刷新前序输入完成后才捕获工作区与Thread；
  取消或超时返回受控提示，不停止账号监控器；视频追加当前 Turn 时复用共享追加确认。
  将说明文字和全部成功下载的图片一次
  提交；UTF-8 文本文件以明确文件名边界提交，小文本内联、大文本使用私有暂存路径。引用正文与当前
  消息明确分离，任一图片失败或总大小超限时不提交部分输入。命令解析只看
  当前消息并复用 Surface 公共模板，未知斜杠
  命令明确拒绝，不会提交为普通 Codex 输入；`/status` 在共享会话状态后追加当前微信轮询健康
  快照。无参数 `/skill` 使用稳定序号展示当前项，`/skill <名称或序号> <任务>` 直接进入共享结构化
  Skill 调用路径。`/plugin` 在共享列表后按当前页可调用项补充可复制的编号任务命令；固定协议未
  验证出站按钮或表单能力，因此不维护渠道私有选择状态。
- `command-renderer.ts`：覆盖全部结构化命令结果与用户错误；Hook 命令复用共享列表、详情和确认文案，
  Adapter 在发送边界中和 Markdown 控制字符，原样沿用 Application 的选择标识与确认令牌；组合根以共享文案检查和微信窄文字保真能力组合审查策略，命令、匹配条件或来源路径需改变时拒绝信任预览与确认，已信任项仍可启停。在命令适配边界把标题和
  `字段：值` 转换为微信客户端稳定显示的 Markdown 粗体标题与项目符号，保留已有段落和围栏代码内空白及 CRLF；Diff 单独放入足够长的围栏，原始补丁行不经过字段改写。
  速度命令、模型能力、状态和生命周期复用共享档位展示。
- `final-text-format.ts`：仅在微信最终回复边界按锁定上游的兼容集合保留标题、粗体、删除线、引用、
  列表、表格、分隔线和代码格式；中文斜体降级为普通文字，H5/H6 降级为粗体标题，普通
  HTTP(S) Markdown 链接保留并交给微信客户端渲染；Markdown 图片标记移除且不触发网络下载，图片仍只由既有
  原生图片通道发送。单行 fenced code 转为行内代码，避免客户端为单条命令生成高大的
  `TEXT / 复制` 区域；多行代码块保留，
  未闭合代码围栏降级为普通文本。
- `markdown-sanitize.ts`：中性化审批、等待式问题与 MCP 交互文案中的 Markdown 控制字符，
  避免固定布局被客户端解析为格式；异步问题保留原始 Markdown 与代码字符。
  公开窄 Hook 文字保真能力，供组合根注入 Application 审查策略；共享格式化器不导入微信实现。
  操作与计划文案不在微信展示，渠道不保留独立渲染器。
- `reply-context-store.ts`：按账号隔离、最多保留 1000 个私聊的进程内
  `actorId + context_token` 副本，支持精确撤销和整体清空。
- `reply-context-persistence.ts`：按精确账号和私聊 Actor 保存严格版本 1 的最近回复上下文；
  macOS 使用独立 Keychain Service，Linux 使用独立
  `credentials/weixin-reply-context` AES-256-GCM 私有目录，Windows 使用同目录语义的当前用户 DPAPI
  主密钥与 AES-256-GCM 记录。载荷、密文或身份不匹配失败关闭。
- `outbox.ts`：只主动发送匹配账号的 Turn 开始确认、最终正文、完成/停止/失败统计、会话空闲解除
  和全局空闲通知，以及上下文压缩开始与完成、自动审批完成结果和 Hook 完成提示。模型请求重试经相同内存快照边界，每个 Turn 最多一次重试与一次收到后续模型输出的提示，最终状态复用已有结束统计。Hook 提示复用有界内存快照投递及发送前授权检查，不落盘，开始通知不发送。自动审批开始不产生消息；完成统计仅在当前 Thread 开启自动审批时显示相关计数。
  完成统计明细由目标展示回调的 `presentationDetail` 选择，缺省 `basic`，独立于日志等级；`brief` 不展开统计。启动环境明细由组合根按启动目标注入，恢复完成记录不因当前完成通知偏好而免除投递义务。
  推理、计划、普通操作、子代理、连接、账户、额度、MCP 状态、CLI/TUI 输入镜像以及
  App Server 生成图片事件不占用微信单次回复窗口；判定集中在目录级 `delivery-policy.ts`，
  这些事件仍由其他渠道或显式查询入口展示。
  `codexc channel send-image` 使用独立的显式图片发送入口，不受事件过滤影响。完成统计保留模型、
  上下文、缓存、分支、官方 Turn 总耗时；首 Token 与速度复用共享完成卡的本轮及会话汇总，不显示模型请求
  聚合耗时。
  非 commentary 的完成正文（包括官方允许的空 phase）统一进入可靠投递，气泡与预览使用微信专用格式器；展示正文超过五个文本气泡且原文 UTF-8 不超过 1,000,000 字节时，
  发送一个有界预览和内存生成的 `codex-final-answer.txt`。文件逐字保留最终正文原文，包括 Markdown 图片说明、链接和代码，不加入后台任务展示前缀，不读取任意路径；原文再大时保持原有
  有界截断。正文分片、文件预览及失败后的剩余文本均在跨片时闭合并重开代码围栏，新增围栏计入字符预算；单行代码超出气泡预算时会在显示边界换行，需逐字内容时以原文文件为准。文件发送明确被平台拒绝且回复上下文仍有效时，从预览截断点继续发送剩余文本，总计仍不超过五个气泡，并让原异常
  进入共享队列的脱敏日志。发送时重新检查 Actor 授权，通过共享 Conversation 队列顺序发送，
  单条最多 4000 个 UTF-16 码元、最多五条并显示截断提示，避免拆开代理对。固定 v2.4.9 合同尚未
  验证可用的出站原生回复字段，普通 Turn 继续发送普通消息。文本、图片和文件发送按目录级
  `delivery-retry.ts` 做有界重试：只有平台业务返回码拒绝以及 429 才重试，最多三次并按
  指数退避；超时、网络中断和响应不可解析不重试，回复上下文失效（返回码 -2）作废上下文后交给
  用户重发，避免重复气泡或重复上传。重试等待期间被取消时，取消错误保留原始发送错误作为 cause，
  便于从日志定位平台返回码。队列关闭或 Conversation 取消时，
  文本、图片、文件和完成回退会接收取消信号；关闭立即取消输出，每次新平台调用前复核，
  等待读图、分片或重试的任务不能在关闭后继续发送。已发请求按实际结果结算，关闭仅有限等待，不能撤回平台已经接收的消息。微信协议客户端支持在 Fetch 层中止请求，与平台无关的状态展示
  不会因取消继续发送。
- `interactions.ts`：命令、文件和临时权限审批使用 96 位随机、一次性、限时的 ID，提示用户完整
  复制 `/批准一次 <id>`、`/批准会话 <id>`、`/保存命令规则 <id>`、
  `/保存网络规则 <id> <序号>` 或 `/拒绝 <id>`；同一审批的选项优先合并到一个 Markdown
  消息，每个选项使用独立代码块提供单独复制入口，超长时只在完整选项之间分组；只接受当前请求实际
  提供的原值决定，并再次绑定账号、Conversation、唯一授权 Actor、Thread、Turn 和请求 ID。
  裸数字、“同意”、畸形、未知、重复、过期或跨账号/Actor/会话命令不会批准。最多三个非敏感
  用户问题通过 `/选择 <id> <问题序号> <选项序号>` 或
  `/填写 <id> <问题序号> <答案>` 分项收集，全部完成后一次返回原问题 ID；敏感问题明确取消。
  异步问题明确提示任务继续执行，题干和选项保留原文，与回答命令分开；在 4000 个 UTF-16
  码元内预分片，跨片重开并闭合反引号或波浪线围栏，未闭合题干不会吞入后续命令。
  围栏自身无法在单条消息内完整展示，或全部提示超过 16000 个码元时，明确取消请求。
  MCP form 只接受 `/提交表单 <id> <JSON>` 后不超过 1000 字符的有效 JSON；MCP 工具审批按
  上游提供的范围接受 `/批准一次 <id>`、`/批准会话 <id>` 或 `/始终允许 <id>`，不要求填写
  JSON；URL 模式只显示 HTTP(S) 链接并接受 `/完成 <id>`。各类交互均可用 `/取消 <id>` 安全取消，答案和表单正文
  不写入日志或持久化存储。
- `surface.ts`：共享一个内存回复上下文组合 Input、Outbox 与 InteractionPort；启停时通过
  官方 `notifystart` / `notifystop` 合同完成在线状态对账；启动时只为当前允许名单中已知且存在
  加密回复上下文的私聊恢复收件人并发送上线通知，不要求当前仍有 Thread 绑定。状态对账或聊天
  通知失败不停止长轮询；
  微信发送接口以 `-2` 拒绝回复上下文时，只清除该 Conversation 的内存与加密记录，等待后续
  入站消息自然写入新上下文；其他发送失败保留最近回复上下文；
  临时渠道故障只取消当前交互，恢复后仍可接收新的审批、用户输入和 MCP 请求；最终停止时才永久
  关闭交互端口，并先取消输入、再取消交互和输出，有限等待在途操作结算，重复停止安全。配置热加载、重启提示与持久化
  Workspace 新增通知复用同一授权绑定和回复上下文边界；没有安全收件人提供器时持久化通知失败关闭，
  不提供一般主动推送。
- `index.ts`：微信模块公开入口。

命令、状态和 Doctor 的结构化标题与字段使用 Markdown 粗体标题和项目符号；其他短通知
保留紧凑硬换行和既有段落，生命周期结构化字段使用项目符号，不把每个字段扩成独立空行；
围栏代码正文不插入硬换行空格，最终回复仍由独立的 Markdown 兼容格式器处理。

二维码、验证码和入站消息正文不持久化；待送达输出由共享独立投递箱加密保留；解密图片只进入受限临时目录并按统一保留期清理；
最近回复目标和 `context_token` 只进入独立加密回复上下文
后端，长轮询游标只进入独立检查点，二者都不进入 Bot 凭据、TOML、SQLite 或日志。未知版本、
身份不匹配、密文或载荷损坏失败关闭，不能当作未配置后静默
重新扫码。微信目录通过一级 `src/surfaces/index.ts` 公开运行时组合所需的窄接口，并由 Bootstrap
内置插件装配安全凭据 Client、游标 Store、精确 Access Policy 和生命周期故障上报。
