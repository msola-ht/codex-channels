# Telegram Surface

Outbox 的完成通知消费目标 `completion` 设置；成功隐藏时沿原队列结算计划、操作缓冲、正文流、输入状态与回复/审批引用，不新增完成卡。过期或撤权仅清理精确 Turn 的本地预览；正文收尾失败仍在原授权下尝试独立提示。实时版式在准入时固定，已入箱完成记录恢复时默认完整呈现。

本目录实现 Telegram Bot 适配器，把聊天、命令、图片、一次性音频、视频附件、UTF-8 文本文件和按钮交互连接到平台无关
的应用与核心模块。

所有普通消息、命令、附件与按钮入口只接受 `chat.type=private`；长轮询预接收的附件和停止事件在登记任务作用域前执行同样检查。群内入口只提示使用私聊，不进入任务或交互。Bot 以最多 4,096 项的进程内地址/Actor 映射记录已授权私聊证明，撤权复核时删除相应证明、关闭时清空；该映射只选择展示范围，不授予投递权限。重启或容量淘汰后，未证明的旧目标仍保留绑定，可选实时工具、计划和思考保守隐藏，收到授权私聊输入后恢复按配置解析；已入箱终态继续独立渲染与投递。

显式 `channel send-file` 复用共享文件 spool 和绑定路由；file/video/voice 分别使用原生 sendDocument/sendVideo/sendVoice，最多 50,000,000 字节，视频 MP4、语音 Ogg/Opus。类型校验与飞书共享受控内容规则，不按扩展名推断，不转码。Outbox 沿原有队列及 API Executor，一次请求不自动重试，以有效 message_id 确认；总预算 120 秒、SDK 单次请求 30 秒。显式图片和文件携带原 Thread 守卫及取消信号，读取前后与 API 调用前复核，支持 spool 停止取消。这些新增路径尚未部署或真实客户端验收。

## 文件

- `index.ts`：Telegram Surface 的公开导出入口。
- `constants.ts`：Telegram Surface 的稳定账号标识。
- `bot.ts`：提供 Bootstrap 使用的单一选项工厂，注册 Telegram SDK 处理器，执行访问检查，
  把标准命令或普通输入提交给 Application；模型按钮以精确 Provider 与模型身份提交，
  不因回调等待期间的订阅变化重新选择其他账户的同名模型；
  模型、Provider 与思考按钮在平台等待后复核原 Workspace/Thread/Session，失效按钮不将选择保存给新会话。
  同一 `media_group_id` 的图片按 Actor 合并为一次最多 4 张的 Application 输入；静态 GIF 无论作为文档还是
  `animation` 消息到达都进入相同内容校验，真正的动画 GIF 会被拒绝；共享输入批处理器在提交时
  将已校验的 PNG/JPEG/WebP/非动画 GIF 暂存文件读取为 Data URL，不把本地路径交给 App Server；
  普通文字、单图和没有相册标识的独立图片立即提交，不用时间窗口猜测图文关系；
  原生 Voice/Audio 最长 5 分钟、最大 20 MiB，只在下载后验证为 WAV、MP3、M4A、WebM 或 OGG
  才构造稳定 `localAudio`，私有临时文件一小时后清理；Application 仅在当前模型目录包含
  `audio` 时提交，否则在创建或追加 Turn 前明确拒绝；
  音频在等待前序输入前登记附件取消作用域，下载前固定工作区与 Thread，`/stop`、关闭或授权变化后拒绝提交；图片与音频下载携带取消信号，并在取得地址、读取完整流和落盘之间共享 30 秒总预算；
  `video`、`video_note` 与视频文档在鉴权后下载，只接受内容签名通过校验的 MP4/WebM，
  保留说明和原生引用，通过视频附件标识提示当前会话调用独立视频 MCP，不暴露本地路径或原文件名；
  接收时先登记Surface取消范围，等待此前停止处理结束后建立Application提交作用域；刷新前序输入完成后、下载前捕获工作区与Thread，提交时在会话锁内复核绑定和授权，绑定改变时明确拒绝；
  未配置 `videoDirectory` 时明确拒绝视频，关闭时取消下载，迟到结果不提交；
  普通文本与图片说明可读取 `reply_to_message` 自带的文本或说明文字并作为明确引用上下文提交；
  `/queue add|list|update|delete|reorder|start` 管理 App Server 持久 Queue，`/schedule <自然语言>` 由前台 Agent 调用 `schedule_task` 工具生成确认预览，`/schedule` 管理显式启用的
  Gateway 计划任务；创建与删除预览直接提供原生确认/取消按钮，确认仍复用五分钟一次性令牌；选择支持多个思考等级的模型后及直接打开 `/effort` 面板时提供思考等级内联按钮；
  同时发送热加载、自动重启、重装要求和失败等配置
  生命周期通知，Workspace 新增通知带直接切换按钮；启动消息只使用组合根注入的 Gateway
  版本字符串和当前 Workspace Git 分支，不读取生成协议。
  空闲解除通知在能确定唯一授权 Actor 时附带“恢复此会话”按钮，仍保留 `/r` 命令；随机一次性
  令牌绑定接收者、聊天、通知消息和 Thread，10 分钟有效，最多保留 100 项，关闭时清空。
  点击复用 Application 的恢复命令与工作区检查；过期或重启后的按钮提示使用原通知中的命令。
- `command-renderer.ts`：复用共享命令结果映射，负责 Telegram 专属展示、按钮和消息发送；模型按钮的随机令牌
  绑定当前模型、浏览范围、有序选项、页面所属 Conversation/Workspace/Thread/Session 与 Actor，
  不能跨目标或操作者复用；最多保留 1000 份菜单状态。列表变化或状态淘汰后旧按钮明确失效，
  不按新列表重新解释旧序号。
  思考等级提交后的新菜单按与刷新相同的 Provider 浏览范围及可选目录生成；操作本身仍用当前模型所属目录验证能力，真实目录或会话变化继续使旧按钮失效。
  模型与提供商菜单复用共享速度档位展示；速度命令及能力提示复用共享命令格式器。
  思考按钮依据目录能力将 `enabled` / `none` 显示为开启/关闭思考，其他等级原样显示，回调仍引用原始目录选项；
  重置券复用内联按钮，选券令牌绑定用户、聊天与实时列表，
  确认及取消调用 Application 的一次性确认入口。
  Hook 列表、详情和确认使用 HTML 面板及内联按钮，仅格式化系统标题与字段标签，命令、路径和说明始终按字面值转义；回调显式传递 Actor，保留 Application 的快照
  选择标识及一次性确认令牌，不在渠道中推导配置 Key 或重复实现持久修改。
- `outbox.ts`：通过 Surface 共用的每 Conversation 有界顺序队列协调流式回复和审批显示顺序；
  空闲解除通知沿原队列发送，恢复按钮只附在面板最后一段，确认消息 ID 后由 Bot 登记令牌；
  发送失败交回原投递链路，不另建重试或发送队列。
  普通 Turn 输入会在内存中绑定到精确消息 ID，“已开始处理。”、阶段性最终正文和最终正文均使用
  `reply_parameters` 原生回复该输入；回复目标保留到 Turn 结束、断线或关闭时清理；
  可见操作结果或生成图片入队前会先刷新同一 Turn 仍在合并窗口内的正文，避免过程通知越过说明文字；
  思考按工具边界拆分为独立流程段，同一思考段可增量编辑并在工具开始时收尾；命令和文件等操作各自
  使用独立的可编辑过程消息，不把整个 Turn 的操作堆到同一条消息；
  活动非终态流最多保留 100 个，单流正文最多保留 1,000,000 个 Unicode 字符并明确标记截断；
  每个 Turn 开始时发送共享确认；每轮状态卡复用共享生命周期字段，显示当前 Workspace Git
分支、官方 Turn 总耗时、模型请求与 Token 统计、当前 Goal、上下文压缩总次数和用量；不显示
  模型请求聚合耗时；首 Token 与速度复用共享完成卡的本轮及会话汇总。最终回复默认使用兼容 HTML，也可选择
  Telegram 原生 Rich Markdown；已完成且非 commentary 的短正文即使未提供 phase，也按该设置格式化，
  HTML 长回复按 3500 可见字符单位分段；选择 rich 时按完整块规划每片最多 5000 个 Unicode 码点，与飞书和 QQ 主动 Markdown 正文的阅读预算一致，不再被 HTML 长消息路径提前截走。超大或未闭合块、交互保留标题在发送前选择 HTML；超过 16000 字符或满足现有长代码条件的正文仍使用预览加附件。明确的格式拒绝只降级当前分段；网络结果不确定时停止本次发送，Turn 完成不重播失败正文；完成的原生 `imageGeneration`
  PNG/JPEG 经过共享安全读取边界后使用 `sendPhoto` 静默发送，且不受操作过程显示档位影响。
  只有上游 `fileId` 而无 `savedPath` 的完成结果独立提示“图片已生成，但当前无法获取图片内容”，
  不显示引用或声称图片已发送；持久恢复保留该状态但不保存引用，`hidden` 同样保留提示。
- `approval-operation-coordinator.ts`：隔离审批请求与操作日志之间的等待、拒绝抑制和 Turn 清理状态。
- `text-streams.ts`：拥有按 Conversation、Turn、Item 隔离的正文流、刷新计时器、消息 ID、首次发送结果未知状态及每 Turn 的正文提醒状态；处理最终 HTML/Rich Markdown、长回复与附件降级，复用 Outbox 的同一投递队列与只读回复目标。
  增量只接收实时 Turn 开始所建立的当前授权活动身份；最多保留 100 个身份，超限淘汰最旧的非关键预览并记录容量告警。
  Outbox 的 `admitLive` 在普通与持久模式发布时固定正文身份；富化副本继承 `liveAdmitted` 上下文，不能在迟到路由时重新建立旧身份。普通模式仍按消费顺序处理展示生命周期，持久模式保留发布时观察；准入与展示清理分离，迟到断线清理不会撤销恢复后的新正文身份。
  撤权、断线或淘汰会取消对应预览和排队操作，不保留等待终态清理的撤权墓碑；重新授权后的新 Turn 可立即建立预览。
  重连时由权威活动恢复重新发布 Turn 开始；缺少该身份的增量安全省略，完整 Item 仍独立按当前授权投递。
  排队预览固定原流身份，迟到操作不会刷新同键新流；可靠完整正文独立持有原文及当前授权，不能复用已撤权缓存，须取得平台发送确认。
  空白 commentary 由 Outbox 明确省略并清理对应流。
  持久操作终态的发送不重新执行当前显示准入；后改 hidden 或 compact 仍保留可见完整或精简表示。相同 Item 的同内容终态需要确认时重新调用平台编辑，明确的 message is not modified 沿原有编辑确认合同处理；其他 Item 不因此重复刷新。审批拒绝抑制保持原规则，不能以显示偏好绕过。
- `message-options.ts`：正文、操作与面板共用的原生回复、静默和 HTML 消息选项。
- 通知策略按逻辑事件降噪。Gateway 启动、CLI 输入镜像、思考/过程增量、操作过程、Turn 结束统计、
  账户/额度更新、普通 warning 和同一回复的后续分片使用 Telegram `disable_notification`；
  同一 Turn 的首个最终回复、审批或用户输入的最后一段、Turn 失败或异常终态、连接断开、MCP
  失败、配置变更和用户主动执行的命令结果保留普通提醒。审批前置长内容只静默发送折叠分片，
  最后带按钮的消息始终开启提醒；静默只控制客户端提醒，不改变队列关键性和失败处理。
- `html-format.ts`：安全转义并分块渲染命令面板、启动通知、审批卡与 Diff；标题由显式 Markdown 标题或调用方提供，不根据首行位置推断。字面面板只呈现系统标题与字段标签，保留外部字段中的 Markdown 符号与反斜线。面板代码围栏转为代码块并在分片时保持闭合；生命周期卡中的 Client 纯文本摘要在此 HTML 呈现边界转义，不由 Client 或 Core 做富文本转义；审批详情整体使用
  Telegram 原生可展开引用，收起时由客户端显示开头与省略标记，点击后才展开完整内容；超出单条
  消息限制时仍按完整引用边界安全分片。
- `markdown-format.ts`：把常见 Markdown 块与行内样式安全转换为传统 Telegram HTML；
  与长回复规划及其他渠道共用纯围栏状态推进，保留独立的 HTML 转义、语言标签与分片预算。
  HTTP(S) 链接转换为可点击链接，Markdown 表格降级为紧凑的粗体表头与项目符号行；
  仅包含 Bot 命令的文本代码块和行内命令会转为可点击纯文本，普通代码块保持不变。
- `long-message-format.ts`：按选定的 HTML/rich 格式统一规划终端或 Telegram 发起 Turn 的回复；rich 按完整块分片，普通 HTML 跨分片保留格式，超长代码与内容使用预览加内存文件。
- `operation-format.ts`：把操作记录分组、截断、脱敏并按完整或单行摘要模式渲染为 Telegram
  HTML；完整模式同时显示状态、耗时和退出码。
- `typing-indicator.ts`：维护活动请求和 Turn 的 Typing 状态、刷新与限速。
  Outbox 将模型请求重试独立呈现为可编辑状态消息，复用共享 `turn-retry-presentation.ts`，不受思考或操作显示设置影响。
- `interactions.ts`：发送一次/会话/命令前缀或网络规则持久审批以及用户输入卡片，按协议能力显示
  互不混淆的按钮；同时存在的异步问题与阻塞输入按原消息 ID 路由文字回复；用户问题与 MCP 表单统一保留最近 1,000 条文字回复目标的消息身份（仅内存），已处理或失效的回复不进入普通会话输入。
  重启或缓存淘汰后，通过当前 Bot 的非转发消息来源、首行固定粗体“Codex 交互回复”及精确格式识别失效回复；
  普通问题、异步问题与 MCP 表单的所有分片均保留标记，当前问题的全部分片都可回复；支持自由文字的选择题显示“输入回答”按钮，点击后通过 ForceReply 提示在底部回复栏填写；无选项问题直接显示回复提示。切题或进入文字输入后，旧分片失效，按钮与状态更新仍使用末尾消息。
  普通及异步题干统一复用安全 Markdown 渲染，标题、问题标签与操作提示独立转义；MCP 表单和工具字段按字面值呈现；处理结果转义并按消息剩余长度限长。
  普通面板和 Markdown 回答遇到相同首行时保留文字及链接等格式、移除首行加粗；Rich Markdown 同名首行使用
  受保护的 HTML 渲染，避免普通回复生成交互专用标记。
  网络会话按钮显示目标主机，持久按钮明确显示允许/拒绝动作和主机，并处理
  超时、回调和跨客户端失效。MCP 工具审批使用独立按钮，并只显示上游提供的一次、会话或始终
  允许范围，不进入 ForceReply JSON 输入。同一请求 ID 只允许一个待处理交互，同时最多保留 100 个；固定选项
  和多问题回复完整验证；切题的更新与发送均检查请求是否取消，迟到的新题消息清除交互入口。
  Gateway 关闭期间未完成的消息发送不会重新建立交互；交互端口复用同一关闭结果，准备清理窗口结束后不再发起状态更新，
  状态排空窗口结束后中止自有清理等待和排队请求，不依赖 Outbox 随后的关闭来使迟到清理失效。`/stop` 取消
  当前聊天最新交互后仍进入共享 Turn 停止命令。初始交互使用 Conversation
  优先有序通道，会排在等待中的非关键流式或状态输出之前；最终带按钮的审批消息保持通知开启，
  长内容的前置折叠分片静默。发送成功或失败只记录脱敏身份和平台错误分类。
- `lifecycle.ts`：Bot 命令注册、Long Polling、连续且属于同一原生媒体组的并发准备、包含系统、会话与 Git
  分支摘要的启动联通通知，以及可取消关闭；拉取循环与普通更新处理使用有界分离通道，精确的
  `/stop` 绕过普通输入和交互响应等待，仍进入现有授权命令处理链。
  沿平台接收顺序登记音视频取消身份和停止边界，再调度紧急命令；停止识别复用SDK命令实体和机器人用户名规则，并要求无参数，普通文本不会触发附件取消。
  审批回调及已知交互消息的文本回复进入独立的会话顺序通道；普通更新保持会话内顺序，不同会话最多并行处理 8 组，媒体组内仍并发准备。
  普通积压最多 1000 项，控制任务最多 100 项；达到上限时暂停拉取，尚未收到的控制消息仍受平台拉取背压限制。只有当前批次全部成功放入对应
  有界通道后才推进 Long Polling offset；关闭时最多等待更新处理 5 秒，超时只记录未完成数量，
  不记录消息正文，也不让 Surface 生命周期无限悬挂。
  有界重试耗尽后向 Bootstrap 报告渠道故障，由该
  Telegram 实例独立退避重连，不停止 Gateway 或其他 Surface。
- `api-executor.ts`：统一执行 Telegram API 调用，处理超时、限流和有限重试；新建消息仅重试明确的限流拒绝，编辑与删除可重试网络异常及服务端错误。每次实际请求前复核目标已登记 Actor 的当前授权，队列与正文计时器捕获可取消的授权范围；热撤权取消无剩余授权 Actor 的目标，重新授权不恢复已取消操作。显式配置通知允许名单内用户自身私聊没有既有绑定，普通输出不把 Chat ID 当作 Actor。`editMessageText` 入口在检查点结算前将该方法明确返回的 `400 message is not modified` 归一为确认，正文、操作与交互共用该入口；取消不能归一为成功。启动通知和直接命令回复仍走各自 SDK 调用路径。
- `sdk-signal.ts`：在 SDK 边界保留原生取消信号身份，并适配 grammY 的信号类型声明。
- `error-metadata.ts`：只保留异常类型、受约束的机器错误码及消息未变化分类，不记录任意异常消息。
- `user-error-renderer.ts`：把平台无关的结构化用户错误映射为 Telegram 专属提示与命令用法。
- `plugin-task-prompts.ts`：把 Plugin 选择后的 ForceReply 提示绑定到聊天、Actor 与精确消息，
  使用十分钟一次性内存状态和 100 项容量上限；过期、跨 Actor 与重复回复不会进入普通 Turn。
- `format.ts`：格式化会话、Diff/Plan、Goal、模型、Workspace、Git 分支、权限、用量、缓存命中率、
  上下文压缩总次数和状态文本；可复用语义委托给 Surface 共享格式器，账户、额度与 MCP 运行状态
  由 `runtime-status-format.ts` 提供；上线通知复用 Surface 共享生命周期字段并把结构化字段渲染为
  紧凑项目符号列表，`/status` 与 Turn 结束统计均显示当前 Workspace Git 分支。
- `file-download.ts`：统一通过 Bot API 定位文件，并执行支持 HTTPS 代理、超时和状态校验的下载；
  图片与文本文件复用该传输边界，各自保留大小、内容和错误语义校验。
- `image-store.ts`：安全获取 Telegram 下载地址和下载流；大小、内容签名、私有暂存与过期清理
  复用上层 `managed-image-store.ts`。
- `audio-store.ts`：复用统一文件定位与下载边界，把受支持音频交给
  `managed-audio-store.ts` 验证、私有暂存和一小时清理。
- `video-input.ts`：复用统一文件定位与可取消下载边界，在平台声明、响应长度与实际流三个位置
  执行 Telegram 的 20 MiB 上限，整体下载预算 30 秒；共享 `video-attachment-store.ts` 拥有
  私有暂存、MP4/WebM 内容校验、24 小时过期与容量控制，目录由 Bootstrap 显式注入。下载传递已授权会话与 Actor 供共享层去重，提交后 retain，失败 discard 保留复用旧附件。
- `file-input.ts`：通过 Bot API 在内存下载最多 1,000,000 字节的普通文件，严格验证文件名、
  UTF-8，文件流读取总时限为 30 秒，清理常见终端转义序列并拒绝残留的不支持控制字符，返回有界文本；二进制正文不进入 Application；清理后至多 32 KiB 内联，更大文本私有暂存 24 小时并提交执行端路径。单个
  UTF-8 文本文件的文件名、说明文字、正文解析和最终原生回复已通过真实 Bot 主路径验收；
  超限、二进制拒绝与多文档相册仍只经过离线边界验证。

Telegram 网络调用不得阻塞 App Server Reader。每个 Conversation 的最终输出保持顺序；审批卡状态更新必须先于批准后的操作展示。图片下载必须限制大小、路径、类型和保留时间，文本文件下载
必须保持有界且严格验证 UTF-8，暂存复用共享文本附件生命周期。
Bot API 与文件下载使用 Bootstrap 按 `api.telegram.org` 选择的统一 HTTP(S) 代理；共享代理
遵循 `NO_PROXY`，Telegram 私有 `proxy_url` 作为显式覆盖。Bot API 的代理连接启用 Keep-Alive，
由 Surface 关闭时释放连接池；主动取消的请求不进入自动重试。
下一 Turn 输入由 App Server Queue 持久保存，Application 提供受控管理入口，不得复用本目录的 Telegram 输出队列；Telegram 只负责
命令解析及位置、容量和 App Server 持久队列语义提示。`/queue list` 还提供当前业务页的刷新、分页和条目入口；
条目按钮使用完整 Queue ID，进入后可启动或删除，删除必须二次确认。新增、更新和排序继续使用文本命令，
不建立渠道私有 Queue 状态。
Telegram 手动命令注册显式接入三个渠道共享的 `/h`、`/work`、`/r` 快捷入口，分别执行
`/help`、`/workspace`、`/resume`；快捷入口不重复写入 BotFather 菜单。帮助消息复用共享的
分组列表，只在 Telegram 边界转换为安全 HTML。无参数 `/skill` 与其他渠道一样展示编号列表，
调用统一使用 `/skill <名称或序号> <任务>`，不维护渠道私有选择状态。
`/plugin` 在共享文字列表上增加当前页可调用项和未过滤列表的翻页按钮；选择后通过一次性
ForceReply 收集任务，再使用完整 Plugin ID 进入共享 Application 调用边界。搜索结果仍保留
可复制的文字翻页命令，避免把搜索词写入 Telegram callback data。
会话列表只支持官方 Pinned 状态，固定与取消固定分别复用 `/pin` 和 `/unpin`；改名继续使用共享
`/rename` 文本语法，渠道不维护自定义分区目录或权限。
审批请求晚于操作消息发送时，Outbox 必须撤回已经发送的命令消息，不能只清理内存状态。
账户额度和 MCP 状态通知也必须进入每聊天有界输出队列；不得从 App Server Reader 直接等待 Telegram 网络发送。
结构化用户错误由 `bot.ts` 转换为 Telegram 专属文案；App Server Turn、warning 和 MCP 错误会
显示 Client 边界已经统一脱敏并限长的详情，未知异常和原始响应正文不写入 Telegram 日志或外部消息。
上下文压缩开始与完成复用共享去重和文案，分别立即入队为独立通知，不受操作显示设置影响。
共享配置 `display.operation_updates` 为 `full` 时显示完整操作详情、状态、耗时和退出码，
为 `compact` 时显示一行状态、元数据和最多 160 个字符的详情摘要，为 `hidden` 时不发送操作
过程；命令、文件、图片和子代理等操作按 item 独立发送并在同一消息内更新状态；成功的 MCP、动态工具和网页搜索按 Turn 延迟到最终回复前聚合，单项保留详情，多项显示
一次分类计数和最多 8 个去重后的详情及各自次数，超出时明确省略数量。失败与拒绝保持即时展示。
审批、错误、最终回复和 Turn 完成统计保持原有行为。
`display.plan_updates = true` 时，官方自动计划先发送一次静默 HTML 清单，每个步骤首次完成时
再发送一条紧凑 HTML 进度，均消费共享标题和列表格式；默认开启，可通过 `display.plan_updates = false` 关闭，不解析模型正文，也不改变 `/plan` 模式。
思考状态只显示“思考中…”；同一思考段的耗时可以在原消息中增量更新，但工具或命令开始后会先把
当前思考段收尾，后续思考使用新的独立消息，不展示推理摘要或思维链内容；`display.reasoning = false`
时不显示。
