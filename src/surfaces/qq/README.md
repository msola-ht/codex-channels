# QQ 单聊 Surface

首个实现切片采用 AppID/AppSecret、WebSocket 和允许名单内的纯文本单聊；凭据由 Setup 扫码取得或手工填写。
接入统一配置、Policy、Application、SurfaceManager 与加密投递箱，不维护会话历史。
用户实录与 App Server 只读历史已交叉确认普通模型轮次及 QQ 回复，`/help`、`/status` 已有用户实测记录；
人工交互、停止/恢复及异常边界尚未验收，详见 [QQ 推进计划](../../../docs/qq-surface-plan.md#真实对话核对与下一阶段推进)。
协议参考固定 SDK 与 2026-10-23 官网快照，不能据此保证所有账号权限。

## 文件

- `index.ts`：QQ 模块公开入口。
- `surface.ts`：单聊事件解码、授权、有限准入、共享命令与 submit、回复关联和完整文本发送。
- `protocol.ts`：固定官方 HTTP 端点、Token 合并刷新、有界响应、取消与结构化成功判断。
- `transport.ts`：WebSocket 鉴权、心跳、有限重连、接收序号和生命周期。
- `ledger.ts`：独立加密传输登记；保存消息身份、发送次数、Thread/Turn 关联，不保存正文或附件 URL。

当前只接受文档定义的 `message_type=0`、`message_scene.source=default`、唯一 `msg_idx` 的纯文本。
去重身份包含账号隔离、Actor、消息 ID 和 msg_idx；同一源消息共享最多四次被动回复预算。
未知/混合/引用输入不提取其中的文本执行。消息时间必须有效、晚于本实例创建且不晚于当前时间；
超过五分钟拒绝，绝不以接收时间刷新窗口。相同时钟秒内的启动前后消息也可能被保守拒绝。
最多登记 500 条五分钟内身份，最多 32 个处理中输入；重复事件不重复调用 Application。

提交前持久登记 `claimed`。实际 submit 返回后才关联 Thread/Turn；输出最多等待已有提交句柄十五秒，
不等待命令回复或完整模型执行，不阻塞 App Server Reader。无法证明关联时保留未确认结果。
已有关联的结果不等待同会话后来的提交。完成的本地命令标记 `handled`，任意登记写失败使当前代次失败关闭。
命令回复在共享用例内捕获操作后的工作区/Thread 守卫，实际发送前再次复核。
steer 不把已有 Turn 的回复来源改为最新来信。首次原始消息额度用尽或过期后不自动借用其他消息。

完整最终文本和 Turn 终态进入共享投递箱。文本按 Unicode 字符切分为最多 3000 UTF-8 字节的片段，
完整正文上限 12000 字节且最多四片；Unicode 边界产生第五片时整条拒绝发送。
首片前原子预留完整结果所需次数，剩余额度不足不部分发送，未知结果不释放预留。每片实际确认后才允许整条结算，
额度不足、超长或发送失败保留结果；不会以截断摘要确认全文。过程 commentary 不自动发送。
明确失败/拒绝操作和普通警告也保留；警告无法证明具体 Turn 回复来源时保留为未确认，不静默丢弃。

重启不复用旧实例 ReplyGrant，即使元数据备份恢复，也不会自动恢复旧消息发送额度。
旧结果继续由共享投递箱保留，本机可核对或按现有维护合同处理；当前没有把新来信绑定旧结果的重发入口。
元数据使用独立 `qq-transport` 目录、macOS `codexc-qq-transport-v1` Keychain 命名空间，版本不兼容失败关闭。
备份应停写并保留配置、加密记录及密钥；回滚先禁用 QQ，保留旧记录和投递箱，不删除数据绕过版本检查。
WebSocket Resume 按官方顺序先接收补发、最后接收 RESUMED；代理 CONNECT 和 HTTP 池由 Bootstrap 注入的每代次网络对象拥有并关闭。

审批、用户问题和 MCP elicitation 当前立即返回共享安全决定，不开放未经平台实测的一次性文字交互。
仅 `/help` 列出的现有会话命令可用；可能启动额外 Turn 的命令、Hook 写入、计划任务、附件、图片、流式、
Webhook 暂不支持。扫码仅属于 Setup，运行时仍共用同一配置和授权链路。
计划任务同时在共享业务授权入口拒绝，不只隐藏 QQ 菜单。
配置通知没有原始回复依据时明确失败；不自动切换主动发送，不伪造送达。
