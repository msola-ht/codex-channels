# QQ 单聊 Surface

采用 AppID/AppSecret、WebSocket 和允许名单内的文本、图片、图文及受限音视频单聊输入；凭据由 Setup 扫码取得或手工填写。
已实现 QQ 正文转换、共享命令结果和失败/终态呈现；`b103450a` 部署后用户确认状态、帮助分段、权限展示及完成面板正常，400 行长结果文件交付和完整性正常。
接入统一配置、Policy、Application、SurfaceManager 与加密投递箱，不维护会话历史。
模块职责及功能语义以现有飞书/TG 和 Surface 共享合同为对齐基线；QQ 上游文档仅核验渠道协议、格式与限制。
当前实机确认限于明确列出的成功路径，不替代复杂正文结构与异常链路验收。
用户实录与 App Server 只读历史已交叉确认普通模型轮次及 QQ 回复，`/help`、`/status` 已有用户实测记录；
人工交互、停止/恢复及异常边界尚未验收，详见 [QQ 推进计划](../../../docs/qq-surface-plan.md#真实对话核对与下一阶段推进)。
渠道协议以 2026-10-23 API V2 官网快照为准，固定 SDK 仅作实现对照，不能据此保证所有账号权限。

## 文件

- `index.ts`：QQ 模块公开入口。
- `surface.ts`：单聊事件解码、授权、有限准入、共享命令与 submit、精确任务来源、主动发送与独立原生 Markdown 流状态机。
- `protocol.ts`：固定官方 HTTP 端点、明确主动/被动发送模式、原生 stream_messages、Token 合并刷新、媒体上传、有界响应、取消与结构化成功判断。
- `media-download.ts`：图片、音频和视频共用的可信附件地址约束，音视频无凭据、无重定向下载。
- `image-store.ts`：QQ 图片下载适配，复用共享私有图片暂存、格式校验和清理。
- `audio-store.ts`：可信 WAV 下载、严格 PCM 分块与时长核验，复用一小时音频暂存。
- `video-store.ts`：MP4 下载、长度与类型核验，复用共享视频附件的作用域、保留和清理。
- `quoted-reference.ts`：有界核验原生引用索引和引用树，只提取上下文文字及固定附件说明，不下载引用附件。
- `content.ts`：按 QQ 官方文字 Markdown 转换正文，处理样式、链接、列表/引用分片单元和连续留白，保留代码/未知语法的完整文本及面板字段字面意义。
- `rendering.ts`：完整结果与可读纯文本、按单次分片预算合并/规划消息及共享操作/终态呈现；权限/重命名/会话/指标的字面字段面板优先避免多余分片，普通帮助仍可混合格式。
- `transport.ts`：WebSocket 鉴权、心跳、有限重连、接收序号和生命周期。
- `ledger.ts`：原有加密被动登记及独立主动计次/流式屏障登记；仅保存传输身份、哈希、时间和计次，不保存正文或附件 URL。
- `interactions.ts`：共享决定与待处理 Registry 的 QQ 适配；命令、文件、网络、临时权限、终端输入、MCP 工具审批、普通 MCP 表单及问题，按原请求呈现授权范围和精确回应。

当前接受文档定义的 `message_type=0` 普通输入及 `message_type=103` 原生引用，要求 `message_scene.source=default`、唯一 `msg_idx`；当前消息支持文本、PNG/JPEG/GIF 图片、单语音或单 MP4 附件。
去重身份包含账号隔离、Actor、消息 ID 和 msg_idx；同一源消息共享最多四次被动回复预算。
未知类型、混合媒体、非法 Unicode 正文和无效引用结构不提取其中的文本执行。消息时间必须有效、晚于本实例创建且不晚于当前时间；
超过五分钟拒绝，绝不以接收时间刷新窗口。相同时钟秒内的启动前后消息也可能被保守拒绝。
最多登记 500 条五分钟内身份，最多 32 个处理中输入；重复事件不重复调用 Application。

图片与图文一条消息一次提交，不按时间合并独立消息；同条最多四张、单图 10 MiB、总计 20 MiB，GIF 仅非动画。
附件先按顶层 Actor 授权，只接受固定资料示例中的 HTTPS `multimedia.nt.qq.com.cn/download` 地址，不接受其他主机、路径、
身份凭据或片段，不跟随重定向、不携带机器人 API Token；用户已确认普通图片输入正常，该反馈不保证所有账号附件地址相同。
内容类型与实际图片头、声明尺寸与实收字节相符才可提交，失败整条拒绝；正文中的 URL 不作为附件下载。
共享 `ManagedImageStore` 负责私有暂存与有界读取，`SurfaceInputBatcher` 转成校验后的 Data URL，
`prepareAttachmentSubmission` 捕获工作区/会话并复核模型图片能力，Client 沿已有 Provider 规则处理图片引用。
附件分支先于交互和命令解析，图文说明中的命令字样不执行。独立 `/stop` 取消接收中的图片准备，关闭和撤权同样阻止迟到下载提交。
图片完成或失败后删除本批临时文件；删除失败记录受控日志并沿共享 24 小时清理兜底，不把本机路径提交给模型。
普通文字与附件按同一会话接收顺序处理，前一条提交结束后才捕获下一条附件的会话；命令与交互回应旁路，不被慢下载阻塞。

语音仅接受 `content_type=voice` 的可信 `voice_wav_url`，不读取原 SILK URL 或 ASR；原附件 size 不当作转换后 WAV 的长度。
WAV 本地支持范围为 RIFF/WAVE、唯一顺序 fmt/data 块、单/双声道 8/16 位整数 PCM；拒绝扩展格式及其他 chunk，按帧对齐、采样率和数据长度核验最多五分钟、20 MiB。
沿 `ManagedAudioStore` 和共享 `prepareAttachmentSubmission` 提交 localAudio，模型未声明 audio 时在 Turn 前拒绝；没有转码或转写回退。
视频仅接受单个 `video/mp4`，以共享 `VideoAttachmentStore` 保存到组合根注入的 uploads/video/qq，最大 64 MiB、24 小时、八个文件；容器签名不代表实际可解码。
提交共享 `videoAttachmentBody` 的单文件随机引用，由配置好的视频 MCP 消费；不新增原生视频模型输入，不将下载地址或本机路径作为视频输入。
单音频或单视频可附文字和引用上下文；多音视频或与独立图片混合整条拒绝。附件文字不执行命令。
停止、关闭、撤权、切换目标阻止迟到提交；确定未提交时清理，成功或可能已提交时音频沿一小时保留、视频沿共享 retain/24 小时保留，避免删除尚在消费的文件。
`/stop` 同时取消停止前尚未提交的普通输入，停止后收到的新图片等待停止处理结束，不重新启动已取消的输入。

原生引用要求唯一 `ref_msg_idx` 与唯一根元素索引一致，拒绝自引、重复或歧义索引；嵌套仅接受类型 0/103，允许官方示例中的 103 无子节点叶子。
本地限制四层、十六节点、每节点四个/总计十六个附件及 32000 UTF-8 字节引用正文，超限或非法 Unicode 整条拒绝；这些不是 QQ 官方保证的上限。
引用作者、URL、文件名和鉴权信息不进入提交，附件只提供固定“未下载/未读取”说明。引用正文仅为不可信上下文，不取得命令或审批权限。
复用 `formatQuotedInput` 的 8000 Unicode 字符展示上限和截断标记；仅在普通文字/附件实际提交时拼接引用，命令、交互和停止始终读取顶层当前文字。
当前文字或当前支持的附件至少有一项；空当前内容不因引用存在而启动任务。附件说明为空时保留对应默认任务，引用不能取代当前附件输入。

提交前持久登记 `claimed`。实际 submit 返回后才关联 Thread/Turn；输出最多等待已有提交句柄十五秒，
不等待命令回复或完整模型执行，不阻塞 App Server Reader。无法证明关联时保留未确认结果。
输出关联等待只覆盖实际 submit 至 Ledger associate，不包含图片下载、前序输入排队和文件清理。
输出与审批共用精确 Thread/Turn 的 Grant 等待；观察已有提交逐个结算，目标一经关联立即继续，不等待同会话其他慢提交，总期限仍为十五秒。
已有关联的结果不等待同会话后来的提交。完成的本地命令标记 `handled`，任意登记写失败使当前代次失败关闭。
命令回复在共享用例内捕获操作后的工作区/Thread 守卫，实际发送前再次复核。
steer 不把已有 Turn 的来源改为最新来信。主动任务来源在本次代次中按原 Actor、目标、Thread/Turn 精确关联，最长 24 小时，不被后续消息续期；
来源和 Turn 索引分别最多 1000 项，满时拒绝新增关联，不用 LRU 淘汰仍有效来源。关闭清空，重启不恢复旧任务发送授权。

完整最终文本和 Turn 终态进入共享投递箱。正文先区分标题、列表、引用、强调、链接、代码与未知结构；
可表示内容以 `msg_type=2` 发送，代码及无法安全表示的部分以 `msg_type=0` 保留完整可读内容。
闭合代码围栏和行内代码只去掉语法定界符，代码内容不作为 Markdown 解释；链接转文本时保留名称及目标。
命令、帮助、状态及错误复用共享内容，面板值保持字面意义，不解释会话名、路径及命令参数中的格式或链接。
原始正文仍由共享持久事件保存；当前发送内容与完整可读纯文本由同一次转换生成。
共享三级及以下标题转为二级标题，列表缩进适配四空格；不执行原生指令标签、不下载 Markdown 图片。
列表项含续行或嵌套代码时整项按原文字面输出，代码围栏内的缩进不参与正文列表推断。
不按字节切分 Markdown；可表示块按格式边界合并，无法容纳的块使用完整文本。纯文本优先按行/空白切片，
预算紧张时使用保全 Unicode 码点的紧凑切片；文本规划本地上限 12000 字节，每片 3000 字节，最多四片，均非官方长度保证。
普通输出使用主动消息，明确省略 `msg_id/msg_seq`，与被动四次预算分离。每次仍按最多四片规划；混合格式过多时使用更紧凑的完整文本。
首片前原子预留完整结果所需主动次数，未知结果不释放预留。每片实际确认后才允许整条结算；
最终正文和共享命令结果超过文本预算时，在普通发送开始前选择完整 UTF-8 文件。
文件保留转换前原文（含 Diff 空白），固定名 `codex-complete-result.txt`，本地上限 1000000 字节；非法 Unicode、空内容及超限拒绝。
使用 `file_type=4`、`srv_send_msg=false` 上传，再以 `msg_type=7` 发送；与图片共用原 Grant、授权、取消和 TTL 检查。
上传前标记正文未完整确认，文件消息确认后才确认全文；上传成功、未知响应或部分正文成功都不代替完整交付。
审批、通知和终态不文件化，Markdown 明确拒绝后的降级及中途失败也不改发文件；未知结果不重试。
没有主动额度、超过文件上限或发送失败保留结果；不会以截断摘要确认全文。过程 commentary 不自动发送。
明确失败/拒绝操作和普通警告也保留；警告无法证明具体 Turn 回复来源时保留为未确认，不静默丢弃。

单片 Markdown 仅在 HTTP 400 或 HTTP 200 业务错误明确为 `40034011/40034124` 且无消息身份/业务字段矛盾时，
记录明确拒绝并重新占主动额度，发送一次完整纯文本；不退还原尝试额度。HTTP 5xx、超时、待审核、长度、
去重及未知响应不触发降级；降级前仍复核授权、取消和原任务来源。矛盾的成功/错误响应归为未知，不能据此重发。
多片及混合发送中途失败不重发已成功前缀，也不将单片确认当全文成功。
最终正文和带详情的失败信息优先采用片数更少的完整文本；纯 Markdown 不额外降级，交互指令区仍保持独立受控格式。
日志记录主动发送模式、规划格式、片数及单次分片上限；该上限不代表主动消息只能发送四次。平台明确拒绝记录 HTTP/业务码，不记录正文或凭据。
连接状态及首次授权完整文本、首次提交返回并登记、首次完整回复确认分别记录为 `connection`、`first-input`、
`first-submission`、`first-reply`，以 `accountId` 和内存 `generationId` 关联。首次里程碑每代次只记录一次，
不是线性状态机：帮助回复可能早于模型提交；同代次重连不重置里程碑，新代次使用新 ID。
平台确认不代表客户端已读或模型完成；这些日志不构成实时健康查询接口。
帮助与命令准入共用同一目录，会话说明复用飞书/TG 的共享帮助，不另设 QQ 首次会话策略。
`/status` 等已开放命令直接沿用共享命令参数、用例和结果渲染，不增加 QQ 专属命令变体。
会话管理开放 `/archived`、`/archive`、`/unarchive`、`/pin`、`/unpin`、`/rename`、`/fork`，
诊断开放 `/permissions`、`/diff`、`/metrics`；保持共享工作区范围、各命令既有约束及操作后的回复守卫。
`/review`、`/plan`、`/skill`、`/plugin`、`/agents` 复用共享参数、列表/详情/健康和调用入口。
启动 Turn 的用例由共享命令提交捕获口在调用前登记 Promise，实际返回后将完整 Submission 关联原来信；外层回复守卫失败不抹掉已经发生的提交。
steer 保留原 Turn 的任务来源，不用新命令延长原来源期限；列表、详情、健康查询和无参数 Plan 切换不登记提交等待。
`/queue` 沿用共享增删改查、排序及启动参数；add 在 RPC 前通过可选捕获口登记 Thread/clientId 与原 actor/target/grant。
本地 Map 最多 500 项、仅当前代次、期限不超过原主动来源；不保存正文或建立队列副本。RPC 结果未知时保留映射至原期限，不重试入队。
外层与代次 output.admitLive 同步消费 Core 的无正文身份事件，立即登记等待句柄；异步关联校验授权和原来源，拒绝覆盖不同 Turn，不阻塞 Reader。
自动消费和手动 start 均以官方 clientId 精确关联；update/delete/reorder/start 不刷新来源。add 回执和未来结果均使用主动消息。
原生客户端创建、重启前、过期或未知来源的队列项仍可执行，但 QQ 没有发送依据，结果不借最新来信；start 回执仅使用 start 来信自身授权。
身份事件不展示、不入持久箱；关联失败保留实际结果。关闭清空来源 Map，并沿已有待办清理等待关联写入。
`/goal` 查询与 `/goal clear` 沿共享解析和用例，复杂目标文字使用字面字段面板；空 Goal 不提示不可用的 set。
直接 `/goal set` 不提供可关联的启动 Turn，QQ 明确拒绝；可在普通任务中通过 Goal 工具创建。
官方 `turn.root.identity` 表示同 Thread 根 Turn 工作链，包含工具创建 Goal 后的续跑，不是 Goal 专属标记。
QQ 同步建立最多 500 项的子 Turn 来源等待；根解析仅接受同 Actor/目标/Thread 的 Ledger 原始 Grant，不经过其他别名。
先捕获原提交 pending 再登记自身等待，避免早到结果抢跑及自等待；确认后仅保留进程内别名，不覆盖根 Ledger，不改磁盘格式。
重复身份不续期；冲突、未知根、自引、跨 Thread、撤权和过期不能取得新来源。输出与审批共用来源查找，实际发送前再次核验别名。
根与后续 Turn 共用原任务主动来源的 24 小时绝对期限；关闭清空映射，重启不重建旧关系，缺少依据的结果保持未确认。
Skill/Plugin/Agent 的名称、描述、选择器等先保护再解析结构，恢复后按字面值显示，不生成 Markdown 指令。
Skill/Plugin/Agent 新建 Turn 沿共享结果省略额外调用回执，QQ 等待最终结果；review/plan 的已启动回执不表示模型完成。
管理命令复用共享 autoreview、compact、revert、release、MCP、Hook 和重置券服务，不增加 QQ 语法或第二套状态。
压缩只回执请求；MCP OAuth 地址由共享服务产生，QQ 不发送无原 Turn 依据的异步完成通知，用户通过 MCP 查询核对。
Hook、Revert 和重置券确认预览在文件规划前检查，必须完整放入单条 3000 字节文字，超限不下发确认令牌、不拆片、不附件化。
Hook 审查策略通过 Surface 公开入口供组合根使用，先核对共享字段保真，再检查 QQ 完整审查预算；真实预览包含实际上下文后再次检查。
操作仍由共享服务复核原用户、会话/工作区/Provider、配置版本及一次性令牌，不把查询、预览、保存或实际执行混为同一状态。
归档检查活动 Turn，取消归档和分叉另检查原生 Queue，沿用共享用例差异。
归档、取消归档和分叉只在共享用例确认后显示结果，不在 QQ 维护第二套会话状态。
Diff 使用共享结果原文按完整文本发送，保留增删符号、缩进及 Markdown 字符，不经过面板结构转换。
完整命令结果超过文本预算时按上述完整文件合同发送，超出文件上限不截断冒充完整结果；
指标及归档列表也可使用共享范围、分页和搜索参数缩小结果。
多行名称、权限描述及查询中的模型等动态字段保持字面内容，结构化结果解析后才恢复字段，不解释为 Markdown。
命令已返回但渲染或发送失败时单独记录回复未确认，不把写操作描述为未执行；失败提示也复核原回复守卫。
会话指标查询固定原 Thread，查询等待及实际回复前的换绑都拒绝旧结果；全局聚合沿用共享范围。
Turn 终态复用共享完成结果模型及结构化渲染器，保留独立回执和纯文本降级结果，不充当正文确认；缺少最终回答单独提示。
正文片数不消耗原来信的终态预算；独立终态仍受主动频率与每日接收额度约束，发送未确认时保留核对，不删除或假确认。

生成图片完成事件复用共享图片读取、持久快照和交付临时文件；不因隐藏过程日志而忽略图片。
仅接收共享事件的 PNG/JPEG 本地结果，不读取模型正文中的任意 URL；拒绝符号链接、非普通文件、超限和不支持的图片头。
本地发送上限 3 MiB，正常持久交付还须扣除 4 MiB JSON 负载的元数据与 Base64 开销，实际可用图片大小略低于 3 MiB。
使用原 Thread/Turn 的任务授权预留一次主动发送，上传到普通 `/files` 接口且固定 `srv_send_msg=false`，
随后以 `msg_type=7` 和 `media.file_info` 主动发送。上传成功不等于图片消息确认；
每次请求前复核授权、取消与原来源，上传凭据另受 TTL 限制，只用于本次发送、不持久保存。
失败或未知结果不自动重发；图片、正文、交互和终态均计入主动频率与接收额度。只有生成引用而无法取得图片时发送明确提示。
上传专用响应允许消息 id 缺失或为空字符串；非空或非字符串 id 仍拒绝，上传回执不代替后续消息发送确认。
完成面板直接消费共享结构化字段；额度的重置/剩余时间为子字段，不因多行值使整面板降级。
正文交付失败的诊断保留受控协议阶段、原因和状态码；同代次同目标 Thread/Turn 的未确认标记保留 24 小时，覆盖原任务发送寿命，后续 Item 成功不清除先前失败，完成面板标明正文交付未确认。
显式 `codexc channel send-image` 复用相同读取、上传与发送链；QQ 要求显式原 Turn 身份，组合根传入固定目标的实时绑定守卫。
排队、读图与实际平台请求前复核原 Actor、目标、Thread/Turn、当前授权及原 Grant，不借新来信或最新轮次发送。
渠道 spool 的 version 2 固定原目标和 Turn，旧 version 1 不补全身份或发送 QQ；持久数据处理与回滚见[渠道图片](../../../docs/channel-image.md#恢复与回退)。
此链路不开放 Markdown 图片素材，正文路径与 URL 不成为文件读取或下载授权；图片输入使用上方独立链路。
生成图片与显式图片输出的真实账号权限及客户端呈现仍待专项验收。

重启不复用旧实例 ReplyGrant 或主动任务来源，即使元数据备份恢复，也不会自动恢复旧任务发送授权；主动计次仍须继承。
旧结果继续由共享投递箱保留，本机可核对或按现有维护合同处理；当前没有把新来信绑定旧结果的重发入口。
元数据使用独立 `qq-transport` 目录、macOS `codexc-qq-transport-v1` Keychain 命名空间，版本不兼容失败关闭。
备份应停写并保留配置、加密记录及密钥；回滚先禁用 QQ，保留旧记录和投递箱，不删除数据绕过版本检查。
WebSocket Resume 按官方顺序先接收补发、最后接收 RESUMED；代理 CONNECT 和 HTTP 池由 Bootstrap 注入的每代次网络对象拥有并关闭。
4009 保留原 Session 和已准入序号，使用 Resume；4006/4007 清除无效会话或序号后 Identify。
按 V2 详细码表，4001/4002/4010–4014/4914/4915 终止连接；失败锁定在外层 QQ Adapter，
共享管理器再次调用 start 不创建新运行代次或发出网络请求。修正配置或账号状态后重启 Gateway 才重新尝试。
同页简化重连说明及 SDK 的 4009 清会话行为不覆盖详细合同，取舍见[上游来源](../../../docs/upstream-sources.md#qq-接入研究基线)。

命令/文件审批按共享请求提供一次批准、会话批准、拒绝与取消；命令前缀及网络持久规则仅在原请求明确提供时显示。
网络规则逐条编号，只回传用户选择的一条；不合并、不补写本地执行规则。临时权限仅本次 Turn，终端输入只批准一次或中止。
展示与回应共用同一选项目录，手写未提供的授权范围或不存在的规则编号不会生效。
MCP 工具审批完整展示共享层核验过的工具说明、参数与授权范围；按请求提供一次、会话或始终批准，决定交回 Coordinator 编码持久范围。
仅有原 Thread/Turn 有效 Grant 时可发送；`turnId=null`、缺少原 Grant 或超出完整展示预算均安全取消，不借用父轮次或新来信。
普通 MCP form 复用共享 JSON 值响应，不复制表单 schema；完整显示请求说明，`/填写 <令牌> <JSON>` 不加问题序号。
最多 4000 UTF-8 字节、64 层容器嵌套，为上游 RPC 外壳保留深度空间；格式错误、非有限数值和超限回应保留原交互供重试。填写不会进入普通模型输入，也不会赋予审批范围。
普通同步非敏感问题最多三项，每项至多八个选项，填写上限 4000 UTF-8 字节。
复用共享 `InteractionRequest`、决定映射和待处理 Registry。原请求 `isCurrent`、Actor、账号、Conversation、
精确 Thread/Turn 与当前代次原 Grant 必须同时成立；无回复依据的子代理/后台请求安全拒绝，不借父 Turn 或最新来信。
完整提示经现有队列及整条预算预留，全部确认后才开放回应；过期、取消、其他客户端处理和关闭都会使令牌失效。
有效期取共享请求剩余期限与原任务主动来源剩余期限的较短者；不延长 App Server 交互期限。
主动任务来源同时受墙钟绝对期限与进程内单调期限约束；被动流另保留平台时间戳窗口，同消息别名共用最早期限，系统时钟回拨不会续租。
无法路由、过期、不支持或完整提示未确认的请求记录受控拒绝原因，不记录详情、答案和令牌。
仅本模块可生成受控 QQ Markdown 点击指令；数据详情以字面文本完整显示，格式降级仍保留完整可复制回应。

## 主动限流与原生流

主动消息先按整条规划持久预留，默认按应用 5 QPS/30 QPM、每位接收者 20 QPM/滚动 24 小时 1000 条保守限制。
每次普通消息实际 HTTP 前再次持久记时并按账号至少 250ms 间隔调度，Token/上传等待不能使旧预留集中突发。
普通消息先取得覆盖 15 秒 HTTP 期限的 Token；实际限流每次等待后，在持久记时前重新核对或刷新 Token。
Token 准备与限流等待共用 65 秒总期限并支持取消，实际请求前再次检查余量，不在发送记时之后刷新。
遵循 V2 仅在剩余 60 秒内换发新 Token 的合同，不再假设提前 85 秒调用就能取得长有效期 Token；刷新返回也复核所需余量。
短期限流等待最多 65 秒，支持取消；每日配额与本地滚动 24 小时 10000 次容量直接拒绝，不淘汰未过期记录。
可靠输出的 QQ 单条尝试预算为 480 秒：65 秒整批预留、最多四片各 65 秒调度与 15 秒 Token/15 秒 HTTP、一次 15 秒上传；
其他渠道仍为 60 秒。该预算不延长原任务、被动窗口或交互有效期。未知、失败和取消不退还预留。

`text.delta` 按精确 target/Thread/Turn/Item 建立最多 256 项的内存状态，消费现有 QQ Markdown 转换；只有稳定且可表示的内容进入 replace 流，每帧携带截至当前的完整正文，
未闭合或不可表示结构缓冲至完整结果；临时缓冲末行不把已确认前缀误判为重写，缩进列表部分等待完整正文确定缩进单位。转换候选必须保留已发送前缀；不重写前缀，也不把源 Markdown 当裸文本发送。
源 Item 与每帧完整正文各最多 12000 UTF-8 字节、每流最多 128 帧，不截断或把增量切片当作完整替换帧；这些是本地资源限制，不是平台长度保证。
响应 `remain_msg_len` 如存在必须是非负安全整数，仅用于受控诊断；官方未定义零值代表流结束，不用该值关闭流或拒绝下一帧，长度限制仍以实际平台结果及本地预算为准。
流首片只占原 Grant 一次被动次数，后续同 `msg_seq`、同服务端流 ID、index 递增，生成中为 1、结束为 10。
仍沿现有保守五分钟窗口，未解决官方普通消息页面的 60 分钟/5 分钟矛盾；所有流请求按账号至少 25ms 间隔，不超过文档 50 QPS。
目前没有足够官方证据确认无原来信的主动流及每片计费语义，因此不开放主动流、`is_wakeup` 或计划任务。

直播准入同步捕获 Bootstrap 的原 owner，要求 Thread 当前绑定仍属于同目标；队列等待后、每次 HTTP 前复核该 owner、原任务来源和当前 Policy。
停止、Item/Turn 结束同步关闭预览，晚到 delta 不重开；最终正文仍由共享持久事件独立结算。解绑、换目标和撤权阻止迟到预览。
未完成末行统一缓冲，首个短增量不立即产生预览气泡；完整结果仍直接进入结束帧或普通交付。
Turn 终态同时收尾已有确认内容的 streaming/fallback 预览，不依赖失败或中断前一定收到文本完成事件。
首片 HTTP 前先持久写入流身份哈希屏障；响应未知则保留最终结果，不重播前缀。完整结束片平台确认且本地记账成功后才确认全文。
最终结果到达时，仍在来源、持久登记、Token/限流等待且尚未开始下一次 HTTP 的预览可确定取消，保持原 index 和已确认前缀，由完整结果继续以全文结束原流；请求已发出而响应未知仍禁止重播。
原生结束片与普通交付共用完整结果校验，空正文、非法 Unicode 或超过完整文件上限的结果不能获得全文确认。
已确认预览因长度、格式变化或过期无法承载完整结果时，先尽可能以已确认完整预览正文和结束状态关闭原流，不能发送空正文 replace 清空预览，再沿普通完整输出规划交付；短正文使用文字或 Markdown，全部正文片整体预留主动次数，不增加单独说明消息挤占四片正文预算。只有确实超过文字预算才使用完整 UTF-8 文件，文件说明与文件整体预留两次。说明和原流关闭不确认全文；关闭请求结果未知时停止另发。每个实际确认帧日志仅记录索引、结束标记、完整帧字节数、可选剩余长度和原 Thread/Turn/Item 标识；降级日志另记录受控原因，均不记录正文。

新增记录位于 `qq-transport/active-v1`，macOS 使用独立 `codexc-qq-active-transport-v1` Keychain 命名空间；版本为 1，与原被动 Ledger 完全分离。
仅存 Actor/流身份哈希、预留时间、流启动/关闭状态及高水位时钟，无正文、附件、令牌或历史。最多 1000 项流屏障，超过 24 小时绝对来源期限后才可清理。
记录上限为 950000 字节，保持低于共享安全存储 1 MiB 限制；版本未知、损坏、写失败、容量满及系统时间回退失败关闭，不清空计数。
容量或频率拒绝前的过期清理也推进进程内时钟高水位，时钟前跳后再回拨不能借失败预留提前释放旧次数；拒绝不覆写磁盘记录，重启仍继承原登记。
运维变更前停写并完整私有备份配置、整个 `qq-transport`（含新目录、密钥）及投递箱；不自动迁移或覆盖原 Ledger。
回滚保留新记录，旧版本可不读取新 namespace；再次升级仍读取原计数。修复期间保持 QQ 停用，核对平台与投递箱，不用删除文件或恢复旧备份覆盖较新的发送登记。
本批只完成本地实现与隔离观察；真实 QQ 主动权限、原生流客户端呈现、频控和复杂异常路径仍待实机验收。
