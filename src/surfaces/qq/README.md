# QQ 文字接入

接入骨架迁自 `feat/qq-adaptation`（`7a867db7`），消息层沿共享 Application、来源授权和持久投递实现。
通过 `codexc setup → 通讯渠道 → QQ` 扫码或手工保存凭据与允许名单，启用后支持普通单聊文字任务。
支持 /help、/status、/stop、/workspace、/model、/new、/sessions、/resume（/r）；不开放附件、审批交互、计划任务或旧结果补发。
列表与恢复沿用共享命令服务、Workspace 校验及绑定切换。列表不撤销来源；带参数恢复在执行前撤销旧来源，失败也不恢复。会话恢复不授予历史 Turn 回传资格。
源码实现与账号验收分开：新 Adapter 的真实 /help 已由用户确认完整收到，临时连接已关闭；用户自行部署后已确认普通文字任务闭环、会话列表分片、显式恢复后继续对话，以及 /new 后再次提交。其他失败、撤权与重启后的旧来源禁发场景仍待实机验收，证据范围见 [QQ 消息合同](../../../docs/qq-message-contract.md)。更新源码不会自动启用用户配置。
上线与共享完成统计通知已在用户授权的部署及 Gateway 单独重启后，由用户确认两项均收到；该收件证据不覆盖所有异常或重连场景。

## 文件与边界

- `index.ts`：QQ 模块公开出口。
- `lifecycle.ts`：复用共享上线信息与 Turn 完成统计，输出 QQ 纯文本通知；完成通知不承诺正文已全部送达。
- `surface.ts`：文字 Adapter，接入共享启停与故障重试；每代次拥有独立网络、Token、WebSocket 和 messages。
  capabilities 显式关闭自动绑定恢复、审批、计划任务和配置广播；持久结果使用共享投递账号。
  关闭取消来源及未发文字，不终止共享 App Server。所有交互使用共享安全决定。
  配置通知没有订阅对象，按空收件人集合完成，不调用平台或阻塞其他渠道的持久配置事件确认。
- `messages.ts`：普通来信准入、去重、必要命令、共享 submit 观察与来源/输出端口装配。入站同步有界接纳，异步任务由代次持有，Transport 不等待 App Server，/stop 可取消准备。
  上线通知由 Surface 首次就绪触发，每次 Gateway 生命周期仅尝试一轮，60 秒总预算，关闭时取消并等待；逐目标复核允许名单和原工作区，失败不自动重试、不恢复旧任务来源。
  普通输入最多并发 32 个，另留 8 个 stop 槽；同目标普通准备不排队。仅非 commentary 完整 Item 与 Turn 终态入共享投递箱；引用在实时准入固定，富化不重选来源。
  被动命令每来信只尝试一个完整计划，失败不递归回错或重用序号；普通任务结果主动发送，发送前使用共享精确授权守卫。
- `send-budget.ts`：每代次账号级预算，完整计划先预留；正文每 Turn 16 片、终态 2 片，主动账号/接收人滚动分钟 24/16 次、接收人滚动日 800 次，未知结果不退额度。
  完整协议调用串行并间隔至少 250ms，覆盖 Token 等待后的并发突发；限速不另建恢复投递箱，等待受完整计划期限和取消约束。
- `protocol.ts`：AppID/AppSecret 校验、Token 合并刷新、Gateway 地址发现、有界 HTTP 响应、取消和结构化错误。
  `sendText` 显式主动/被动模式，单片最多 2000 UTF-8 字节；被动序号取本地保守 1–4，
  原消息 300 秒窗口在调用时转换为单调期限，Token 等待后再次核验，不因等待重置。
  必传取消信号和同步 `beforeSend` 守卫，Token 前和最终 HTTP 发送前复核；一次操作的 15 秒期限覆盖 Token 与响应读取。
  成功只返回合法 `messageId`；`QqTextSendError.outcome` 区分 not-sent、rejected、unknown。仅一致的已知业务拒绝码认定 rejected，
  5xx、畸形/矛盾响应、缺少 ID、网络中断或发出后取消均不当作可重发失败。不分片、不重试、不切换模式，不写检查点。
- `inbound.ts`：纯普通单聊 Dispatch 解析，输出最小文字与来源字段，区分非目标事件、格式错误、不支持和超出本地预算；
  RFC3339 日历校验、Unicode 校验、唯一不透明 msg_idx 和引用/附件排除均在该边界完成。
  不保留 ext 中的鉴权字段，不执行允许名单、Workspace、去重或任务授权；这些仍属下一层，不以解析成功代表准入。
- `task-sources.ts`：本代次任务来源注册表，由 messages 持有。接收已解析的来信身份和已授权作用域，
  不保存正文；原 Actor、Workspace 和 Thread 的实时检查由调用者提供，异步或抛错的检查拒绝准入。
  调用者须在撤权/归属切换时调用取消接口，Adapter 重建时 close；本模块不监听配置变化。
  守卫返回后再次复核关闭、取消和期限；30 秒准备预算从 reserve 入口起算，等待还复核投递调用方的取消信号。
  `reserve` 返回去重/容量拒绝或一次提交票据，票据观察器直接适配 Application `SubmissionObserver`。
  `capture` 只在请求尝试后捕获早到候选；`awaitSource` 等待最终结算，`isCurrent` 检查精确 Thread/Turn 和原作用域。
  `terminal` 收紧终态排空期限，`cancelTarget`/票据取消/`close` 清理授权及等待；这些都不会中断 App Server 任务。
  每账号最多 4096 个去重条目、128 个活动或预留来源、128 个关联等待；未知项留至代次结束，容量不足明确拒绝。
  普通任务结果按主动模式合同使用；被动命令次数和发送调度不由本模块管理。引用不能单独充当持久发送授权。
- `outbox.ts`：独立的完整文字执行组件，复用共享 ConversationDeliveryQueue、DeliveryReceipt 和 checkpointDelivery。
  全文先按字素规划，再作为一个队列操作串行发送；最多 8 片、每片含包装最多 2000 UTF-8 字节，被动序号整体不得越过 4。
  总期限 45 秒，失败停后片，不截断、不自动重试、不切换模式；调用者提供精确目标的实时发送守卫。
  被动原来信窗口在整条计划开始时固定为单调期限，排队与逐片发送不因墙钟回退延长窗口。
  关闭只取消本组件队列，不关闭 Adapter 持有的协议客户端。事件选择、来源与跨计划预算由 messages/send-budget 承担。
- `transport.ts`：原样迁入 WebSocket 鉴权、心跳、接收序号、Resume、有限重连和关闭流程。
- `network.ts`：从旧 Surface 提取的网络资源接口；Bootstrap 的 `qq-network.ts` 保留每代次代理与连接池的所有权和关闭行为。

允许名单策略位于 `src/policy/qq-access.ts`。名单新增热加载，删除、账号或凭据变更以及启停要求重启 Gateway；
这些处理复用配置变更分类。QQ 不广播配置变更；上线通知使用当前应用启动时的允许名单，在实际发送前复核实时授权，状态仍可通过本机 Setup、Doctor 与日志核对。
WebUI 沿用渠道状态摘要，QQ 凭据编辑仍使用 Setup，不新增 WebUI 编辑入口。

扫码 Worker 与生命周期入口位于 `scripts/qq-registration-worker.mjs` 和 `scripts/qq-registration.mjs`，
由 `qq-setup.mjs` 调用。锁定依赖 `@tencent-connect/qqbot-connector@1.2.0` 仅负责扫码材料取得；
没有代理注入能力，扫码使用直连；运行时 WebSocket/HTTP 使用共享网络代理。
移除扫码入口时应移除三份 QQ Setup/扫码脚本与该依赖。

## 数据与当前限制

配置复用私有 TOML、源修订核对和原子保存，不迁移旧 QQ 配置或其他用户数据。
不接入旧 `qq-transport` Ledger，不自动恢复旧 QQ 绑定或旧来源，不清理历史消息或发送记录。
新来信可经共享用例恢复已选 Thread，并为明确参与的 Turn 建立新来源；旧 owner 或旧代次记录只留核对，不能补授资格。
StateStore 与 Delivery schema 不变，QQ owner 使用 v3；人工重试沿用共享机制，仍复核来源和预算，可能重复已收到分片。
回退前将 QQ 配置禁用；若回退版本不识别 `[qq]`，先私有备份配置并显式移除该配置段，
不要通过删除数据库或凭据目录绕过兼容校验。

不迁入旧正文状态机、交互、Ledger 或附件实现；详细范围、策略与证据见[QQ 消息开发流程与合同](../../../docs/qq-message-contract.md)。
完整文字 Outbox 的本地拒绝观察（2026-10-24）：非法 Unicode、超过 16000 字节、不可拆分的超长字素和被动分片越过序号 4 均返回 `invalid-input`；
拒绝发送守卫返回 `authorization`，关闭后调用返回 `AbortError`，上述路径检查点数均为零。
观察使用无真实凭据的协议客户端，守卫在联网前拒绝；未向 QQ 发送样例，未观察新 Outbox 的真实分片送达、平台失败或持久恢复。
第一层实现期间按用户要求未再次探测，只完成静态链路/失败分支审查及既有检查；旧脚本观察不等于新实现已经实机验收。
第一层提交后用户允许必要探测，具体范围与未决问题以消息开发合同为准，不因此启用正式 QQ。
连接失败使用受控错误；终止类关闭码锁定当前 Adapter，不借共享重试重新连接，修正配置后重启 Gateway。

协议参考见[上游来源](../../../docs/upstream-sources.md#qq-接入骨架基线)。
静态检查和本地观察不证明真实账号能力；真实连接证据及剩余缺口见下文。
