接入骨架迁自 `feat/qq-adaptation`（`7a867db7`），消息层沿共享 Application、来源授权和持久投递实现。

通过 `codexc setup → 通讯渠道 → QQ` 扫码或手工保存凭据与允许名单，启用后支持普通单聊文字任务。
群聊源码已接线：另行配置明确同意公开输出的群/成员名单，仅消费群 @机器人事件。成员独立 Conversation、工作区和交互权限，输出向群公开；物理群共享 Outbox 顺序及额度，群不使用单聊流式或常驻菜单。启动和配置通知仍只发单聊名单，真实群平台验收待完成。
群配对复用当前 QQ 连接：Setup 经私有 IPC 发起五分钟一次性码；`messages.ts` 只将已解析的群 @纯文字配对提交注入端口，不进入 Actor 注册、Application 或回复路径。保留配对指令在未配对或失效时也不当作任务，附件/引用不能配对。`surface.ts` 持有注入端口的启停，关闭清空配对；Bootstrap 组合私有 IPC，Runtime 不接收平台原始事件。身份识别后仍需本机公开输出及完整配置确认，不自动保存。
支持 /help、/status、/stop、/workspace、/model、/new、/sessions、/resume（/r），并已接入共享审批、用户问题与 MCP 交互；图片输入及 PNG/JPEG 图片交付、文本/普通文件与原生引用输入、显式本机文件发送及音视频输入已接线，真实客户端仍待验收；超长文字结果可交付为文本文件。第九批已接入原生 Queue、计划任务和当次配置通知，真实 QQ 客户端仍待验收；旧结果来源仍不恢复。

查询不撤销来源，结果复用共享格式器；手输命令被动回复、消息按钮回调主动回复，发送前通过 Outbox 检查各自完整分片预算，超限只发查看提示，不自动切换发送模式或转文件。
查询回复每片固定原 Thread；账户查询同时固定原 Provider 并核对订阅就绪，队列或 Token 等待期间切换后拒绝继续发送。
/diff 只展示当前已取得的 Turn Diff，不补读重启前历史；查询命令各分支仍待实机验收。

上线与共享完成统计通知已在用户授权的部署及 Gateway 单独重启后，由用户确认两项均收到；该收件证据不覆盖所有异常或重连场景。
共享订阅恢复修复部署后，用户再次要求重启并确认“可以了，能恢复了”；该反馈只记录重启恢复，不扩大为所有停止竞态或旧结果禁发实机验收。

该样例不覆盖长任务窗口过期、平台限流、在途撤权、逐字完整性或全部失败恢复场景，详见消息合同。

## 文件与边界

第三批模式与状态菜单复用共享 effort/fast、无参 plan、permissions 和 autoreview；Goal 仅开放已有就绪 Thread 的查询/清除，whoami 只呈现本用户脱敏身份。审批方式按钮绑定精确 Thread，生命周期守卫透传共享服务；设置和查询保留结果来源。详情沿 Outbox 完整 Markdown 预选及字面回退，全部确认后激活按钮。真实客户端仍待验收，范围与观察记录见消息合同。
第五批接入 review、Skill/角色/Plugin 任务与带需求 Plan；菜单复用回调，用户需求通过填入稳定名称后追加文字提交。命令在授权和解析前建立提交观察，结果只接受权威响应的精确 Thread/Turn；Review 不伪造用户消息 ID，Goal set 保持拒绝。早到流式候选不先占用唯一 Item，确认后同步选择，最终全文仍沿共享持久投递。填写任务按钮不是上下文授权快照，实际发送时重新解析和授权；真实客户端仍待验收。

- `index.ts`：QQ 模块公开出口。
- `addressing.ts`：群/成员 Conversation 与物理收件人之间的显式映射；C2C 字符串和群对象是不同类型，不从不透明 OpenID 前缀猜端点。每成员独立业务身份，同群共享出站顺序与额度；只对规范群 Conversation 放宽长度预算。
- `privileged-management-menu.ts`：重置券与进程释放的完整预览、单次按钮与生命周期门槛；不直接消费账户或终止进程，复用 Application。手输 force 也先预览，只有可靠 PID/启动身份才开放确认，未知结果不重试。
- `queue-sources.ts`：本代次原生 Queue 身份注册，最多 128 个准备/等待/活动项及 4096 个去重项，不保存正文。add 成功与官方用户消息身份共同关联 Turn；start 还须匹配精确条目和响应 Turn。确认入队后的等待不沿普通三十秒期限，结果只走主动投递，未知不自动重试。精确删除撤销匹配项；停止、切换和关闭不能使迟到通知复活。
- `schedule-menu.ts`：通过共享命令服务渲染计划任务列表、Run、管理操作和创建/删除预览；列表/Run 使用共享结构化格式器，任务按钮显示限长名称并绑定完整 ID，Run 页补齐当前任务信息。菜单身份绑定原 Actor、Workspace 与上下文，五分钟内单次有效。完整字面预览及末片按钮取得平台确认后才开放确认，文字 confirm 同样复核门槛；停止、切换、取消及关闭撤销未执行确认，已提交写入不回滚。只保留临时呈现身份，不保存任务定义或正文。
- `media-input.ts`：只消费已准入的单一语音/MP4 元数据；平台转写优先作为普通正文，无转写时只下载转换 WAV，20 MiB/30 秒/保留一小时。视频复用 VideoAttachmentStore 的 QQ 随机引用，64 MiB/60 秒/保留 24 小时；类型、声明长度和实际字节均校验。初始化及下载可取消，关闭等待在途资源。共享附件作用域在首次等待前捕获目标，提交结果未知保留视频引用，确定未提交才删除。媒体来源准备最多 120 秒，不改变原来信被动窗口。
- `image-store.ts`：仅消费已准入事件的图片元数据，复用 ManagedImageStore 私有暂存及共享 Data URL 转换；每批最多四张、输入总量 20 MiB、单图 10 MiB、整批三十秒，声明类型必须与内容签名一致。暂存初始化等待可取消，关闭取消下载；成功落盘后沿共享 24 小时清理，不在提交未知时立即删除。下载由注入的 Network 窄端口处理，不接受消息正文 URL。
- `file-input.ts`：只接事件中单个 `file` 附件，按明确扩展名区分文本与不透明文件；文本复用严格 UTF-8 校验和 TextAttachmentStore（1,000,000 字节，32 KiB 以上暂存），其他文件最大 5,000,000 字节。安全下载与声明/响应/实际字节核对共用；原名只作显示。关闭取消等待并回收在途任务，完整文件按 24 小时清理。
- `binary-file-store.ts`：不透明文件的独立私有暂存，随机 `.bin` 名称、最多 16 项、每项 5,000,000 字节、保留 24 小时；不解压、执行或改变权限。只向任务传原名、路径、字节和期限，完整落盘后取消或提交未知仍保留至到期。
- `body-markdown.ts`：任务正文的原生 Markdown 安全前缀选择；保留原文，不补围栏或改写已发送前缀。完整简单 HTTP(S) 链接、公开 URL 图片及严格 qqbot-media 图片引用可透传，未闭合图片保持原子性；代码图片样例、带凭据 URL、私网字面地址、标签、潜在实体和未知语法留给普通文字。图片 URL 不做 DNS 解析，由 QQ 获取资源；不读取本地路径或生成按钮。
- `message-markdown.ts`：通知、命令和完整正文的发送前表示规划，另为审批、预览及 Diff 提供完整字面围栏候选。正文安全 Markdown 块整体装箱，每片最多 5000 个 Unicode 码点（含包装，20000 UTF-8 字节兜底）；特殊构造、未闭合或超长块使用 2000 字节字素分片，后续完整安全块恢复 Markdown。流式续接按完整原文计算可恢复 Markdown 的边界，不从半个围栏重新解释。整篇最多八片；通知、命令、审批仍保留原预算，不做发送失败后的格式回退。
- `command-menu.ts`：固定 `/help` 分类首页、统一 style=0 的按钮构造器及消息键盘宽度规划；Outbox 发送前在五行预算内展开长标签，保留功能分组和全部动作。点击执行使用 type=1 回调，需填写文字使用 type=2、enter=false。首页直达常用功能、子分类不重复收录同一操作；具体操作复用现有控制器和命令路径；协议层统一补齐回调与填入按钮的 visited_label。
- `command-menu-controller.ts`：工作区、模型/思考等级/速度、会话恢复和统计选择菜单；列表读取及选项执行复用共享命令服务，模型选择复用共享快照和选择守卫。
  本代次持有有界、十分钟、单次消费的选项令牌，仅保存具体 ID/选择请求与授权上下文，不保存会话历史或模型正文；关闭清理，跨用户、工作区、会话或过期选择拒绝。
  动态名称只用于经过转义及限长的显示，不拼入可执行指令；回调沿用共享命令执行和既有一次性菜单令牌，不直接操作 App Server。模型翻页保留提供商筛选和共享快照；客户端反馈与未观察边界见消息合同。
- `extension-commands.ts`：扩展命令准入、任务入口判定与展示，复用共享 Plugin/MCP 参数解析器和结果格式；Skills/Agents/MCP 列表分页、Plugin/MCP 精确条目核对及 MCP 登录、重载和资源读取。Skill 只有共享目录明确可调用时才生成填写任务按钮，执行仍重新解析。OAuth 地址使用经过协议校验的 URL 按钮，保留原查询参数；链接送达不代表登录完成。
- `hook-review.ts`：QQ Hook 信任的字面审查策略；与共享完整性检查共同拒绝截断或展示时会改变字符的审查内容。Hook 菜单复用共享预览/确认，全部详情确认送达后才开放按钮或文字确认；生命周期守卫贯穿最终写入。
- `interactions.ts`：共享 `InteractionPort` 的 QQ 呈现与回应适配；复用 `PendingInteractionRegistry` 和 `resolveApprovalChoice`，处理 command/stdin/file/permissions、逐题用户输入与异步问题、MCP 工具审批及 form/url elicitation。
  随机一次性令牌绑定原请求、用户及上下文，翻页或逐题推进递增 revision；按钮回调与普通文字 `/respond` 共用回应映射，输入按钮填入前缀后由用户追加正文发送。请求剩余期限包含展示发送，关闭、停止、切换及跨端解决撤销旧入口，不恢复旧令牌。
  问题保留原正文 Markdown、选项与必要输入提示，去除重复题号；提供完整字面预览作为发送前备选。审批及 MCP 工具审批以固定代码围栏保留共享完整详情，候选安全且可完整规划时与按钮合并；不反解共享转义或改变审批值。特殊构造及围栏冲突仍用完整字面方案，转义说明仅在内容确实发生转义时展示。审批按钮优先整行，按数量在五行内排布，不截断授权范围或移除选项。
- `bot-menu.ts`：应用级常驻菜单的严格结构校验与 Codex 入口追加计划；保留现有菜单，拒绝同名冲突、未知结构与容量不足。
  接受并保留实测由 QQ 补充的 send_message HTTPS icon；新项回读允许补图标，既有项及确认快照仍精确比较。
- `lifecycle.ts`：直接将共享上线信息与 Turn 完成统计交给共享结构化渲染器，保留分组/嵌套字段；不经纯文本再转 Markdown，不附加每次上线/完成的 QQ 固定尾注。Bootstrap 将统一日志等级的 debug 开关传入启动和完成通知；Outbox 仍负责表示预选及原发送预算。正文失败提示保留在实际失败路径，任务完成不等于正文送达。不新增任务开始通知。
  空闲释放、警告、连接与会话变化、Hook、压缩、自动审批完成及账户/额度/MCP 状态复用共享呈现。消息层为实时通知建立独立有界来源，不借用 Turn 输出资格；全局目标来自显式单聊允许名单，仍走共享快照或持久投递分类。
- `task-progress.ts`：有界任务过程呈现状态；复用共享重试、思考状态、计划、工具操作与子代理格式和全局 display 设置。QQ 操作通知不更新原消息，仅发送完成、失败或拒绝等终态，不发送运行中气泡；`hidden` 仍抑制操作通知。来源准入、Outbox 顺序及额度仍由 `messages.ts` 管理；不呈现原始思维链，不建立历史或恢复旧来源。后续修改的观察范围在消息合同单独记录。
  操作通知对齐飞书的加粗状态与代码详情层级：compact 用行内代码，full 用受检查的字面代码围栏；标题、状态、耗时与详情脱敏仍来自共享模块。不支持的 QQ Markdown 在发送前选用原文字，不修改命令内容。
- `surface.ts`：文字 Adapter，接入共享启停与故障重试；每代次拥有独立网络、Token、WebSocket 和 messages。
  capabilities 启用共享绑定、订阅恢复、交互和计划任务；`configurationNotifications: false` 只排除持久 Workspace 配置事件重放，当次 `configurationChanged` 仍主动通知。交互仍经过共享持久投递屏障，持久结果使用共享投递账号。
  关闭取消来源、交互及未发文字，不终止共享 App Server。无法路由、归属失效或展示失败的交互使用共享安全决定。
  当次配置通知仅面向显式单聊允许名单，每轮六十秒、最多八轮在途，共享主动额度和 Markdown 规划；逐人完整平台回执后才确认该轮，失败或未知不自动重试，空名单按成功完成。不阻塞其他渠道的持久配置事件确认。
- `messages.ts`：普通来信准入、去重、必要命令、共享 submit 观察与来源/输出端口装配。入站同步有界接纳，异步任务由代次持有，Transport 不等待 App Server，/stop 可取消准备。
  按钮回调先校验单聊或群成员身份、应用、对应允许名单与新鲜度，在本地三秒预算内 ACK；未确认不执行、不重试。普通回调在 ACK 前占用同会话输入槽，停止撤销待 ACK 输入；普通/停止 ACK 接纳分别为每秒 24/8。回调结果使用主动回复并计额度，不能把回调 ID 当 msg_id。
  交互单独复核实时请求、原 Actor/Workspace 和当前绑定或已核验祖先归属，不借用旧正文来源；异步问题的最终回答来信通过原 SubmissionObserver 建立新来源，使该次提交的后续正文可回传。

  Queue 命令复用共享六操作和分页；add 的成功响应、官方 `item/started.userMessage` 的 Thread/Turn/Item/client ID 投影共同建立结果来源，start 另需精确 Queue ID 与响应 Turn。只接收当前已握手连接的身份通知；Queue 变化清理未用选择，不取消已发请求。计划任务由 Executor 在提交前准备独立来源，SubmissionObserver 精确确认 Turn；固定任务 Workspace 及原后台绑定，切换前台不撤销该来源，移除原绑定则拒发。两类结果均沿共享持久投递主动发送完整输出，不启动被动流；来源表仅保存身份，不保存正文。
  普通输入最多并发 32 个，另留 8 个 stop 槽；同目标普通准备不排队。仅非 commentary 完整 Item 与 Turn 终态入共享投递箱；引用在实时准入固定，富化不重选来源。
  被动命令每来信只尝试一个完整计划，失败不递归回错或重用序号；任务可使用被动正文流，未开始流式的完整结果主动发送，发送前使用共享精确授权守卫。
- `streaming.ts`：临时正文归约与被动 replace 流；同步观察增量，路由准入后启动合并发送，最终全文仍经共享持久投递。
  每次路由调用最多发送一帧并等待完成，更新不会在共享会话队列外循环；队列关闭信号贯穿来源等待、节流与平台请求。
  每来源只选一个 Item、固定序号 2（序号 1 留给输入错误回复），每代次最多记录 4096 个已选来源、128 个未收尾 Item。
  必须先观察到关联来源的 Turn 开始；追加到已运行 Turn 的来源保持完整正文投递，避免从中间增量开始拼接。
  每个正文最多 16000 UTF-8 字节，最多 120 个中间帧和一个结束帧，中间更新至少间隔一秒；这些均为本地限制，不是平台上限。
  协议透传可选的 `remain_msg_len` 非负安全整数；调度保留该回执。流控制器以新增后缀的 UTF-8 字节作保守扣减，只收紧、不提高本地预算；为零立即结束已确认前缀，缺失保持既有约束，非法值按结果未知关闭，不自动重试。
  帧复用账号串行发送器但不计入主动文字额度；原来信 300 秒单调期限不续期，收尾总期限 45 秒，每次 HTTP 仍为 15 秒。
  最终正文复用完整投递的本地引用显示转换，仅当候选仍延长已确认前缀时采用，否则保持原文；不改持久正文或已发前缀。结束帧成功后才写完整确认；已发或未知结果不自动整篇重发，显式人工重试沿用完整文字路径。
  长任务边界由一个代次持有的定时器在原窗口到期前 45 秒触发，只结束已确认前缀，不发送新正文；与在途帧通过同一 tail 串行。
  正文或帧数预算耗尽也尝试结束前缀。结束确认后才允许按最终全文与字素边界切出剩余正文，使用主动文字或文件接续；
  前缀检查点与剩余正文检查点共同构成完整交付，未知结束结果仍失败关闭。定时器在完成、关闭时清理，撤权信号阻止实际发送。
  关闭、来源撤销取消在途发送；未取得首帧或确定未发送/被拒绝时才允许完整文字回退。不存正文历史，不恢复旧流。
- `send-budget.ts`：每代次账号级预算，完整计划先预留；正文每 Turn 16 片、终态 2 片，主动账号/接收人滚动分钟 24/16 次、接收人滚动日 800 次，未知结果不退额度。

  `sendMarkdownImage` 仅用于显式图片 Markdown 模式，使用素材 prepare、无凭据预签名 PUT、ETag/MD5、complete 后发送严格 qqbot-media 引用；仍以最终消息 ID 确认。120 秒预算、各阶段原来源守卫及取消；客户端内最多缓存 100 个成功素材，保守 TTL，不延长、不持久化、不自动清理平台素材。Network 的 uploadImageMaterial 沿固定公网 IP 上传，使用原 MIME 并返回受限 ETag；普通 uploadPart 保持原协议。
  `getBotMenu`/`putBotMenu` 为 Setup 独立管理入口提供有界 GET/PUT；不参与 Gateway 启动、事件连接或消息投递。
  `sendStream` 显式指定 text/markdown 格式，生产正文使用被动 markdown/replace 帧，固定原来信、序号、索引和流 ID，复用有界请求、同步授权守卫及保守结果分类；不使用 event_id 或 is_wakeup。
  `sendResultFile` 固定文件名、UTF-8/Base64、file_type=4，正文最多 256 KiB；`sendImage` 只接共享校验后的 PNG/JPEG，file_type=1、固定文件名、本地最多 5,000,000 字节。两者先以 srv_send_msg=false 上传，再用 msg_type=7 发送，仅最终合法消息 ID 确认。
  协议不接任意本地文件路径或下载 URL。Outbox 图片沿共享顺序、主动额度和持久检查点；生成图还受共享 Journal 更小的有效图片容量约束，无路径仅 fileId 时提示内容不可取得，不伪称已发送。
  `sendFile` 接受安全读取后的字节、受限文件名和显式 file/video/voice 类型，复用两阶段上传发送；普通文件最多 64 MiB，MP4 30,000,000 字节，SILK 20,000,000 字节。超过 5,000,000 字节使用 upload_prepare、预签名 PUT、upload_part_finish 与合并，布局严格验证且不自动重试。显式文件沿独立 spool，原 Thread 守卫和取消贯穿每个网络阶段，完整预算 120 秒；旧长正文预算不扩大。file_info 按 TTL 保守计时，不跨目标或请求缓存；上传失败是 not-sent，最终消息派发后不确定才是 unknown。
  `sendText` 显式主动/被动模式，单片最多 2000 UTF-8 字节；被动序号取本地保守 1–4，
  原消息 300 秒窗口在调用时转换为单调期限，Token 等待后再次核验，不因等待重置。
  必传取消信号和同步 `beforeSend` 守卫，Token 前和最终 HTTP 发送前复核；一次操作的 15 秒期限覆盖 Token 与响应读取。
  成功只返回合法 `messageId`；`QqTextSendError.outcome` 区分 not-sent、rejected、unknown。仅一致的已知业务拒绝码认定 rejected，
  5xx、畸形/矛盾响应、缺少 ID、网络中断或发出后取消均不当作可重发失败。不分片、不重试、不切换模式，不写检查点。
- `inbound.ts`：单聊及群 @ Dispatch 解析，输出最小文字、成员 Conversation、来源、JPEG/PNG/GIF 图片、单文件或单一音视频元数据；纯附件可无正文，混合媒体拒绝。type103 引用只取唯一 ref_msg_idx 匹配元素的文字及固定附件注记，不下载引用附件，不输出其中的凭据或 URL；群可仅提供有效匹配引用，单聊保留原空正文拒绝合同。限制整树节点、深度及字节，拒绝嵌套历史。区分非目标事件、格式错误、不支持和超出本地预算；
  RFC3339 日历校验、Unicode 校验、唯一不透明 msg_idx 及附件 URL/数量/元数据预算在该边界完成。
  不保留 ext 中的鉴权字段，不执行允许名单、Workspace、去重或任务授权；这些仍属下一层，不以解析成功代表准入。
- `button-inbound.ts`：仅解析当前应用的 type=11/version=1、c2c/chat_type=2 或 group/chat_type=1 按钮事件，复用 RFC3339 日历校验；拒绝矛盾身份、畸形或超限回调数据，不解释命令或授予权限。
- `message-input.ts`：区分普通来信与按钮回调身份；回调没有普通消息的 msg_idx 或被动回复锚点。
- `task-sources.ts`：本代次任务来源注册表，由 messages 持有。接收已解析的来信身份和已授权作用域，
  不保存正文；原 Actor、Workspace 和 Thread 的实时检查由调用者提供，异步或抛错的检查拒绝准入。
  调用者须在撤权/归属切换时调用取消接口，Adapter 重建时 close；本模块不监听配置变化。
  守卫返回后再次复核关闭、取消和期限；普通 30 秒、音视频 120 秒准备预算从 reserve 入口起算，等待还复核投递调用方的取消信号。
  `reserve` 返回去重/容量拒绝或一次提交票据，票据观察器直接适配 Application `SubmissionObserver`。
  回调回答沿相同观察器确认结果资格，去重身份与文字来源分开；新回调来源不提供 streamSource，结果使用主动完整投递，不伪造普通来信。若实际追加到仍有效的同 Turn，原来源的期限与锚点保持不变。
  `capture` 只在请求尝试后捕获早到候选；`awaitSource` 等待最终结算，`isCurrent` 检查精确 Thread/Turn 和原作用域。
  `terminal` 收紧终态排空期限，`cancelTarget`/票据取消/`close` 清理授权及等待；这些都不会中断 App Server 任务。
  每账号最多 4096 个去重条目、128 个活动或预留来源、128 个关联等待；未知项留至代次结束，容量不足明确拒绝。
  普通任务结果按主动模式合同使用；被动命令次数和发送调度不由本模块管理。引用不能单独充当持久发送授权。
- `outbox.ts`：独立的完整文字执行组件，复用共享 ConversationDeliveryQueue、DeliveryReceipt 和 checkpointDelivery。
  同一 Item 的完成事件始终先核对已有流式，包括增量未标 phase、完成才标 commentary 的情况；已确认完整的流不再整篇投递，未发送的普通 commentary 仍按原路径发送。晚到 phase 的流式续接沿正文规划保留 Markdown 边界，不按正文字符串去重。
  全文发送前选定表示，再作为一个队列操作串行发送；最多 8 片，主动正文 Markdown 每片含包装最多 5000 个 Unicode 码点（含包装，20000 UTF-8 字节兜底），普通文字仍为 2000 字节，被动序号整体不得越过 4。每片记录实际文字/Markdown 类型，混合规划不改变原文字序。
  完整正文中独立一行、语法明确的 Unix 绝对本地文件/图片引用只展示名称和代码路径，不上传、不生成可点击链接；代码示例、网络路径和歧义构造保持字面回退。转换只影响发送候选，原正文和流式偏移不变，按转换后长度核对预算。菜单及计划任务的字面字段统一复用共享转义，不将普通括号转成公式分隔符。
  交互把完整字面详情与末尾按钮纳入同一计划，并可提供完整安全 Markdown 候选；发送前预留全部预算，逐片确认，不转文件。审批围栏候选保持共享详情原字面内容，不反解授权范围。
  用户问题可提供完整 Markdown 候选，合并正文与操作提示后复用安全段落规划；不超过原文字加控制面板的片数才采用，短问题同气泡附按钮，长问题仅最后一片附按钮。无法安全完整规划时仍用字面详情加面板，发送失败不换表示重试。
  通知和命令的 preferMarkdown 不增加原文字片数。正文的 preferMarkdown 与 allowResultFile 共同启用八片内的混合规划，可带续接 Markdown 起点；无法规划才选择原文字或文件，实际发送前已固定表示。显式 representation 的单片菜单不与自动规划或文件选项混用。
  总期限 45 秒，失败停后片，不截断、不自动重试、不切换模式；调用者提供精确目标的实时发送守卫。
  仅任务正文显式允许文件方案：在任何发送前先尝试完整文字规划，无法在八片内按字素完成时预选文本文件。
  文件与文字共享 Receipt、来源守卫和主动预算，一份文件计一次发送；不会在部分文字发送失败后改发整篇文件。
  正文失败提示只使用受控文案、现有状态额度及最多十秒预算；检查点写入失败、取消或撤权时不额外发送提示。
  被动原来信窗口在整条计划开始时固定为单调期限，排队与逐片发送不因墙钟回退延长窗口。
  关闭只取消本组件队列，不关闭 Adapter 持有的协议客户端。事件选择、来源与跨计划预算由 messages/send-budget 承担。

- `network.ts`：从旧 Surface 提取的网络资源接口；Bootstrap 的 `qq-network.ts` 保留每代次代理与连接池的所有权和关闭行为。

扫码 Worker 与生命周期入口位于 `scripts/qq-registration-worker.mjs` 和 `scripts/qq-registration.mjs`，

## 数据与当前限制

配置复用私有 TOML、源修订核对和原子保存，不迁移旧 QQ 配置或其他用户数据。
不接入旧 `qq-transport` Ledger；通过共享恢复协调器恢复当前 StateStore 的前后台绑定、模型及活动状态，不恢复旧消息来源，不清理历史消息或发送记录。
新来信可经共享用例恢复已选 Thread，并为明确参与的 Turn 建立新来源；旧 owner 或旧代次记录只留核对，不能补授资格。
StateStore 与 Delivery schema 不变，QQ owner 使用 v3；人工重试沿用共享机制，仍复核来源和预算，可能重复已收到分片。
回退前将 QQ 配置禁用；若回退版本不识别 `[qq]`，先私有备份配置并显式移除该配置段，
不要通过删除数据库或凭据目录绕过兼容校验。

不迁入旧正文状态机、交互、Ledger 或附件实现；详细范围、策略与证据见[QQ 消息开发流程与合同](../../../docs/qq-message-contract.md)。
完整文字 Outbox 的本地拒绝观察（2026-10-24，当时未启用正文文件方案）：非法 Unicode、超过 16000 字节、不可拆分的超长字素和被动分片越过序号 4 均返回 `invalid-input`；
拒绝发送守卫返回 `authorization`，关闭后调用返回 `AbortError`，上述路径检查点数均为零。
观察使用无真实凭据的协议客户端，守卫在联网前拒绝；未向 QQ 发送样例，未观察新 Outbox 的真实分片送达、平台失败或持久恢复。
第一层实现期间按用户要求未再次探测，只完成静态链路/失败分支审查及既有检查；旧脚本观察不等于新实现已经实机验收。
第一层提交后用户允许必要探测，具体范围与未决问题以消息开发合同为准，不因此启用正式 QQ。
连接失败使用受控错误；终止类关闭码锁定当前 Adapter，不借共享重试重新连接，修正配置后重启 Gateway。

协议参考见[上游来源](../../../docs/upstream-sources.md#qq-接入骨架基线)。
静态检查和本地观察不证明真实账号能力；真实连接证据及剩余缺口见下文。
