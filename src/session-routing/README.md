# Session Routing

本目录维护外部 Conversation、Workspace 与 Codex Thread 的前台绑定、后台绑定和订阅状态。

会话诊断只在内存保存最近一次成功新建、恢复或派生返回的压缩 Item ID 与指令文件来源；
绑定释放时清理，待恢复订阅不展示指令清单。`instructionSourcesForThread` 提供加载快照，
不扫描文件、不写入 StateStore，也不宣称反映后续文件修改或所有动态指令。
会话切换失败后的补偿恢复复用订阅恢复入口，刷新来源快照和实际设置，并清除待恢复标记。

执行上下文同样只作内存诊断：`executionContextForThread` 返回最近确认 cwd 和最近生命周期
响应的 roots 加载快照（含该快照 cwd）。设置通知只更新 cwd，不伪造实时 roots；目录变化
使已开始的审批归属查询失效。断线、关闭、待恢复及解绑后不展示旧上下文，成功恢复后重建。
未知上下文不由迟到通知复活。此投影不改变精确目录准入、执行请求或 Workspace 权限。
设置与关闭的上下文事实在同步接收边界消费，旧连接排队中的设置不覆盖重连状态。
生命周期诊断通过有界失效记录检查请求至最终绑定期间的变化；同 Thread 变化、断线或
观察窗口溢出时保守保持未知，不用迟到响应覆盖较新事实。确认取消订阅后统一进入待恢复状态。

`thread-port.ts` 的 `isThreadExecutionSettled` 接受 `idle`、`notLoaded`；`systemError` 还必须有 Client 在当前连续订阅中观察到的明确 Turn 终态证据，已知活动 Turn 始终否决。元数据读取中的空 Turn ID 和历史状态不能证明执行结束。该判据供释放与后代活动查询共用，不替代本地活动、交互、子代理和 Queue 检查。失败会话在订阅内完成最后完整复核，以取消订阅作为释放边界，随后复核父会话可见活动、本地活动与授权守卫、Queue 和后代；不在取消订阅后沿用失效证据。普通空闲路径仍做取消订阅后的权威复核。断线或重新订阅后无法确认的失败会话保留绑定，跨渠道接管仍使用独立空闲与授权条件。

显式生命周期操作接收可选授权守卫，并固定接收时的绑定与工作区；锁等待、权威读取、取消订阅和
本地绑定提交之间再次核对。已提交归档按实际结果结算；切换失败时恢复旧订阅、清理新订阅不受
过期用户守卫阻断。列表快速查询转完整扫描前及 Client 分页请求前均保留守卫。
订阅恢复清理不可用 Thread 时保留已经保存的工作区选择；失效的工作区 ID 继续报错，不能静默切到默认目录。
新建、自动接续和后台创建在绑定落盘失败时清理新订阅；已有合法归属的订阅仍保留。
清理也失败时同时报告原始写入和清理错误，不发布绑定成功或吞掉补偿失败。
活动恢复观察由调用方提供，Router 在每次实际权威读取或恢复请求前建立窗口，在合法绑定建立后交回快照，并在成功、失败或取消时释放。解除订阅后的补偿恢复使用新窗口，不复用被 `thread.closed` 失效的旧窗口；生命周期锁等待结束后才开始观察，避免把旧关闭事件应用到新请求。Router 不依赖 Core，也不保存第二份 Turn 历史。

## 文件

- `index.ts`：本模块的公开导出入口。
- `thread-port.ts`：定义 Thread 查询与生命周期窄端口，以及只包含路由、恢复和会话列表所需字段的
  稳定快照；快照保留 App Server 返回的 `historyMode`（`legacy` 或 `paginated`），新建 Thread 使用分页
  历史，既有 legacy Thread 不宣称支持 Revert；官方分区裁剪为稳定 `id/name/builtIn`，内置 Pinned 另投影为 `isPinned`，运行中 Turn 以 `activeTurnId` 表示，恢复会话另携带
  模型 Provider、实际 Default/Plan 协作模式、实际审批审查方式、更新时间/最近活跃时间；可选 `parentThreadId` 保留官方派生父子关系供本机归档识别和子代理交互归属核验，
  压缩 Item ID，不向业务层暴露完整官方 Turn。Thread 快照还保留官方当前模型与思考设置，供子代理开始和继续展示；只读查询支持取消，不把当前配置当作历史轮次遥测。端口可选声明已配置的模型 Provider 判定，用于把
  Provider 已被移除的历史 Thread 排除在自动接续之外，未实现的部署视为不做限制。
- `router.ts`：选择、搜索、绑定、恢复、归档和解绑 Thread，前台不注入 Workspace 权限；
  由 App Server 解析原生配置及会话继承，不按 Provider 或模型限制审批方式。已加载会话保留实际审批方式、订阅和活动 Turn 恢复管理能力，未知或 Guardian 值仍按实际值投影。协调持久化映射、订阅恢复、Provider/模型设置、
  压缩 Item ID、新建前台 Thread 的动态工具注册及 `thread/unsubscribe`，并按 Thread 向 Core 提供已绑定
  Workspace 的稳定 ID 与名称；动态工具不会触发既有前台 Thread 的替换或解绑；切换目标恢复成功后才解除当前绑定，启动恢复只有在 Thread 明确不存在、
  已删除、已归档、所属工作区不再配置或恢复校验明确不匹配时移除持久化绑定，但不改工作区选择；订阅恢复时把稳定 Thread 快照交回组合根。跨渠道接管只允许
  当前 Thread 与目标 Conversation 原 Thread 都由 App Server 报告为空闲时执行；保留被接管
  Thread 的现有订阅，只取消目标 Conversation 被替换 Thread 的订阅。跨 Provider 模型切换通过
  `newSession` 解除当前绑定并保留原 Thread，下一 Turn 由对应 App Server 以精确 Provider 和模型新建 Thread；
  不使用 `thread/fork` 复制 Provider 专属历史。自动接续收到渠道保留的 Provider 时只恢复相同
  Provider 的候选 Thread；没有兼容候选时按该 Provider 新建，避免把模型交给错误的 App Server。
  Provider 已由操作员移除的历史 Thread 属于永久不可用，不会被自动接续选中，此时改用其余
  兼容候选或新建 Thread，避免 Conversation 永久卡在恢复失败上。
  `startBackground` 是计划任务专用的窄入口：始终发送稳定 `threadSource=automation`、强制
  `thread/start`，不调用 `ensure` 的空闲候选选择，并在写入前限制每个 Conversation 三个后台绑定；
  后台 Thread 不携带前台 `dynamicTools`，防止计划任务递归创建任务。
  后台新建排队结束后复核本地提交守卫，并透传到 Client 的最终 RPC 发送边界；取消尚未提交的创建，
  不丢弃已提交创建的响应和 Thread 身份。
  后台容量由 Router 统一维护：异步新建和增加后台绑定的恢复切换先预留容量，完成或失败后释放预留；
  前台降为后台同步复核同一预算。恢复已有后台到前台的等量交换不额外占位，计划任务调度也读取
  包含预留的可用容量，避免不同入口并发时突破每 Conversation 三个后台绑定的限制。
  后台释放在本地绑定已被撤权清理时仍通过 `thread/unsubscribe` 取消订阅；已成为有效前台的 Thread 不由后台清理取消，避免仅删除映射留下订阅。
  Router 通过公开偏好接口保存未绑定会话的模型设置，解绑时与前台绑定和强制新建标记原子更新；
  前台绑定建立后消费保存值，已有 Thread 仍从 App Server 恢复权威设置。
  `newSession` 可接收同步 `onCommitted` 观察回调，在本次绑定/偏好提交后、通知或异步返回前调用；模型选择据此推进自身已提交的快照预期，不把等待期间的外部状态变化吸收为合法变更。回调不授予新的权限，也不表示后续操作已经完成。
  Router 同时向 BindingStore 维护会话活动时间与持久化“强制新建”标记：空闲释放、跨 Provider
  切换、Workspace 切换、新建、归档和跨渠道接管会标记下一消息必须新建 Thread；普通消息在
  `ensure` 创建 Thread 后清除标记，显式 `/r` 恢复也立即清除，因此只有恢复命令能重新关联
  已释放的历史 Thread。撤权清理所有绑定时会同时写入强制新建标记，重新授权后的普通消息
  不会自动接续旧 Thread。
  `releaseIdle` 只解除仍符合扫描条件的前台绑定；在 Thread 生命周期锁内及取消订阅返回后复核。
  若新活动使扫描失效，恢复同一 Thread 的订阅并交回权威活动状态；关闭或断线取消时保留绑定，
  由既有重连恢复处理，不写入强制新建标记。
  取消订阅后若持久化解绑失败，保留原绑定和压缩状态；空闲释放即时补偿订阅，普通解绑通过组合根
  回调登记既有订阅恢复；未提供同步状态恢复回调时，`ensure` 遇到待恢复绑定会重新登记恢复并拒绝本次输入，
  等待组合根恢复活动 Turn 状态。
  未注入回调时 Router 直接补偿；补偿失败的绑定在 `ensure` 中也必须先恢复订阅，
  不把仍存在的绑定直接视为可用。`ensure` 对已有前台绑定读取不含历史的权威快照，复核工作区和
  与显式恢复相同的来源；发现 `notLoaded` 时复用按 Thread 串行的订阅恢复，再通过调用方的同步
  回调恢复活动状态，同一次输入等待成功后继续。读取或恢复失败时不提交 Turn，不重发失败的 Turn。
  自动历史候选同样排除不允许的前台来源。只有解绑提交成功才清理派生路由状态。

切换到不同 Workspace 会解除当前前台 Thread，并在下一条消息中强制新建 Thread，不自动接续目标 Workspace
中的历史空闲 Thread；当前模型、思考等级和服务层级偏好仍按 Conversation 保留。

仍有活动 Turn、子代理或待处理交互的前台 Thread 在 `/resume` 或 `/new` 切换时转为后台绑定，保持 App Server 订阅与原
Conversation 归属；新输入只路由到前台 Thread。后台 Turn 完成后先与原生 Queue 的自动派发
协调；Queue 已启动下一 Turn、仍有排队条目或 Thread 仍为活动状态时保留绑定，只有权威状态确认
空闲后才取消订阅并移除后台绑定，Thread 历史仍由 App Server 保存。释放在生命周期锁内以及取消订阅后复核活动，
新活动或无法确认的读取会保留绑定并恢复订阅。Gateway 恢复时同时恢复前台与后台订阅；后台清理由 Application
按同一条件执行，确认释放后才提示通过 `/resume` 查看，不依据父 Thread 空闲推断子代理结束。
后台末次读取失败在补偿订阅后仍向生命周期所有者报告失败，进入既有恢复重试，不与权威确认仍忙混同。
- `thread-state-sync.ts`：定义并消费不含协议信封的稳定 Thread 路由事件，同步模型、思考等级和
  服务层级，并在官方通知未携带不可变 Provider 时保留 Router 已确认的值；归档或删除事件会清理对应绑定，关闭事件只表示无订阅者的空闲 Thread 已从
  App Server 内存卸载，保留可恢复的持久化绑定并登记订阅恢复；通知遗漏时由 `ensure` 的权威读取补足。
  官方通知的校验和转换由 `codex-client` 完成。

自动接续前必须检查来源、Workspace、活动状态和是否被其他 Conversation 占用。App Server 响应是事实来源，Router 的缓存只用于路由和界面加速。
已保存的 Workspace ID 不在当前注册表时明确拒绝，不改写为默认目录；只有从未选择的会话使用默认项。
Workspace 列表保留失效选择的身份，用户可以显式选择已注册项恢复，不自动迁移绑定或删除原数据。
输入携带的提交守卫同时约束新建、自动接续和已有订阅恢复；响应迟到时复核后才发布新绑定，失效的新订阅按既有清理路径释放。
显式恢复只接受当前工作区历史；`resume` 在写请求前读取 Thread 元数据，核对选择时的目录
和允许来源。恢复与重连统一检查历史目录及响应中的实际目录、权限和活动状态，避免用旧绑定
覆盖历史目录；普通切换失败时取消新订阅并保留原绑定。显式恢复、重连、接管或恢复旧订阅时，
若确认目录、权限或活动状态不匹配，统一先移除对应绑定，再取消已有订阅；前台绑定移除后，
下一条普通消息在当前工作区新建 Thread，不自动接续旧历史，也不改变其他有效的前后台绑定。
恢复、解绑、前后台切换、接管、归档与取消归档按 Thread 串行执行；涉及新旧两个 Thread 时按固定
顺序获取执行权，其他 Thread 不受阻塞。后台恢复在执行前及 RPC 返回后复核原绑定，官方通知已
移除的绑定不再写回；过期恢复不发布成功回调，也不取消后来恢复成功的订阅。
Gateway 重连或重启后，Client 必须从 `thread/resume` 返回的 `status` 与 `turns` 映射
`activeTurnId`，组合根再恢复仍在运行的 Turn，不能只恢复绑定，否则 steer、停止和下一 Turn
队列会误判为空闲。Provider 路由必须根据 Thread 的官方 `modelProvider` 选择已用对应启动配置
加载模型目录的 App Server，不能让第三方 Thread 回到 OpenAI 实例或 fallback 元数据。
恢复失败会区分永久不可用、固定版本官方 active-writer 冲突和其他暂时错误；Thread 已删除或归档、其 Workspace
已从注册表移除，或其 Provider 已由操作员移除时，绑定属于永久不可用并安全清除；Router 只返回稳定分类，
由组合根决定重试与通知。active-writer 仍保留绑定，不在本模块删除锁、抢占写入方或复制 Thread。

本模块不得导入 `codex-client` 或 `codex-protocol`；具体 Client 由组合根作为
`ThreadLifecyclePort` 实现注入。
审批归属查询只沿官方 `parentThreadId` 查找已绑定祖先，并核对各层 Thread 身份、工作区路径和
Provider；不把 Fork 或当前会话当作父子关系，不写入新的持久绑定。异步查询开始时固定绑定归属，
查询结束及交互期间继续检查有效性，绑定转移不能把旧审批送给新会话。任一层属于无人值守
`automation` 来源时拒绝交互，子代理不会绕过自动化任务的非交互边界。
分区目录与排序不进入 StateStore；Application 每次从 App Server 读取权威目录，并通过 Router
把官方分区过滤与 `section_position` 排序参数交给 Client。Router 只在已有 Thread 快照中携带
当前归属，用于会话列表和 `before` 校验，不建立平行分区索引。
