# 本地指标 WebUI

主会话列表以“总耗时”列显示会话总耗时；会话详情不再显示独立耗时卡片，每轮明细以“耗时”列显示本轮耗时。
数据来自 Gateway 持久化的官方 `Turn.durationMs`；总耗时仅汇总当前会话保留轮次，
不叠加子代理，也不受请求筛选影响。历史未补齐或耗时缺失时，累计值带 `*` 标记，提示说明这是已知累计，并注明历史状态和缺失轮数；全部耗时未知时显示 `—`，不按零处理。API 的 `sessionDurationMs` 仍仅返回完整总数，`sessionTiming` 提供已知累计、缺失轮数和历史完整性，渠道卡片与 WebUI 共用指标查询。

`codexc webui` 启动本地指标 WebUI，展示模型请求指标数据库（`request-metrics.sqlite3`）中的全局统计、
会话、请求明细与错误聚合；设置页还可修改结构化配置，并通过白名单异步任务执行受保护的服务与维护动作。回环监听未配置令牌时复用真实回环连接与 Origin 约束；配置令牌或绑定非回环地址时使用同一令牌鉴权。WebUI 不读取业务会话库，不接受任意命令。
“调用详情”页另有一份受限视图，按逻辑模型调用展示Codex 与 Relay 共用的全局采集开关落盘的一条请求与一个
终态响应；原始事件默认收起，只对回环连接开放，并可在预览确认后清空全部已识别转储。

## 服务日志

从「调用监控 → 服务日志」（`#/logs`）查看 Gateway、App Server、WebUI 或 Relay 的最近运行日志。
默认读取最近 100 行，可选择 100、200、500、1000 行；搜索只筛选当前结果，不检索全部历史。
服务通过 shadcn Base UI Tabs 切换 Gateway、App Server、WebUI、Relay；支持键盘标签导航。搜索、读取行数、级别和自动刷新直接显示在同一排，窄屏自动换行。
日志复用请求列表的 DataTable，表格撑满页面剩余高度并在内部滚动，支持列显示设置；当前读取片段不再分页。时间、级别、模块、来源、消息独立分列，每条记录单行显示；长消息截断，可悬停或展开详情查看，窄屏横向滚动查看各列。支持全部、警告及错误、单一级别与未识别筛选；搜索包含已读取原文中的事件和关联标识。
识别 Pino JSON 和带 ISO 时间、级别、模块的 tracing 文本；Linux 同时使用 journald 的优先级、微秒时间戳和进程标识，systemd 启停等消息据此显示级别与来源。应用正文中的明确级别与模块优先于 journald 元数据；无法识别且缺少元数据的内容保留原文，标准错误输出不自动视为错误。
有时间的记录跨来源按最新优先合并，时间未知的记录置后并保留来源内原始顺序，避免倒置多行纯文本。列表标题旁仅显示当前读取条数；筛选时显示「匹配条数 / 读取条数」。
详情按需展开结构化字段及脱敏原文，支持复制、换行与 JSON 格式化；不补采异常正文、堆栈或会话内容。
支持手动刷新及可选的 5 秒自动刷新，隐藏页面时暂停调度，离开页面取消请求。读取失败时保留同一查询的上次结果并标记可能过期，暂停自动刷新，手动刷新成功后恢复。
展开详情或向下滚动阅读时固定当前列表，后台仅保留最新读取结果；标题右侧与「列」按钮同排显示「回到最新」，出现变化时按钮改为「查看新日志」，点击后收起详情并回到顶部。切换服务或行数清除旧查询的阅读状态。

`GET /api/v1/logs?target=gateway&lines=100` 沿用只读 API 的 Bearer 令牌鉴权与不缓存响应；
`target` 仅支持 `gateway`、`app-server`、`webui`、`relay`，`lines` 为 1–1000 的整数，拒绝未知或重复参数。
Linux 读取对应用户服务的 journald；macOS/Windows 读取私有运行目录中的标准输出与标准错误，合并展示时保留来源标识，每个来源最多返回指定行数；运行目录与服务安装器一致，由当前配置的 `codex.socket_path` 所在目录确定。
Linux 使用 journal JSON，`streams[].lines` 每项为仅含脱敏 `MESSAGE`、`PRIORITY`、`__REALTIME_TIMESTAMP`、`SYSLOG_IDENTIFIER`、`_COMM` 的 JSON 字符串；不透传进程命令行等其他字段。文件来源的每项仍是脱敏文本。journald 优先级 0–2 显示致命、3 错误、4 警告、5–6 信息、7 调试；详情保留原始优先级。
文件读取上限为每个来源尾部 256 KiB，接口通过 `truncated` 标明较早内容被省略，页面仅显示当前读取条数；journal 命令有 5 秒超时和 256 KiB 输出上限，超限返回读取失败。
缺少日志文件与日志读取失败分别展示。常见凭据键、认证头、Cookie、URL 凭据在服务端隐藏，正文按纯文本显示，不翻译日志。
页面不接受文件路径、任意命令或日志删除，不连接 App Server 会话，也不改变日志等级；日志等级仍在「设置 → 数据与日志」管理。

Gateway 日志携带 `service=gateway`，组合入口按职责附加模块；WebUI 后台错误、Relay 转储/目录诊断与监听状态复用 Pino 安全 Logger，并附加服务、模块和稳定事件标识。现有 Thread/Turn、任务等关联标识按需保留，不记录消息正文或任意异常对象。
Gateway 沿用配置日志级别；WebUI 与 Relay 的上述服务诊断使用 `info` 阈值。正常监听变化为信息，可恢复的目录下载/设置回读失败为警告，明确的指标写入、转储、请求处理或审计失败为错误。
WebUI 后台启动输出结构化日志，交互终端保留访问地址提示；App Server 的输出格式由其自身管理。

## 命令

模型目录以独立的“内置搜索”列只读显示各账户 config 中的搜索配置，使用普通文本区分关闭、缓存、索引、实时及跟随全局。共用模型目录的账户仍分别显示，不把一个账户的设置应用给其他账户；配置读取错误按账户返回脱敏状态，刷新中与失败时隐藏旧值。使用主 config 的固定提供商显示全局值。模式是请求策略，实际搜索执行仍受上游接口、模型及权限约束。

`#/models/providers` 提供“提供商联网搜索”设置卡，覆盖具有独立 config 的第三方受管、Codex 兼容及自定义切换提供商。OpenAI 和使用主 `config.toml` 的固定提供商在通用设置中修改全局 `web_search`。第三方按精确 Provider ID 选择“跟随全局”或关闭、缓存、索引、实时，预览后明确确认；直接写入对应 config（例如 `sf-clp-main.config.toml`）顶层的 `web_search`，跟随全局则删除该字段。保存复用事务备份与并发修订保护，完成后回读并提示应用，不自动操作服务。旧 `codexc-provider-search.toml` 不读取、不迁移、不删除，仅保存在旧文件中的值需重新设置。新启动实例的新建／冷恢复会话采用设置，已加载会话不会即时更新；原生显式搜索参数仍优先。完整文件与恢复合同见[独立提供商的搜索模式](provider-integration-guide.md#独立提供商的搜索模式)。

「模型管理 → 模型配置」的 OpenAI 模型卡片统一读写 `$CODEX_HOME/models_cache.json`（未设置时为 `~/.codex/models_cache.json`）。展示缓存中的模型、上下文、可配置上限与思考等级；隐藏或不支持 API 的模型不展示。页面重新读取只查询文件，不导出、不联网，缓存缺失或结构不支持时明确报错，不用内置目录补齐。

Unix 缓存读取接受当前用户拥有且其他用户不可写的普通文件（包括上游可能创建的 `0644`），拒绝符号链接、非普通文件和超过 8 MiB 的内容，不主动修改现有目录权限；Windows 沿用私有文件 ACL 检查。备份保持私有。覆盖提醒按缓存路径和归属隔离，同一归属下 CLI 版本升级不会清除已保存值的跟踪；切换归属不混用提醒。实际上下文写入与目录刷新执行消耗管理高风险额度，预览只消耗普通写请求额度。

名称仅显示 `display_name`；「思考等级」取 `default_reasoning_level`，悬浮或键盘聚焦可查看全部 `supported_reasoning_levels`。「加速等级」展示 `service_tiers` 的名称，未声明时不推断档位。模型目录表格不展示「自动审批」列；刷新对比仍展示审批提示词声明：`model_messages.approvals` 任一模式有非空提示文本时显示「声明」，否则显示「未声明」，悬浮列出各模式状态，不代表当前启用了自动审批。缺失/null 使用上游默认文本，不表示不支持审批，也不代表当前权限或审批策略。模型列表接口只返回模式与状态，不返回审批提示文本。

详情侧栏分为「模型能力」和「模型提示词」。提示词页通过独立的 `GET /api/v1/management/models/official/prompts?model=…&revision=…` 读取选定可见模型，沿用管理鉴权与限速，缓存修订变化时拒绝旧请求。按基础指令、审批模式、协作模式、自动审查、权限与沙箱、多代理、Token 预算与压缩、操作确认策略、工具指引分组，逐条展开原文；缺失/null 不补齐，空字符串明确标注。仅返回 `model_messages` 中已定义的提示文本路径和工具描述前缀，不遍历其他任意字段、不返回工具参数 Schema，最多 512 项，仍受缓存文件 8 MiB 上限约束。正文仅在此接口返回，不随模型列表或刷新对比返回，不写日志、不持久化到浏览器存储。以纯文本展示，不执行 HTML、链接或模板，也不宣称是当前会话的完整提示词或 CLI 内置默认值。

点击模型名称打开只读详情侧栏，分为使用指引、输出设置、工具与输入、运行特性四组。25 项白名单目录声明中，输入类型、有效上下文比例、搜索工具支持状态和补丁工具类型移至模型列表，侧栏不重复展示。输入类型以文本、图片等标签展示，空列表显示无；有效上下文比例显示百分比；「工具」列以两行文字展示工具搜索与文件编辑的声明状态，补丁工具类型通过悬浮提示展示，缺失显示未声明，不把缺失当作不支持。网页搜索类型是独立字段，保留在侧栏。包含使用指引不等于功能可用；工具输出截断不等于模型上下文上限。缺失/null 显示未声明，与明确 false 分开；思考摘要参数缺失时附注锁定上游的默认支持值，不宣称会话已生效。悬浮或聚焦字段名可查看原始字段和值。模型消失、缓存范围切换或读取失败时不沿用旧详情。刷新对比仍展示全部变化字段，包括移到列表的字段。

加速档位说明中明确出现 `1.5x speed`、`2x speed` 等格式时，显示为 `Fast · 1.5×`、`Fast · 2×`；这是目录声明的速度倍率，不是实测性能或费用倍率。加速列不提供悬浮备注或下划线；无法识别速度倍率时只显示档位名称，不根据档位或用量描述猜测倍率。侧栏的「使用指引」和「运行特性」默认折叠，点击展开；刷新差异里的相应字段仍直接展示。

工具列在搜索明确支持、文件编辑格式已声明时使用「搜索」「编辑」短标签，以虚线下划线提示可悬浮或聚焦查看支持状态、文件编辑格式（例如 `freeform`）。不支持或未声明仍直接标出，不隐藏缺失状态。「编辑」对应 `apply_patch` 文件补丁工具。

OpenAI 模型的上下文可按精确 ID 编辑，使用专用的 272K（272000）、372K（372000）、500K（500000）、最大值和自定义选择。第三方另用与 CLI、自定义模型新增／编辑一致的 128K（131072）、256K（262144）、384K（393216）、512K（524288）、1M（1048576）预设，两组不混用。超过模型上限的固定预设禁用，最大值取该模型的可配置上限，自定义显示整数输入框。切换为自定义时保留当前选值。所有选择仍通过原有预览和确认流程，只接受正整数且不超过该模型已有的可配置上限；缺少上限或缓存归属元数据时不允许修改。保存只改对应模型的 `context_window`，不改思考等级、上限或其他模型，并保留缓存原有的 `fetched_at`、`etag`、`client_version`、`identity` 等元数据，不伪造缓存新鲜度或账户归属。

刷新仅提供「刷新当前配置目录」：先确认并备份，再执行 `codex debug models`。该命令可能自行更新缓存，因此预览阶段不执行命令；执行后对比实际缓存，不将标准输出再次写入文件。有效缓存可能直接复用，过期、CLI 版本或认证身份变化时是否联网取决于当前提供商、认证与配置；命令成功不等于远程刷新成功。输出的可见模型信息与缓存不一致时提示可能使用静态目录或回退结果，仍以缓存为准。执行后展示可见模型的增删、名称、上下文上限和思考等级前后变化，不展示隐藏模型、提示词或账户标识。不提供内置目录覆盖入口。

导出超时、输出超限或取消时会终止本次命令。若终止未确认，刷新返回错误，同一 WebUI 进程继续拒绝缓存写入，直到实际关闭；关闭服务也会保留未退出命令的归属并报告清理失败。

写入经过预览、一次性确认、文件修订复核和私有备份，保存后重新读取；结果无法确认时提示检查缓存和备份，不自动重试。备份和 WebUI 写锁独立保存于 Gateway 用户数据目录的 `providers/openai-cache/` 下，不修改 Codex Home 的目录权限。恢复应先核对后续变化，再从备份恢复，避免覆盖新的官方目录。Codex 不使用 WebUI 写锁，最后一次检查与替换之间仍有上游刷新竞态；后续官方刷新也可能覆盖手动修改。界面常驻说明覆盖风险，并在同一浏览器标签页重新读取时对比最近保存的修改，值改变或模型消失时提示可能被覆盖。这里只能观察文件变化，不能判定变化一定来自官方刷新，也不自动写回。

缓存文件不代表已运行 App Server 内存中的模型目录；全局上下文覆盖、缓存过期、CLI 版本或账户身份不匹配仍可能改变 Codex 实际使用值。上下文保存不触发联网刷新；当前配置目录刷新可能联网。操作均不重启服务，也不保证旧会话立即使用新值。

接口使用管理鉴权与限速：`GET /api/v1/management/models/official` 读取；`POST .../official/preview`、`POST .../official/context` 预览并保存上下文；`POST .../official/refresh/preview` 提交 `revision` 获取确认，`POST .../official/refresh` 提交同一 `revision` 和 `confirmationToken` 执行当前配置目录命令，不接受来源选择。确认绑定输入和缓存修订，同一 WebUI 服务内操作互斥。导出限制 30 秒与 8 MiB 输出，刷新请求预留 45 秒以涵盖进程收尾；断开请求或服务关闭时取消并等待自有操作结束。命令失败或取消不代表上游尚未写入，需重新读取，不能自动恢复备份覆盖可能发生的新变化。非取消失败记录固定原因分类，不记录 CLI 原始输出、缓存账户标识或模型提示词。

「模型管理 → 模型配置」按提供商显示模型：DS、CLP、CCG、OCG 各显示一份共用目录，自定义目录按各自 Provider ID 显示。自定义目录可添加、编辑和设置默认模型；
自定义、CCG、OCG、CLP 可通过独立本地移除按钮预览影响后确认。移除无需重填 Key、不联网更新目录，
CCG／OCG 的提供商组提供手填与 DS 来源导入，CLP 提供发现新模型；先读取候选，再选择新增模型、查看完整字段与来源、确认保存。候选有效期十分钟，过期或本地修订变化必须重新读取；不会覆盖已有模型，也不会删除远端缺失的旧模型。手填必须明确思考等级、图片、补丁与工具搜索能力，不能用未知值代替声明。下载和交互不占用全局保存锁。
所有同家族账户的默认模型和最后一个模型受保护。DeepSeek、官方模型目录显示不支持移除的原因；CLP Relay 的独立管理保持原入口。
编辑或移除均复用会话绑定的一次性确认、文件修订复核、审计和保存后回读。确认页说明历史引用、
Relay 保留授权及可能的在途影响；保存不自动重启。完整范围与恢复说明见[日常模型管理](provider-integration-guide.md#日常模型管理)。

已有自定义提供商的连接编辑与模型编辑分开。连接确认展示地址、协议、运行模式、WebSocket 声明及配置转换影响；保存保留模型目录和各自默认选择，不再重填模型或探测能力。连接保存结果无法确认时先回读，核对私有 Provider 配置备份后人工恢复，不直接重复写入；目录的 CLI `keep／rollback` 不代替连接配置恢复。

```text
codexc webui [--host 127.0.0.1|::1|0.0.0.0] [--port 端口]
```

参数优先级：命令行 > `config.toml` 的 `[webui]` 段 > 默认值（`127.0.0.1:8787`）。

- 默认监听 `127.0.0.1:8787`，无令牌即可访问；
- `--host 0.0.0.0` 绑定所有网卡（局域网/公网/Tailscale 直连）；此时必须先通过 `codexc config` 设置 `[webui].token`，不接受命令行 `--token`，
  API 使用 `Authorization: Bearer <令牌>` 校验，缺少令牌会拒绝启动；
- `config.toml` 示例：

```toml
[webui]
enabled = true        # false 时 codexc start/restart all 不再启动 WebUI；未设置沿用已安装状态
host = "127.0.0.1"   # 127.0.0.1 / ::1 仅本机；0.0.0.0 必须设置 token
port = 8787
token = "你的_访问令牌"
```

也可以运行 `codexc config` 选择「WebUI 设置」交互修改启用状态与以上三项，效果等价。关闭影响
`codexc start/restart all` 的启动选择和 `codexc update` 的服务恢复范围：设置本身不会停止正在运行的
实例，也不删除已生成的服务定义；`codexc restart all` 会停止它且不再启动，需要立即停止请运行
`codexc stop webui`。`codexc install` 只生成服务定义、不启动 WebUI，开启开关后仍需
`codexc start webui`；关闭后也仍可用 `codexc webui` 前台运行。
通过 `codexc config` 或 WebUI 设置页切换到 `0.0.0.0` 时，尚未配置令牌会自动生成 32 字节密码学随机令牌，
与监听地址一并保存到 `[webui].token`；已有令牌、切回本机后再次切换时的令牌均保持不变。
WebUI 的预览和取消不写配置，确认写入后提供新令牌供复制；配置修订变化或后续写入结果不确定时隐藏旧令牌。交互终端会显示本次生成的令牌，重定向输出不包含令牌。
请在重启 WebUI 前保存令牌；若未保存或响应丢失，可从服务器配置文件获取，或显式重新设置。
普通启动、只读配置查询和命令行 `--host` 覆盖不会自动生成令牌；手工配置仍须提供有效令牌。
需要更换随机令牌时，可在 `codexc config` → 服务访问 → WebUI 设置 → 访问令牌选择“重新生成随机令牌”，
或在 WebUI 的“网络与访问”页点击同名按钮。确认后生成并保存新值，取消不写入；保存新令牌后重启 WebUI，
旧令牌才会失效，浏览器须用新令牌重新登录。未配置令牌时该入口显示“生成随机令牌”。
- 前端在 API 返回 401 时显示令牌输入页；也可以通过
  `http://<地址>:<端口>/?token=<令牌>` 直接携带令牌打开（令牌会出现在浏览器历史，谨慎使用）。
  页面启动后会从当前地址中移除令牌参数。手动登录验证最多等待 30 秒，失败后可重新提交；令牌无效与服务暂不可用分别提示。
  令牌优先保存在浏览器持久存储，失败时尝试会话存储；无法保存并读取时停留在登录页明确报错，不反复刷新。

## 访问方式

单实例绑定一个端口即可同时支持以下入口，不需要多开进程：

| 方式 | 服务器绑定 | 令牌 | 典型命令 |
| --- | --- | --- | --- |
| 本机浏览器 | `127.0.0.1` | 不需要 | `codexc webui` |
| SSH 隧道 | `127.0.0.1`（或 `0.0.0.0` 经回环转发） | 绑定 `0.0.0.0` 时需要 | 本机执行 `ssh -L 8787:127.0.0.1:8787 user@服务器`，再访问 `http://127.0.0.1:8787/` |
| 反向代理 | 只读访问可用 `127.0.0.1`；管理写入用 `0.0.0.0` | 管理写入需要 WebUI 令牌；只读访问可由反代层鉴权 | Nginx/Caddy `proxy_pass http://127.0.0.1:8787`，管理请求保留原始 Host |
| Cloudflare Tunnel | 只读访问可用 `127.0.0.1`；管理写入用 `0.0.0.0` | 管理写入需要 WebUI 令牌；只读访问可由 Cloudflare Access 鉴权 | `cloudflared tunnel --url http://127.0.0.1:8787`，管理请求保留原始 Host |
| 局域网直连 | `0.0.0.0` | 需要 | 先运行 `codexc config` 设置 WebUI 令牌，再运行 `codexc webui --host 0.0.0.0`，访问 `http://<局域网IP>:8787/?token=令牌` |
| 公网直连 / Tailscale 直连 | `0.0.0.0` | 需要 | 同上，地址换成公网 IP 或 Tailscale IP |

- SSH 隧道、反向代理与 Cloudflare Tunnel 都可以连接服务器的回环地址；绑定 `127.0.0.1` 时可以保持无令牌，
  但管理写入仍只接受回环 Origin。域名反代可读取指标及不带 Origin 的只读管理资源；要提交管理写入，须绑定 `0.0.0.0`、配置 WebUI 令牌，并由代理保留浏览器访问的原始 `Host`；
- 只有直接绑定 `0.0.0.0`（局域网、公网、Tailscale IP 直连）才必须设置令牌；
- 所有入口共用一个实例与端口，配置一次 `[webui]` 后各方式同时生效。

回环监听的设置管理要求真实回环连接，Origin 只接受 HTTP 回环主机 `127.0.0.1`、`localhost` 或 `[::1]`；
SSH 隧道的本机转发端口可以与服务器监听端口不同。绑定 `0.0.0.0` 时，直连和域名反代均可管理设置，
每次请求必须通过非空 WebUI Bearer 令牌验证；写请求必须携带精确 HTTP(S) Origin，主机和端口须与请求 `Host` 一致。
读取请求可以不带 Origin，携带时仍校验；不信任 `X-Forwarded-Host`、`X-Forwarded-Proto` 等转发头。
令牌代表同一个管理身份，包含设置、提供商、Relay、服务任务和投递内容管理权限；高风险操作仍需预览确认。
原始调用转储仍仅允许真实回环连接访问。远程公网访问建议使用 HTTPS 反代保护令牌。

## 后台服务

WebUI 是独立后台服务，已安装时纳入 `stop/status/logs all`；`start all` 与 `restart all` 的启动段
按 `[webui] enabled` 跳过已关闭项。
`codexc install` 只生成服务单元并启动 App Server
与 Gateway，需要后台常驻时单独管理：

```bash
codexc start webui       # 启动
codexc status webui      # 查看状态
codexc logs webui -n 100 # 查看日志
codexc restart webui             # 重启
codexc stop webui        # 停止
```

- Linux 使用 systemd 用户服务 `codex-connect-webui.service`，macOS 使用 launchd
  `com.hegenai.codex-webui`；`codexc uninstall --services` 会一并卸载；
- 服务单元固定运行 `codexc webui`，host/port/token 全部来自 `config.toml` 的 `[webui]` 段；
- WebUI 自身重启和全部重启需要在本机终端执行，以免停止当前管理任务；管理 API 在预览与执行时均拒绝这两类自中断任务；
- 指标库只接受当前 Schema；不兼容时 API 明确报错，不迁移或删除数据库，见[源码安装与更新](source-install.md#更新)。

## 页面与 API

控制台显示已观测执行线程和轮次，跟随汇总时间范围：只统计期间有 Thread 和 Turn 归属的非审查请求，
线程按 Thread 去重，轮次按 Thread + Turn 去重；子代理是独立执行线程，不能把该数解释为用户会话数。
这是本机保留指标中的观测，不代表完整官方会话历史。
会话列表顶层只显示主会话；输入、缓存命中率和输出列展示会话自身，“总计”列展示自身与所有已登记后代的输入加输出，缓存属于输入的一部分，不重复计入。悬浮或键盘聚焦总计可查看纵向排列的子代理输入、缓存、缓存命中率、输出、合计及最后的总计；缓存部分缺失时直接显示已知数量，全部未知时显示 `—`，没有请求时缓存数量显示 `0`。主会话自身或后代在筛选范围内存在匹配请求即入选。行内轮次、请求仍仅统计自身，页面上方汇总包含子代理。

自动审查不作为独立用户会话或普通子代理列出。新采集请求只通过官方 `guardian_review` 来源和完整父 Thread/Turn 身份关联触发任务；明确审查不计入会话、轮次及子代理的任务请求数、用量或线程/轮次计数。全局、提供商和模型总量包含审查，以 `reviewUsage` 返回同范围“其中自动审查”子项，每条请求只计一次。原始父任务归属保留；缺少用途或归属时不从名称、时间或工作区回填。会话、每轮列表及 `/run` 的代表提供商、模型和思考等级只取相应范围最近的未标记响应（`source = owned`、`operation = response`、`request_purpose IS NULL`），不借审查、压缩或后代补齐。只有审查请求的会话/轮次不入选；有其他请求但无代表响应时保留行，模型等字段未知。用途为空不证明普通任务身份。

请求列表和详情的思考等级优先使用实际请求参数，HTTP 与 WebSocket 均采集 `reasoning.effort`，不依赖调用转储开关。自动审查缺少有效参数时显示 `—`，不继承父任务等级；修复采集前的历史空值不回填。响应格式 `SSE` 表示事件流传输，与是否思考或自动审查无关。

上述请求、模型及用量汇总均以成功入库且仍保留的记录为准，不表示提供商的完整账单。指标 IPC 的成功确认仅代表入队受理；拒绝、连接失败和确认超时会报告错误，不重发模型请求或指标。未入库请求、迟到指标和已裁剪历史不能由现存用量补算，自动审批事件的完整性也不用于证明 Token 完整。

请求及调用转储列表、详情将记录模型和“自动审查”用途标签分开显示；保留请求模型、响应回显和提供商，不从模型名猜用途。控制台“按模型统计”按持久化模型 ID 及统计映射归组，审查计入所属模型，在模型成员详情的独立列显示审查 Token，不生成名为 `auto-review` 的用途模型组。统计组名仅用于汇总，选择项、请求名称、响应回显与各项明细保留原模型；缺少模型时保留未知，不推断实际执行模型。路由、数据库、导出及模型筛选使用原始值。

固定模式自定义提供商的新转储使用真实 Provider ID 作为采集标签，不使用主实例的 `openai` 路由别名。已有转储保留原标签；历史记录只有 `openai` 标签时不根据当前配置推断第三方身份，转储明细展示已记录模型及用途。此采集修复需 App Server 使用更新后的代码重新启动，已有文件不改写。

请求与调用转储的“方式”列区分审查、压缩和已记录传输 `wss` / `http`；`wss` 不声明 TLS 状态。独立用途筛选支持全部、`autoApprovalReview` 和 `unmarked`（未标记，含历史未知），后者不证明普通请求。请求与错误页保留用途筛选，原始请求可组合父 Thread/Turn 归属；任务列表、轮次和 `/run` 固定排除审查，不接受用途选择。新指标保留用途与原始审查身份，无转储仍可辨认。模型完成/失败不表示审批通过/拒绝，无准确 Review ID 关联时不把汇总决定分配给单条请求。

调用转储列表与详情复用相同的用途和身份投影：HTTP 从已保存请求头读取，WebSocket 从该次请求的正文元数据读取，保留原始索引、请求头及报文。已识别审查但父身份不完整时，父会话/轮次为空；不可读取的历史正文不从握手或时间推断，保留原索引身份且用途未知。请求跳转转储仍只使用 `label + session + interaction` 精确引用，父身份缺失不使引用失效；文件清理或写入失败仍可导致详情不可用，不回退匹配其他调用。

`/api/v1/overview` 通过 `threadCount`、`turnCount` 返回这两个计数。
“按提供商”表格及 `providers[]` 同样提供 `threadCount`、`turnCount`，按所选时间范围内该
Provider 的请求独立去重。跨 Provider 的同一会话或轮次会分别计入对应行，行间相加不代表全局去重总数；
表格中的会话、轮次与请求数均显示精确整数。

控制台模型卡片显示请求数、涉及轮次、输入、缓存命中率和输出，默认前八组并支持展开全部。模型卡片不显示常驻框线；服务端有至少一个 `members` 就可点击或键盘聚焦打开详情，保留提供商与记录模型，键盘焦点有可见提示；未知模型明确显示未知。成员与分组的涉及轮次独立去重，不可相加。
`/api/v1/overview.models` 与全局、趋势使用同一只读快照和入库时间半开区间，按[模型统计分组](display.md#模型统计分组)跨提供商合并。所有用途按记录模型归组，未配置映射则保留原名，成员明细保留原模型。模型与提供商完整返回；CLI 模型报表按原始模型统计，最多二十组并显式说明截断。请求总量包含审查、压缩和 Relay，各自“其中项”不能再次累加；关联不足只计全局请求/用量，不补造轮次。缓存命中率按输入和缓存共同观测的样本加权，不平均百分比。

各聚合、会话、轮次、子代理、压缩及趋势返回 `usageCoverage` 的输入、输出、推理缺失请求数。数值字段保留已知累计：零请求为零，全部缺失展示 `—`，部分缺失直接显示已知累计，不加特殊标记；输入输出合计不重复加入缓存或推理。`reviewUsage` 是同范围明确审查子集，不表示审批事件数。缺失计数只描述现存行，不证明没有漏采或历史裁剪。日期趋势按入库时间；账户本地窗口估算可按请求开始时间，官方额度及重置快照保持独立来源，不能与请求趋势强行对账。

概览仅接受 `range/from/to` 时间参数，拒绝不支持或重复参数。统计映射通过管理设置接口在“模型管理 → 模型配置 → 模型统计分组”或 CLI 显示设置中编辑，不限 DeepSeek。保存后下次读取即生效，无需重启服务，未变化时不写入。概览和调用采集开关共享进行中的私有配置读取及取消机制，不缓存配置值或权限判断；配置不可读取或不符合当前结构时返回脱敏的 `503 configuration_unavailable`。

“首 Token”读取 `firstTokenMs`，从实际提交上游请求计到首个非空思考、正文、拒绝文本或工具参数内容事件；状态、额度和仅有用量的事件不算首 Token，也不以首包或完成事件填补缺失值。非流式 JSON 仅在完整解析并确认实际内容后观测，不推算流式首字。`responseTimeMs` 仍保留原始首事件时间供 API/JSON/CSV 诊断，不再作为页面或卡片的性能展示项。
Chat 原生与转换链路共用非空内容判定：正文、明文思考（含无签名 `reasoning_details`）、拒绝文本和函数名称/参数可计时，工具 ID、索引、类型和空参数不可计时；转换器不支持的内容仍按转换合同拒绝，不因计时判定而放宽。Responses 的内容 `.done`、内容块及输出条目 `.done` 首次携带已支持的非空内容时也可计时，`response.completed/failed/incomplete`、错误、Chat `finish_reason` 和 `[DONE]` 不兜底。未支持的事件或模态不据名称推断内容。
“速度”是请求平均输出速度，用总输出 Token 除以从提交上游到收到终态的请求耗时，展示为 `56.8 /s`。包含请求等待、思考、正文、工具参数、阶段间空档和网络接收，不含请求外的工具执行，也不是模型纯生成速度。总输出已经包含推理，不重复累加。增量可能集中到达，隐藏思考 Item 也可能在计算结束后才发布，因此不能用首末增量或 Item 接收间隔作完整输出量的分母；这些区间仅保留作诊断。

导出在独立只读 Worker 中使用同一快照，按当前排序逐块传输；浏览器保存 JSON 下载内容。每个 WebUI 进程最多同时导出两份，每份最多 64 MiB，读取和传输共用 120 秒预算，初始化与关闭另有限时。WebUI 通过显式 `Accept: application/vnd.codexc.metrics-export.v1` 请求有界帧流，校验完成终帧和流结束后才生成 JSON 下载；首块发出后的容量或超时错误也通过错误终帧保留原因和指导。默认 HTTP 请求仍返回 JSON，CLI 格式不变。超限请缩小时间范围或增加筛选条件后重试；截断或非法帧明确失败。取消请求、离开页面及停止 WebUI 会取消导出；尚未确认退出的 Worker 继续占用名额，Windows 辅助进程未确认退出时保留进程引用。
帧头固定为 1 字节类型和 4 字节大端无符号负载长度。类型 `1` 的数据帧各含 1–65536 字节 JSON 原始片段，最多 1024 帧、累计不超过 64 MiB；类型 `2` 是零负载完成终帧，类型 `3` 是 1–64 字节 UTF-8 错误码终帧，只接受既有指标导出及数据库错误码。终帧后必须立即结束流；未知类型、长度、错误码、错误码的非法 UTF-8 编码、截断或额外数据均失败。首块发送前的 HTTP 错误仍用原状态和 JSON 错误对象返回。
请求明细表在模型名旁为已登记的子代理请求展示小号「子代理」标签，不展示代理路径或单独的会话类型列；主会话及未关联请求不加标记。标识仅覆盖 Gateway 已登记的子代理关系，不根据模型或请求内容推断。Relay 和自动审批审查请求不使用归属会话推断子代理身份。来源列仅展示 Codex 或转发及调用方。此关联不改变请求筛选、排序、分页或统计口径，也不修改数据库格式。
请求明细表不展示 Thread、Turn 列，筛选栏也不提供 Thread ID、Turn ID 输入；从会话或轮次跳转时仍保留
链接中的关联范围，点击“重置”可清除。其他页面的会话与轮次筛选、API 和 JSON 导出的归属字段仍保留。

手动查询时，WebUI 通过私有 Gateway IPC 发起查询，由 Gateway 实时访问第三方官方账户接口，OpenAI 则复用
App Server 额度查询；成功结果由 Gateway 写入快照后返回页面。数据库保存最近一次观测，不代表持续实时更新。

此账户查询通过 Gateway IPC 获取脱敏快照，不读取凭据、不直接调用官方接口、不执行 CLI 命令，也不定时轮询。查询失败时
保留最后一次有效快照，在对应账户卡片内显示“刷新失败”与单账户重试；查询失败按配置、超时、认证、限流、网络、服务与响应异常生成固定提示，未知内部异常仍显示“账户刷新失败”，
不透传异常正文。上游认证失败返回账户刷新错误，不触发 WebUI 退出登录。Gateway 日志只记录 Provider、
失败阶段、分类、耗时和受控 HTTP/网络错误码，不含凭据与响应正文。
四类账户查询共用每次 10 秒总预算；CCG 两次串行请求不重置预算。同账户并发查询共享正在进行的请求，
各等待方独立取消，最后一个等待方退出才取消上游查询；页面断开经 HTTP 和私有 IPC 传递取消，Gateway 关闭主动取消刷新与启动预热，在关闭指标存储前最多等待预热 5 秒，迟到结果不写入快照。
预热失败也按账户记录安全日志，主动取消不报为上游故障。页面最多同时查询 4 个账户；
每个账户完成后立即更新对应结果，不等待其他慢账户。刷新期间禁用刷新按钮，各账户错误互不覆盖。
单账户成功只更新该账户，失败只更新错误；快照回读和刷新响应按观测时间保留较新值，
重置券操作期间的新额度不会被其他账户的迟到结果覆盖。独立快照同步会取消尚未完成的批量刷新收尾读取，
避免旧整表因缺少新账户而清除刚取得的额度；有效的整表读取仍负责移除已删除账户。
OpenAI 快照的更新时间表示额度查询成功的时间，普通 Token 用量查询不推进这个时间；
Gateway 重启后若尚未取得新额度，普通用量查询也不覆盖数据库中的已有额度。
较早发起的额度查询迟到时不能覆盖较新的成功观测。
账户刷新使用独立的每主体每分钟 120 次限额，不消耗设置写入配额，鉴权与 Origin 校验保持不变。
刷新响应中的有效快照会直接用于展示，包括首次列表读取失败后的重试；后续列表
同步失败不丢弃已取得的数据。账户列表或快照整体读取失败在账户区标题下提示；某一提供商的账户元数据无法读取时
保留来源标识并只提示该来源异常，不把该来源误报为未配置，也不影响其他 Provider 或该来源已有的有效快照。

OCG 官方接口明确返回 HTTP 403、`EntitlementError` 和 `OpenCode Go subscription required.` 时，
卡片显示“无有效订阅”，隐藏旧额度，提供重新刷新与“删除本地账户”。该响应不能区分已到期和从未开通；
其他 403、鉴权失败或网络异常不作订阅状态判断。删除复用账户设置的预览和二次确认，明确提示该账户历史
Thread 将不可恢复，不会取消或续订官方订阅；不会根据错误状态自动删除账户。
无订阅状态及确认时间由 Gateway 保存到共享快照，页面重开与服务重启后仍可读取；普通刷新失败
只提示本次查询异常，不恢复旧额度。成功取得新额度后更新状态。删除成功立即移除对应卡片，
再独立同步列表；同步失败不撤销删除成功提示，并保留运行服务所需的 `codexc restart all` 提示。
删除与列表同步按完整 Provider ID 隔离；删除 `ocg-main` 不影响同名的 `ds-main` 或 `ccg-main`。
账户快照使用指标数据库表与 JSON 字段，`subscription-required` 表示无有效订阅。
历史快照按指标保留期限清理，但每个账户源的最新确认状态继续保留；保留期限到达不会将无订阅账户恢复为可选。

API 响应类型由 `scripts/webui-api.ts` 声明，前端从该共享类型导入，不再单独手写镜像。

## 架构

```text
Gateway 指标收集 ──> request-metrics.sqlite3（指标数据库）
                            │ 只读
                            ▼
              scripts/webui-server.mjs（codexc webui 服务）
                ├─ /api/v1/* 指标只读 JSON API（Observability Store 只读模式）
                ├─ /api/v1/management/* 回环管理，或 0.0.0.0 下强制 Bearer 的远程结构化管理 API
                ├─ /api/v1/traffic* 回环限定的模型转储只读 API
                └─ webui/dist 静态托管
                            ▲
                            │ /api/v1/*（同源，令牌可选）
              webui/（Vite + React 前端）
                ├─ lib/  API 客户端、格式化
                ├─ hooks/ 数据 hook
                ├─ components/ 布局、指标区块与请求明细数据表格
                └─ pages/ 页面组合
```

- 服务端只读查询复用 `codexc metrics` 的同一能力（`metrics-database-access.mjs` /
  `metrics-export-format.mjs`），不维护平行索引；
- API 响应类型单一来源是 `scripts/webui-api.ts`，前端只做转出；
- 前端构建产物随源码安装器构建并安装，`codexc webui` 不依赖源码目录即可托管。

## 边界与安全

- 默认只监听回环地址；绑定非回环地址（`0.0.0.0`）时必须启用访问令牌，否则拒绝启动，
  令牌比较使用常数时间算法，令牌存浏览器 `localStorage`，重新打开浏览器仍可复用；
- 指标数据库以只读模式打开；设置修改只经过 Config 结构化写入口，不直接写数据库；
- 静态资源按白名单扩展名提供，路径限制在 `webui/dist` 内；HTML 页面及未构建回退页设置同源脚本 CSP、
  禁止 iframe 嵌入与 Referrer 泄露，主题初始化脚本作为同源静态文件加载。

边界约束：

- WebUI 不读取、不解析业务会话库；App Server 用户设置通过后端结构化 RPC 适配器访问，不把协议或凭据暴露给前端；
- 调用详情页只接受真实回环连接，且只按已知标签读取用户数据目录下 `traffic/` 的 V2 session，不接受任意
  路径；该页展示的是未脱敏的原始 prompt、代码与工具输出，不要分享截图或展开内容；
- 指标 API 不提供写接口；设置管理仅允许计划内字段，并修改对应结构化入口；敏感 Provider 凭据只写入私有凭据目录；
- 指标 API 只接受 GET，设置管理只接受明确的 JSON POST/PATCH/DELETE；未知 API 与非 `/api/v1` 前缀统一返回 JSON 404；
- 既有配置令牌不通过读取或预览响应返回，也不写入日志；首次切换全网卡监听或显式重新生成的新令牌仅随该次成功写入响应提供，页面暂存供复制，不自动写入浏览器存储。登录时输入的访问令牌按前述约定保存在 `localStorage`。

## 前端

左侧导航的“渠道投递队列”进入独立页面（`#/delivery`），在线只读查询当前配置对应的持久投递箱。记录采用与会话页相同的 DataTable 列表容器，包含标题摘要、列显隐、表内空状态和骨架行，表格区域独立滚动；底部显示匹配条数、固定每页 50 条及页码翻页，窄屏可在表格内横向滚动。主列表展示目标会话及账号、内容摘要、状态、入箱时间和操作，状态计数合并在筛选项中。取消行内详情展开，不展示检查点、尝试次数、占用及原始 Thread/Turn 等诊断字段；记录 ID 仅保留在操作确认摘要中。元数据接口不返回消息正文、授权归属、密钥、平台消息 ID 或检查点操作内容。普通实时增量和临时状态不在此列表。存储中的 `sending` 不能证明 Gateway 当前在线，`uncertain` 也不等同于确定发送失败。

查询固定每页 50 条，`before` 是上一页最后一条的序号（初始 0，表示无上界），`state` 可省略或为 `pending`、`sending`、`uncertain`、`blocked`；返回 `nextCursor`，不接受未知或重复参数。列表按入箱序号倒序排列，最新入箱的记录在前；此排序不改变实际投递顺序，汇总始终表示全局。取消固定元数据轮询：页面 Hook 订阅 SSE，收到队列变化通知后合并短时间内的事件，再读取当前筛选和分页快照；每次快照读取完成后，下一次自动读取至少间隔 2 秒，为摘要及其他管理读取保留配额；读取或确认操作期间保留通知，结束后补查。仅成功快照确认读取开始前的通知版本，读取期间新增的通知继续保留；临时网络、超时和 5xx 失败按 2、4、8 秒最多自动重试 3 次，429 每次至少冷却 60 秒，通知及订阅重连不绕过冷却或重试上限；非临时错误或耗尽重试后提示手动刷新。失败时不显示列表已同步，手动或操作完成后的读取成功会恢复自动更新。页面隐藏或网络离线时断开订阅，恢复可见、网络恢复及重连成功时通过初始通知补查；离开队列页面取消请求和订阅。通知中断显示重连状态，按 1 至 30 秒退避重连，保留手动刷新；筛选或翻页不会混用旧页面数据。投递箱尚未创建、读取失败和当前筛选为空分别显示；读取失败隐藏旧记录。读事务不创建投递箱、不访问密钥、不执行恢复或修改发送状态，磁盘格式仍为 v1。

列表通过 `POST /delivery/content-batch` 一次补充当前页最多 50 条内容摘要，请求体为 `entries: [{id, revision}]`，重复 ID、空批次和超限批次均拒绝；响应 `records` 保持输入顺序，每条包含 ID、修订及 `content`，缺失、修订失效或无法解码的记录返回 `content: null`，不影响其他记录。该接口虽使用 POST 承载有界批次，仍为只读操作，消耗管理读取配额，不消耗写入及高风险操作配额；Origin、鉴权、正文上限和 no-store 保持不变。同页按 ID 与修订复用结果，事件触发的元数据刷新不会重复解密未变化记录。离开页面取消请求并释放缓存，临时网络错误、429 或 5xx 在页面可见时每隔 60 秒最多自动重试两次，成功摘要继续复用；记录失效或不可解码不自动重试。手动刷新可重新尝试失败摘要。摘要展示本地化事件类型、状态、最多 160 个字符的两行文本，图片仅提示格式；不支持从列表展开全文或原始协议字段。读取失败显示“摘要暂不可用”，不妨碍核对投递元数据。

内容接口仍受管理鉴权、Origin 和读取限速约束，不缓存 HTTP 响应；批量读取先取得元数据修订基线，再逐条在短只读事务内核对修订并读取对应密文，事务释放后才解密、裁剪和等待消费确认。修订变化的项返回空结果，不混用旧元数据与新正文，也不在等待客户端时持有会阻塞投递写入的读锁。仅返回限定展示字段，不输出 owner、密钥、工具输入、平台消息 ID 或图片二进制，不累计原始正文。文本以纯文本显示，不执行 HTML。
投递箱读取由最多两个只读 Worker 执行，初始化在 Windows 限时 30 秒、其他平台 5 秒，普通读取和关闭分别限时 5、2 秒；批量投影结果累计最多 4 MiB。每条内容处理确认后才读取下一条，断开连接取消本次读取；过载返回暂不可用。未确认退出的实例继续占用名额，Windows 还须确认 ACL 辅助进程已退出，不因等待超时宣布关闭成功。元数据查询不访问密钥或正文，也不创建投递箱或修改发送状态。

`uncertain` 和 `blocked` 记录可勾选；表头只选择当前页可处理记录，筛选/翻页重置选择，修订变化使旧选择失效。点击“重试所选”或“忽略所选”后统一确认，最多 50 条。批量接口接收 `action: retry|ignore` 和 `entries: [{id, revision}]`，确认时另带一次性 `confirmationToken`；重复 ID、空批次和超限批次均拒绝。确认框显示数量、可滚动的所选会话/账号/记录 ID 摘要及动作风险，预览和提交期间显示处理中反馈，无需停止 Gateway。重试会清除检查点并重新排队，可能重复已送达内容；忽略会永久移除所选记录、不再发送，不能撤销，也不表示已经送达。

投递 SSE 使用 Authorization 请求头及现有管理鉴权、Origin 校验和读取限速，不把令牌放入 URL。通知只包含 changed / heartbeat / unavailable 类型，不携带正文或身份。Gateway 在投递入箱、状态转换、检查点及管理操作完成后，经独立私有通知 IPC 推送变化，100 毫秒内合并通知；通知端点沿用投递控制端点路径并追加 `.events`，与管理写操作独立，各最多 8 个连接。订阅先注册再通知首次读取，避免快照与订阅间漏变化。15 秒心跳不查询数据库，连接最多保留 5 分钟后重新建立以重新鉴权；慢客户端超过写缓冲即断开，由重连后的快照收敛。WebUI 停止时关闭长连接。


预览只读，记录修订覆盖展示字段、完整检查点和加密载荷身份。提交经同一管理鉴权、Origin、高风险限速与审计后，优先通过投递箱的私有 IPC 交给运行中的 Gateway。Coordinator 暂停取出新投递，目标会话有在途投递则返回忙碌，其他会话继续处理；在一个事务内重新校验全部记录并处理，同步内存容量、顺序屏障并唤醒调度；预览及提交前按 ID 索引在一次读事务中读取所选元数据，不重复统计全局队列；任一记录变化则整批拒绝。IPC 请求有版本、最多 50 条的唯一 ID/修订、256 KiB 帧及 20 秒超时限制，Unix 端点位于系统 `/tmp` 对应的规范目录下 `cdc-<uid>/<投递目录规范路径的 SHA-256>`，长度不随数据目录增长；父目录须为当前用户拥有的私有目录，Socket 仅当前用户可访问。Windows 使用已有私有描述文件及认证管道。批量查询通过单个 Worker 命令执行，查询与管理写入均不占用确认、关闭的预留邮箱容量，过载时返回忙碌。仅在确认未发送 IPC 命令且 Gateway 不可连接时使用维护模式并获取独占锁；命令发出后响应丢失返回结果未确认，不自动重试或回退。运行中的 Gateway 未提供当前在线接口且持有写锁时明确拒绝操作，提示核对版本并重启；不会绕过写锁进入维护模式。维护模式不创建投递箱、不恢复其他 `sending`、不清理临时图片，也不自动启停服务。在线重试成功后自动恢复发送，仍复核当前授权；Gateway 未运行时保留待发送状态直到启动。提交结果未知时刷新核对；审计和关闭失败分别报告，关闭未确认时先检查进程与队列。单条 `/delivery/preview`、`/delivery/retry` 接口仍仅支持重试。


调用详情的调用列表、错误记录列表也复用上述公共表格，列显隐分别保存。调用列表保留提供商/批次筛选、每页条数、分页上限和点击行进入详情；错误列表保留查询筛选及会话/轮次跳转，并使用统一的每页条数与分页控件。三者维持服务端原有顺序，不提供仅对当前页生效的伪全局排序。

前端是独立的 Vite + React 子项目（`webui/`），UI 使用 shadcn 的 Base UI `base-nova` 组件，保留深浅色主题与中英文显示。模型目录更新成功使用自动消失的 Toast；确认弹窗仍需明确确认，执行期间不可关闭。组件维护规范见 [WebUI README](../webui/README.md#ui-组件规范)。

目录结构：

```text
webui/src/
  lib/         API 客户端、共享类型转出与格式化（Token/时间）
  hooks/       资源数据 hook（统一 loading/error/refetch）
  components/  Sidebar 布局、指标区块、共享数据表格组件与调用摘要/明细区块
  pages/       概览、会话、会话详情、请求、错误、调用详情、模型管理、消息渠道、设置子页
```

左侧「模型管理」使用可折叠二级菜单：提供商（`#/models/providers`）、账户与凭据（`#/models/accounts`）、模型配置（`#/models/configuration`）、上下文与压缩（`#/models/context`）。子页可直接打开，当前子页高亮并展开父级；点击父级文字或箭头仅展开或收起子菜单，不跳转页面；桌面图标模式点击父级同时展开侧栏，手机选择子页后关闭抽屉。提供商状态与自定义提供商使用表格，新增或编辑在弹窗内预览确认；账户按平台汇总为可筛选表格，凭据只写入。模型配置区分 Codex 默认值、托管提供商默认值与渠道新会话覆盖；上下文页只保留 Codex 全局窗口覆盖与自动压缩。各模型窗口在模型配置表格内编辑：OpenAI 使用专用 272K、372K、500K 预设（K = 1000 Token）；托管账户及自定义目录与 CLI 共用 128K、256K、384K、512K、1M（K = 1024 Token），两组都保留最大值和自定义输入；第三方最低 1024 Token，OpenAI 保留正整数约束。托管目录按提供商家族分组，每家只展示一组模型；上下文、默认思考等级、模板和本地移除作用于该家共用目录，账户默认模型选择仍各自保存。用户偏好作为一组写入，Plan 思考等级等仍保留在设置页。各子页手动刷新及恢复可见时读取当前配置，确认期间延后自动刷新；写入后刷新同页关联配置。

自定义提供商的新增／编辑弹窗添加模型时，先选择起始模板，默认固定 OpenAI 底座，也可选择 DeepSeek，再填写模型 ID、显示名称和上下文。模板带入提示词、来源及已声明的有效上下文比例、压缩阈值和截断策略；上下文必须手动填写，压缩阈值须适配手填窗口；可展开查看所选模板的能力参考，明确标为仅建议。思考、图片、`apply_patch` 和 `tool_search` 能力均可选择支持／不支持／未知，未知暂不启用。模板选择只影响下一次添加，不覆盖已填写草稿或已有模型；已有模型仍通过独立的「更新模板」流程修改模板。候选通过只读 `GET /api/v1/management/provider-model-drafts` 加载，失败须重读，不回退空白模型；关闭弹窗取消未完成读取。

内置搜索读取全局 `web_search` 及精确 Provider ID 的独立覆盖，不使用额外的模型搜索能力声明过滤请求；搜索是否执行仍取决于上游接口和模型。模型目录提供全局设置与独立提供商搜索设置入口；保存确认按实际值展示修改前后的模式，缺项显示“跟随全局”。搜索诊断保留，不自动修改配置。

`apply_patch` 和 `tool_search` 提供独立检测按钮。每次使用当前地址、协议、模型、凭据及手填默认思考等级，只探测所选工具，最多三次请求、总预算 45 秒，可能计费。结果需明确回填且只修改对应项；可取消，修改草稿后旧结果失效，最终仍需预览确认保存。另有「检测原生网页搜索」可选诊断，最多一次请求、总预算 45 秒，会让上游真实执行 `web_search`，可能产生模型和搜索费用。只有完整、可验证的 `web_search_call` 搜索完成事件才能确认支持；请求成功、普通文本或模型自称已搜索都不足以确认，Chat 转换链路未取得执行事件时显示未确定。网页搜索诊断不提供回填、不生成保存绑定令牌、不改变联网搜索开关或 `tool_search` 声明。覆盖与限制见[添加时探测并写入](provider-integration-guide.md#添加时探测并写入)。管理接口 `POST /api/v1/management/provider-settings/probe` 必须指定 `capability`（`applyPatch`、`toolSearch` 或 `webSearch`）与 `reasoningEffort`，沿用管理鉴权与来源校验，正文最多 16 KiB，每个 WebUI 实例同时只运行一个探测，连接断开取消请求。

自定义模型的高级设置默认折叠，提供模型描述、等级说明、最大窗口、图片原始精度、详细程度、摘要参数、指令模板、有效上下文比例、压缩阈值和工具输出截断；采样字段沿用已加载定义，暂不增加编辑项。预览展示来源、三态声明和实际指令（优先显式 `instructions`，其次模板 `modelMessages.instructions_template`）；目录与详情保留未知和不支持的区别。切换思考为未知或不支持会清除关联默认等级及说明，关闭图片能力会清除原图细节，避免冲突。Chat 上游同样开放全部能力选择，切换协议保留已有声明，不因这三项声明拦截保存；界面说明当前请求转换限制。字段约束及 v5 备份回退规则见[扩展能力与高级设置](provider-integration-guide.md#扩展能力与高级设置)。

模型配置目录的所有模型行均提供「操作 → 检测原生网页搜索」，包含 OpenAI 官方、托管账户、共享官方目录和自定义目录。弹窗说明模型及搜索费用，用户点击「开始检测（可能计费）」后才发请求；共享目录包含多个账号时必须明确选定一个，不会广播其他账号。`POST /api/v1/management/provider-settings/web-search-probe` 仅提交 `provider`、`model`、`revision`，使用所选账号当前配置的连接、凭据及上游模型映射，第三方沿用模型默认思考等级；官方 OpenAI 不额外指定思考等级，使用当前可读取的登录凭据，凭据不可用时明确报错，不自动刷新登录。请求上限、证据判定和仅诊断限制与草稿入口一致。切换账号、关闭弹窗或配置／目录修订失效时中止请求并丢弃旧结果；进行中禁用重复发起，支持主动取消。结果不保存、不回填，也不修改策略或模型能力声明。

DS、CLP、CCG、OCG 和自定义独立目录的模型行提供“更新模板”：选择准确来源，受管提供商可选提示词／能力范围，自定义提供商可更新提示词及来源并选择“本地工具”，两类模型均可独立勾选运行设置（有效比例、压缩阈值、截断策略）；默认仅更新提示词，其余手动参数保持原值。核对前后差异后确认。旧模型缺少关联时不自动预选。读取选项使用 `GET /api/v1/management/provider-model-templates?provider=...`，响应 `availableSections` 决定可选范围；自定义的本地工具仍使用接口范围 `capabilities`。CLP 此时下载一次官方候选，整体限时 25 秒并支持取消，无需先运行 CLI 命令。只投影当前目录受支持模型，候选包含 Flash 时才读取仓库 DS 模板。快照仅在当前进程保留 10 分钟，预览和写入复用该快照，不重新联网。每个 WebUI 实例只允许一个候选读取，断开连接取消下载。写入继续使用 `/provider-settings` 的 `model.template.update`，复用修订、一次性确认、审计和回读；候选过期或被淘汰、进程退出、目标目录修订变化时须重新读取。保存不自动重启服务。来源与保留字段见[账户模板更新](provider-integration-guide.md#对比并更新账户模型模板)。

### 刷新、草稿与关联状态

- 已加载的设置在后台刷新或刷新失败时保留展示；失败明确提示并提供重试，依赖该快照的修改操作暂时禁用。
- Codex 设置与提供商设置的只读快照在服务启动或重启期间遇到 503 暂不可用或网络连接失败时，分别最多补读 3 次（间隔 1、2、4 秒，仅在本轮读取开始后的 10 秒内发起）。慢请求、鉴权失败及修改请求不自动重试；离开页面或手动重新刷新会取消旧的读取及等待。服务端从读取开始设置 20 秒取消期限，包含连接与初始化；HTTP 断开或期限到达关闭本次自有连接，资源清理仍须等待确认，不终止共享 App Server。关闭失败保留客户端，后续读取或 WebUI 关闭先重新清理；预览和已提交修改不使用这套读取取消语义。
- 第三方模型目录通过 `GET /api/v1/management/provider-model-catalogs` 独立读取本地已保存目录，响应为 `{ catalogs }`，不接受查询参数，不调用 App Server。首次管理快照不可用时仍可查看目录、能力及提示词；文件损坏或未完成事务返回 `503 provider_models_unavailable`，已有模型保留只读展示。只有本地目录与完整管理快照的 Provider 和目录修订一致，且两次读取都成功，才恢复编辑；确认与写入仍重新校验完整资源修订。本地目录不提供可写的管理版本，也不把保存的默认值当作当前会话状态。
- 未编辑字段跟随新快照；未保存的草稿不会因切回页面、其他设置保存或后台刷新而被覆盖。确认成功后仅重置对应设置组；令牌和代理输入仅在对应修改成功后清空，不写入浏览器缓存。
- 预览与确认绑定同一设置版本；重复提交被阻止。离开页面取消前端未完成的请求，但不表示已经提交的服务端写入或后台任务被撤销。
- 管理任务通过鉴权的 `GET /api/v1/management/tasks/events` 接收 SSE 变更通知，通知仅包含变化或心跳，按当前任务所有者隔离；任务列表与运行期间的服务状态不再每 2 秒轮询。连接建立先补查，后续变化合并读取，每次读取完成后至少间隔 2 秒；心跳不触发查询。隐藏页面或离线时断开，恢复后补查；预览确认与写入期间延后读取，保留通知。快照临时失败最多重试 3 次，429 至少冷却 60 秒，通知不可用时提示手动刷新。
- 管理任务进入完成、失败或取消终态时先失效服务状态缓存，设置页读取终态后刷新关联配置和服务状态；调用清理页同步刷新记录。首次读取到的历史终态不会触发重复刷新。通知仅连接 WebUI 进程，不连接或唤醒 App Server；账户快照、请求指标、任务、Relay 与渠道投递通知共用最多 8 个订阅名额。
- 从 Thread/Turn 跳入请求或错误页时，关联范围显示在筛选栏下方，可单独清除；清除 Thread 时同时清除关联 Turn。
- 账户余额按实际返回的数据展示，不因账户不可用标志隐藏 DeepSeek 零余额。手动刷新替换快照后，旧请求的迟到结果不得覆盖新数据。
- 设置确认弹窗在后台刷新时显示“正在刷新…”并禁用确认，仍可取消；实际提交期间禁用确认与取消，避免重复操作。输入草稿不因其他字段的配置版本变化而重建，失焦提交与草稿使用同一去空格值；成功写入后只释放对应设置（Workspace 按身份与字段匹配）的草稿。

请求列表与导出支持 `source=owned|relay` 和 `callerId` 精确筛选。Relay 行展示真实调用方与独立交付状态，Thread/Turn 为空，不参与会话归属；启用全局采集后可关联转储正文。调用方密钥由 `codexc relay` 与模型转发管理页共用管理接口；新秘密仅在成功签发或轮换后显示一次。

Relay 的 `relay.chat` / `relay.responses` 标签分别保存脱敏的原生请求与上游 JSON/SSE，展示对应协议的输入、请求参数、输出和保存报文；客户端交付状态与上游报文单独标识。开关、容量、保留与回滚见[模型 API 转发](user-guide.md#可选模型-api-转发)。无引用无法区分未开启与采集失败，不据此伪造正文；已有引用但文件未落盘、失败或清理时返回明确的定位错误。

Relay 全局调试沿用“调用详情”页面：原请求/响应展示出站与上游报文，调试区域补充客户端入站、客户端交付和实际处理记录。头与正文的省略分别标注，普通头及关联 ID 保留，仅凭据、URL 中的秘密与 CSP nonce 脱敏；统一开关、模式及回退操作见[用户指南](user-guide.md)。

Codex 与 Relay 共用 Gateway 系统设置中的“记录调用详情”和“调用记录模式”。生产/调试分别写入已有裁剪参数 3/65536 与 0/0，不新增模式字段；关闭采集不删除历史记录。



请求列表的转发行直接显示受控失败原因，不再显示复制请求 ID 按钮；调用详情保留已有转储定位复制入口。无转储仍不提供详情入口，提示未关联原因未记录。当前采集状态不用于推断历史未采集原因；已有引用在文件尚未落盘、损坏或被清理时仍由详情接口报告不可用。

Key 编辑按提供商分组勾选多个模型，可跨提供商；思考策略仅在 Key 设置，目录不再有全局启用或思考开关。修改授权或策略时 API Key 保持不变，旧请求取消。删除使用破坏性操作确认，显示用途、调用方和提供商；保存后撤销 Key 并从列表移除，历史指标和转储保留。操作均使用同一预览、修订及一次性确认流程，生效未确认时仍明确提示。

模型目录更新成功使用右下角悬浮通知，约 3 秒自动消失，也可手动关闭；下载失败或保存后审计失败仍在目录区域持续显示。

左侧“模型转发”下的“请求队列”进入独立页面（`#/relay/queue`），展示已鉴权且尚未结束的模型请求：用途、提供商、模型、思考等级、协议、阶段和自接收以来的耗时。阶段区分接收请求、等待名额、准备上游、上游处理及交付响应；按接收顺序展示，不代表按 Key 公平调度的出站顺序。不包括模型列表查询，不保存历史或正文。队列页面使用共享表格组件，支持排序、分页与列显隐；耗时为快照值。通过鉴权 SSE 订阅队列变化，合并事件后读取快照，每次读取完成后至少间隔 2 秒；无变化不查询。隐藏页面时断开订阅并暂停后续自动查询，离开队列页面取消在途查询与订阅；重新进入或恢复连接补查快照。通知断开显示重连状态，并对已连接流的中断补查一次；未恢复连接的失败尝试不持续读取。临时快照失败按 2、4、8 秒最多重试 3 次，429 冷却至少 60 秒，保留手动刷新。HTTP 成功但 Relay 返回 `unknown` 时仍视为未确认读取，不确认通知版本、不清零失败次数，走同一有界重试；`stopped` 和运行中的空队列是有效快照，无变化时不重复查询。查询失败隐藏旧明细；进程停止、状态未确认与运行中空队列分开显示。进程存活但停用、配置无效或尚未监听时显示对应提示，并保留尚未结束的请求。用途名称随每次队列快照更新，不依赖 Key 列表刷新；提供商表示该次请求实际绑定的提供商，正文解析前显示未确定。控制 IPC 为 v6，新增必需的可空思考等级字段，更新后需重启 Relay 和 WebUI，新旧版本不匹配显示未确认。读取接口为同一管理鉴权下的 `GET /api/v1/management/relay/queue`，变化订阅为 `GET /api/v1/management/relay/queue/events`；通知只含变化或心跳，Relay 私有订阅连接与控制命令隔离，账户快照、请求指标、Relay、投递队列与管理任务合计最多 8 个订阅。不触发模型请求或更改管理修订。

Responses 调用详情优先展示非空终态输出；终态 `output` 为空时保留原始事件中已完成的 `response.output_item.done` 条目，适用于 SSE 与 WebSocket。空终态不会再清空已经保存的正文或工具调用。读取时处理已有 V2 转储，无需重新采集；不从不完整增量编造完成输出，原有截断提示仍保留。

Chat 调用详情按消息展示文本、思考和拒绝说明，并展示请求及 JSON/SSE 响应中的函数工具名称、参数和调用 ID；工具结果保留对应的调用 ID。SSE 按 choice 和工具 index 有界拼接，超过展示预算后停止追加，避免把丢失的中间片段与后续参数拼成完整内容。采集或读取正文发生截断时，输出区同步提示不完整。异常内容项保留为 JSON，不因单个空值中断整条详情读取；展示不修改模型请求或历史记录。

输出 trace 因容量不足丢失时，采集端停止追加该次调用的后续输出片段，并在 V2 响应索引追加可选 `traceTruncated` 标记；后续独立调用可继续采集。依赖 trace 提取的输出会提示不完整，已有完整终态输出仍优先展示。读取历史 HTTP trace 时也检查已有分片编号连续性，发现缺口后不再跨缺口重组内容。历史记录不改写；旧记录缺少标记时不能据此确认其 trace 完整，特别是整条 WebSocket 事件丢失时。

API Key 列表增加“最近调用”和“近 24 小时”调用数、未成功数。按调用方与 Key 标识从现有指标库聚合，凭据轮换前后合并，模型失败、未完整完成和未知状态计为未成功；不包含未出站请求，最近调用仅覆盖保留期内已入库记录。数据库不可用显示“暂不可用”，空记录显示“暂无记录”和零次；随页面刷新更新，不影响配置修订及 Key 管理。

API Key 行内提供“编辑”“查看调用”“复制模型 ID”和更多操作按钮。“复制模型 ID”菜单只列出该 Key 已授权的完整调用 ID（含本项目提供商前缀），选择后复制并提示结果；剪贴板不可用时显示可手动复制的文本框，不复制上游原始 ID 或 API Key。轮换并启用、停用、删除收进更多操作菜单；删除单独分组并保留危险操作样式，所有修改继续使用原有预览确认流程。

Key 表单选择关闭思考时，仅展示明确声明支持关闭的模型；打开已有关闭策略的 Key 或切换到关闭策略时，草稿会移除未确认支持关闭的已选项并提示数量，预览确认后才保存。能力不可读取时不允许提交关闭策略；切回跟随客户端恢复完整候选目录，但不会自动重新选中被移除的模型。此筛选不修改其他 Key 或上游目录，也不保证上游实际执行所声明的能力。

API Key 列表使用 Card 分区及 Table，“凭据轮换”独立成列，仅显示当前凭据代次数值（初始为 1，每次轮换递增），不混在用途/身份字段下；用途列只显示名称，未命名时回退调用方 ID，不再额外展示调用方 ID 与 Key ID；列表不展示“允许模型”列，长名称换行，操作按钮在单元格内排列。队列页面使用共享数据表格，支持排序、分页与列显隐，固定刷新工具栏，表格区域滚动；加载、空列表及服务不可用分开显示。请求模型表示本次实际请求的模型，不表示该 Key 的完整允许模型清单。

模型转发页将配置状态、监听状态、并发上限与服务启停操作合并为一张「转发服务」卡片，下方直接展示 API Key 管理。左侧二级菜单「API Key」与「请求队列」分别进入管理页和实时队列页；页面不再常驻队列、调用采集和指标交付的统计卡。采集开关在设置页管理，底层排队、采集和指标交付保持运行。

调用详情列表的“客户端”从已保存的 User-Agent 识别，存在 Relay 调试记录时只使用受支持版本的入站记录，缺失或未知时不回退猜测；无调试记录时使用出站记录；已有转储无需迁移。显示的是客户端自报的产品名，不是已验证身份；明确应用标识优先；浏览器 UA 显示 Chrome、Edge、Firefox、Safari 等名称及可识别的操作系统（如 Chrome / macOS），不据此猜测浏览器扩展；其余客户端从开头的 `产品名/版本` 提取自报名称，例如 `Bob/1.21.0 (...) Alamofire/5.6.2` 显示 Bob，无需逐个注册应用；也支持 `产品名/v1.2`、`产品名 v1.2`、`产品名 1.2`，名称可包含最多四个单词且总长不超过 64 字符。只有库名时显示库的自报名称，不推断背后的应用；不完整的浏览器兼容前缀、无版本的未知值（如 `node`）或非法值显示“—”。原始 User-Agent 可在调用详情请求头中核对。

调用详情列表的“协议”按该条记录的实际接口显示 Chat 或 Responses，与提供商支持能力及 JSON/SSE 无关；HTTP 请求路径和 WebSocket Responses URL 均可识别，模型列表或无法确认的接口显示“—”。历史转储按已有路径读取，无需迁移或重采。

### OpenAI 重置券使用

OpenAI 账户卡片提供“使用重置券”：实时读取当前 ChatGPT 账户可用券，按到期时间排序，选择后预览官方名称、说明和到期时间，再确认消费。仅支持官方明确可用的 `codexRateLimits` 券；明细缺失或未知类型不允许盲选。API Key 账户不支持。

操作沿用 WebUI 管理接口的监听模式、Origin、令牌与限速要求。WebUI 通过 Gateway 私有账户 IPC v2 调用 App Server，不读取凭据或直接操作数据库；升级后须同步重启 Gateway 和 WebUI，旧 IPC 版本明确拒绝。确认令牌绑定管理会话与 Gateway 内的随机操作 ID；Gateway 保存至多 128 个、5 分钟过期的预览，执行前复核账户、券说明、状态和到期时间，同一时间只允许一个消费操作。并发忙碌拒绝也使对应预览失效；管理确认已接受、但审计检查等前置步骤失败时，会尝试释放该预览，不发起消费。重启使未执行预览失效，不恢复消费。

成功、无需重置、券不可用、该次操作此前成功分别展示。消费 RPC 使用显式券 ID 与一次性操作 ID 作为幂等键，不自动重试。连接中断、超时、无受控错误码的 HTTP 错误（包括 502/504）均显示结果待确认，需刷新核对，不直接重复消费；查询、取消和预览不消费券。取消预览或关闭预览对话框会释放 Gateway 预览和管理确认令牌；清理请求失败会显示错误，残留记录由 5 分钟有效期兜底。已确认结果不因随后额度刷新或完成审计失败改为消费失败。操作后的余额、重置券和当前周额度快照由 Gateway 单写者刷新，手动刷新可重试额度查询。卡片的周额度百分比与重置日期取自官方账户快照的普通用量桶，不依赖新的模型请求；没有官方周窗口时显示未获取，不回填历史请求中的旧窗口。历史用量估算仍使用请求记录。

管理 API：`GET /api/v1/management/accounts/openai/reset-credits`，`POST .../preview` 接受唯一 `creditId`，`POST .../consume` 与 `POST .../cancel` 接受 `attemptId` 和 `confirmationToken`。券明细与确认上下文仅短期驻留，不增加数据库字段。审计只保留操作指纹及受控结果，不记录凭据或官方原始响应。


### 独立请求诊断

普通代理和 Relay 的请求指标独立采集上游明确返回的诊断摘要，无需开启调用采集。
请求列表在模型旁展示实际上游提供商；提供商尝试次数大于 1 时显示次数提示，不将它解释为切换次数。
请求详情还显示模型尝试次数、Chat `finishReason`、HTTP/流式错误阶段，以及 CLP 已识别错误包装中的
内层错误码、类型和 HTTP 状态。内层状态不覆盖本次请求的 HTTP 状态，也不触发自动重试。
Chat JSON（含 CLP 成功包装）和 SSE 使用相同口径；Responses 未返回 Chat 路由或结束原因时保持为空。
历史记录、缺失或无效字段显示为空，不从模型名、候选提供商或转储文件推断。完整诊断、标识、费用和报文仍留在可选调用转储中。
这些字段同时进入请求 JSON/CSV 导出；不增加聚合筛选或排序维度。
