# 配置与生命周期统一改造计划

## 结论

项目用户配置继续使用 TOML，不迁移为 JSON。

- `~/.codex-connect/config.toml`：Gateway、渠道、WebUI、数据中心和本机指标配置。
- `~/.codex/config.toml`：Codex 官方用户配置、模型、Provider、Profile 和会话默认值。
- JSON：仅用于 `--json` 机器输出、内部状态快照、备份清单和协议数据，不作为第三套用户配置格式。

JSON 不会解决当前的重复入口、令牌边界、设备标识或重启逻辑问题；引入双格式还会增加迁移、回滚、文档和测试成本。

## 改造目标

1. Setup、Config、Doctor 和独立 CLI 对同一配置使用同一 Schema、同一文案和同一状态结果。
2. 配置写入、激活、服务健康确认三个阶段明确分离，用户能区分“已保存”“已生效”“服务已就绪”。
3. 重载、重启、重装和未运行状态统一，不因维护命令把原本未运行的服务隐式启动。
4. 数据中心统一 Provider、账户、额度窗口、设备 ID、设备名称、周期起止时间等统计维度。
5. 文本输出与 JSON 输出由同一结构化结果生成；JSON 只作为稳定自动化接口。

## 分阶段实施

### 第一批：配置结果与文案收敛

- 保留 TOML 路径和格式，不新增 JSON 配置入口。
- 定义统一激活结果：`none`、`reload`、`restart`、`reinstall-required`、`failed`。
- Setup、Config、Provider、WebUI、Center 使用同一结果文案：配置已保存、配置已生效、服务已就绪或需要执行的明确命令。
- 明确未运行服务修改配置时只保存，不隐式启动；下次显式启动时生效。

验收：交互菜单、脚本调用和 `--json` 对同一变更返回一致的激活状态；不泄露令牌。

### 第二批：生命周期统一

- 抽出服务状态、健康确认和原状态恢复的最小生命周期边界。
- `metrics prune/cleanup` 默认恢复服务原状态；显式要求重启时才执行重启。
- 修正 macOS reload、Linux uninstall 和安装/重启失败的部分状态。
- WebUI 和 Center 启动增加有界健康确认。

验收：停止状态执行维护后仍保持停止；启动状态执行维护后恢复原状态；文本和 JSON 健康字段一致。

### 第三批：数据中心维度统一

- `device_id` 只自动生成且不可由用户输入。
- `device_name` 为空时使用系统名；显示名称和上报名称只保留一个来源。
- Provider、账号、额度窗口和重置周期使用规范化字段，避免同一渠道生成重复卡片。
- 周期时间使用真实重置时间，使用量继续来自本地观测数据，并显示周期起止和周期长度。

验收：多设备、多渠道、多窗口不会因别名或显示名产生重复记录；OpenAI 与第三方额度口径不混淆。

### 第四批：WebUI 与错误记录

- 错误记录按最新时间倒序展示，每条记录保留可操作的中文/英文消息、错误类型和上下文摘要。
- 图表 tooltip、图例和日总计使用同一数据 DTO，避免符号、间距和系列互斥不一致。
- 热力图和趋势图使用统一容器尺寸与响应式布局。

验收：默认显示日总计，同时可查看缓存输入、非缓存输入、输出和推理输出；错误详情可追溯到具体记录。

## 约束与回滚

- 不改变现有公开命令名称，不增加隐式别名。
- 不自动迁移旧配置格式；不支持的输入明确失败。
- 每批只修改对应模块，先跑定向测试，再运行文档和索引检查。
- 配置写入保留现有原子写入、修订冲突检测和备份；任何激活失败不得回滚已经成功保存的配置，但必须明确当前生效状态和恢复命令。

## 当前执行顺序

先完成第一批的统一结果和文案边界，再处理服务生命周期，最后处理数据中心和 WebUI。配置格式保持不变，避免把格式迁移误当作交互和生命周期修复。

## 本轮进度

- 第一批配置结果已完成基础收敛：配置写入器现在同时返回兼容的内部激活范围和统一的状态、目标、命令列表；Config/指标菜单、数据中心菜单和 Setup 顶层返回已复用该结果，飞书、Telegram、微信 Setup 也保留并返回同一激活信息；DeepSeek、OpenCode Go、模型默认值、Codex 用户设置和官方登录的重启提示已改为复用统一文案，不再自行拼接 `restart-*` 命令。自定义主 Provider 的备份错误分支仍保留上下文专用提示。
- 第二批已补齐独立服务的有界健康确认；配置菜单在注入自动重启回调时返回 `activationState: applied`，未注入回调时返回 `pending`，自动重启失败仍保留已保存配置并抛出可操作错误。服务安装在写入定义后激活/就绪失败时会尝试恢复旧定义和核心运行态，恢复失败会明确要求人工处理；跨平台部分失败结果仍待生命周期执行器统一。
- 数据中心与 WebUI 本轮完成现状复核而非协议改造：设备 ID、设备名称、额度窗口、错误记录和图表已有实现与测试覆盖；WebUI 中心每日统计测试已改为相对时间，避免固定日期边界误报。若进一步调整统计维度，必须单独设计 Schema 版本和迁移方案；历史数据迁移仍未执行。
