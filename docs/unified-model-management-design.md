## 当前链路与后续统一方案

本节按提供商共用模型目录的当前实现更新。下方第一版运行观察是历史证据，不代表本次共享事务、迁移或跨平台行为均已验证。

| 边界 | 已实现 | 尚缺的统一能力 |
| --- | --- | --- |
| 目录身份 | DS、CLP、CCG、OCG 按提供商家族共用模型目录；自定义模型按各自 cp-ID 保存 | 使用官方共享目录的第三方仍不能按接入裁剪 |
| DS 模板更新 | CLI／WebUI 按精确模型 ID 预览提示词／能力差异，保留本地窗口与默认等级 | 不自动修改账户目录 |
| 自定义模板更新 | 固定 OpenAI 底座或 DS 专用来源；无关联模型明确选择来源并保存 `template.source/model` | 不读取实时官方目录，不按名称猜测，不自动继承源窗口；底座更新不自动应用到已有模型 |
| CLP 更新 | 联网发现只添加；统一模板更新使用同一 Cline 候选快照；Flash 保留仓库 DS 复合模板 | 消失的候选须单独本地移除，不把候选声明视为实测能力 |
| CCG／OCG 更新 | 新增导入记录显式 ID 映射；已有模型按 manifest 关联预览更新 | 旧目录无关联须手动选择，手填模型不自动生造来源 |
| 保存与恢复 | 自定义使用目录 pending；受管移除、上下文、模板更新及 CCG／OCG 添加导入复用提供商共用目录事务 | 初始账户配置仍属于账户事务，不据此宣称所有事务完全相同 |
| WebUI | 表格、详情、上下文、移除、CP 编辑、模板来源选择及差异确认 | 候选失效须重新读取，不静默重新下载后执行 |

本轮先修正会破坏后续统一的现有行为：CCG／OCG 添加导入改用持久恢复记录；无内容变化不覆盖备份；源目录不再支持已保存思考等级时拒绝刷新，不静默替换非默认模型；WebUI 提供商编辑与模型编辑都绑定打开时的读取修订，防止旧连接表单回写旧模板。

统一更新遵循以下合同：

1. **明确逐模型来源。** CP 沿用已保存关联，DS 新建时记录官方精确 ID。CLP 记录 Cline 候选与项目提示模板的不同来源；CCG／OCG 导入时记录源模型与已定义 ID 映射，手填模型必须显式关联后才能模板更新。现有目录缺少证据时不按名字自动补关联。
2. **分离发现和更新。** 获取远端目录用于展示新增候选；更新已有模型通过同一计划接口，受管模型分别选择提示词和能力，自定义模型仅更新提示词及来源。自定义上下文、思考、图片等能力完全由用户设置。未选择的模型与字段保持原值，默认、工具、采样、压缩和当前窗口不因刷新联动变化。来源缺失、等级或窗口冲突都在预览阶段报错。
3. **统一可确认计划。** 精确绑定 Provider ID、模型、来源摘要、选择范围及账户文件修订。网络来源在一次计划内使用同一已校验候选；执行时复核本地修订，不重新下载并悄悄采用另一份内容。源内容变化需要重新生成计划，不能用名称或下载时间代替内容身份。
4. **接入现有 WebUI 管理链。** 在 `/provider-settings` 中增加独立模板操作，复用认证、Origin、限速、管理锁、审计、一次性确认和保存后回读。预览须显式定义来源、模型对象及字段差异投影；字段缺失使用稳定的存在标记，与 JSON `null` 区分，避免 `undefined` 进入确认指纹。不得直接透传 CLI 预览或新增无保护写入口。
5. **验证所有消费路径。** CLI 和 WebUI 产生同样的计划与结果；保存目录继续供 App Server、聚合和 Relay 读取。分别观察冲突拒绝、取消、无差异、家族隔离、共享设置及恢复和重启后的消费，不把保存成功或静态检查等同于上游模型能力验证。

来源关联保存在受管 manifest 的 `modelTemplates`，最近一次更新摘要与范围保存在 `templateUpdates`，保留当前 catalog Schema。显式关联或更新前备份 catalog 与 manifest，并纳入同一恢复记录。旧目录不自动迁移；回滚须核对后续修订，不能覆盖之后的修改。移除模型同步剪裁该模型的两项来源记录。CLP 的 `cline` 关联指经项目投影的模板，Flash 的 DS 基础来源仍由顶层 `source/model` 说明。

读取也有待分清：模型详情 GET 已按模型与修订读取提示词，但 Provider 设置 GET 为支持完整 CP 编辑仍携带完整定义（含提示词、采样）。后续若要求列表不携带正文，应同时增加版本化编辑详情读取；不能只裁掉列表字段而让保存丢失数据。

此前 Linux 隔离观察覆盖 CCG／OCG 四文件恢复、后续修改拒绝、无变化保留备份，以及 WebUI 自定义表单过期修订拒绝。原 CLP 全量重建的观察仅适用于该历史实现，不能代替现行发现／更新流程的证据。当前统一链路观察在交付说明中报告；不据此宣称 Windows/macOS 服务与云端模型能力已验证。

## 第一版目标与范围

统一入口和可复用流程，解决模型管理分散、托管模型在 WebUI 缺少移除入口的问题。
保留现有目录格式、账户和凭据机制，不重做整套模型生命周期。

不新增模型数据库、选择记录、禁用名单或目录版本，不引入跨数据库事务、
自动引用迁移、Relay 空授权或自动模型替换。不支持的操作显示原因，不用统一按钮掩盖差异。

| 类型 | 第一版能力 | 影响与限制 |
| --- | --- | --- |
| 自定义模型目录的 Responses/Chat 接入 | 集中已有添加、编辑、默认选择和移除能力 | 当前提供商；Relay 共用目录时也受影响 |
| CCG、OCG | 接入已有模型选择、手动添加和模板导入；WebUI 增加本地移除 | 同族账户、聚合及使用该目录的 Relay；不新增任意能力编辑器 |
| CLP Codex | 统一列表和默认选择，增加不联网的本地移除，保留显式联网更新 | 所有 CLP 账户的共用 Codex 目录与聚合；独立 Relay 目录不变 |
| DeepSeek | 展示现有模型和已有设置入口，CLI 支持模板对比更新 | 暂不开放单模型移除；同家族共用模型窗口，不跨提供商跟随 |
| 使用官方共享目录的第三方接入 | 展示目录和已有默认设置 | 暂不提供单接入裁剪，不修改共享官方源文件 |
| CLP Relay | 保留独立目录查看、更新和 Key 管理 | 本次不新增模型删除或选择策略 |

官方 OpenAI 登录态接入不在本次范围。连接和账户继续使用既有接入入口；
配置完成后从模型管理入口操作。模型移除不要求重填 Key、不删除账户、不改变地址或协议。
上下文按提供商和单模型保存，同族账户读取同一份值；不复制广播到多份目录，不跨家族修改。

## 入口与身份

WebUI 保留提供商接入、账户与凭据、模型管理的职责划分。
模型列表展示精确 ID、提供商或共享账户组、默认使用情况及允许的操作。
受管目录按提供商呈现；从任一 CLP 账户进入操作的是同一份 CLP 模型目录。账户身份仅用于连接、默认模型选择和凭据，不增加模型目录层级。

操作以精确提供商或受支持共享组加模型 ID 定位，由后端解析已有路径。
不接受客户端路径，不使用显示名定位；聚合 slug 和 Relay 公共 ID 通过既有规则映射，
不能直接作为目录删除键。独立目录不因模型同名联动删除。

第一版不建立源目录、策略目录、有效目录三层存储。现有保存目录就是启用集合；
需要额外策略才能隔离的官方共享目录和 CLP Relay 删除不在本次范围。

## 统一操作流程

选择操作 → 预览 → 确认 → 锁内复核 → 备份与保存 → 回读和生效提示。

1. 读取当前目录和相关账户，返回真实支持的操作；不支持的操作解释原因。
2. 预览列出模型变化、共享账户、默认冲突、Relay 联动、备份与生效要求。
   本地移除不联网、不探测模型、不要求新凭据。
3. 复用[管理接口安全](management-interface-security.md)中的认证、Origin、
   会话绑定确认令牌、修订和审计合同。输入或相关状态变化后重新预览。
   WebUI 模型编辑携带打开编辑器时的资源修订，首次预览也拒绝覆盖外部变更；CLI 在编辑结束后复核原目录。
   模型操作审计使用提供商与完整模型 ID 的有界指纹，兼容合法的长模型 ID。
4. 使用现有 Provider 管理锁，复核目录、账户、Profile、来源文件及相关默认设置。
   必需文件缺失、损坏或修订变化时拒绝；不能只比较页面可见字段。
5. 只修改目标目录及必要来源信息，保留连接、凭据、其他模型参数和账户默认值。
   回读确认保存结果；断连或回读失败不自动重试写入。

管理编排保留在 scripts，解析与文件访问使用 runtime。CLI/WebUI 共用变更计划与应用函数，
不将没有预览修订合同的交互式 callback 直接作为 WebUI API。
Application/Core 不读取管理文件路径，不引入通用插件框架。

## 移除规则与已知影响

| 情况 | 第一版行为 |
| --- | --- |
| 当前账户默认模型 | 阻止移除，先改默认值 |
| 最后一个启用模型 | 阻止移除，沿用非空 Codex 目录合同；整体移除走账户或提供商入口 |
| 读取到 Gateway 显式默认引用 | 拒绝本次移除，按实际提供商解析，不按裸模型名跨目录阻断 |
| 旧会话或计划任务 | 保留记录，提示可能无法继续执行；沿用使用时检查，不做全局引用事务 |
| Relay Key 授权 | 不自动清空；共用目录移除后调用受目录限制，恢复模型可能重新满足旧授权，确认页必须提示 |
| 显示分组、指标、转储 | 不删除或迁移，不清理其他提供商的同名数据 |
| 上下文与模板 | 不扩大局部编辑范围，不删除 DS 源模板；账户之间不自动跟随 |

Provider 锁不协调全部 Gateway 配置、任务存储或外部手工修改。
第一版保护提交时可复核的状态，不承诺之后不会出现新的失效任务或配置引用；
调用仍按原有检查报错，不静默换模型。不将“未做全局扫描”展示为“没有引用”，
也不把必需目录或默认配置读取失败当作无引用。

保留 Relay 授权是明确取舍，避免引入空授权 Schema 或强制销毁 Key。
永久撤销访问应通过既有 Key 管理修改授权或撤销 Key，模型移除不是凭据撤销。
CLP Codex 移除不影响其独立 Relay 目录，该模型仍可能通过 CLP Relay 调用，预览必须写明。

## 保存、更新与重新添加

- 自定义目录：移除精确目标定义并按原生成器编译，保留默认值和其他模型能力。
  添加、编辑复用现有能力与探测约束，不通过移除重写整个连接配置。
- CCG/OCG：复用账户检查、默认保护、合法 ID/能力校验、Codex 目录校验和备份。
  手动添加与模板导入继续显式选择，不在本地移除中刷新模板。
- CLP：裁剪提供商共用目录，保护所有 CLP 账户的默认模型，保留剩余能力和来源提交信息。
  目录与 manifest 一致，核对 Flash 移除后的 DS 模板来源标记；
  `cline.commit` 与数字时间戳 `cline.downloadedAt` 复用现有 CLP 来源 Schema 校验，不把时间戳改成字符串或迁移既有文件；来源不一致使用独立错误码，界面提示核对共享目录来源。
  不套用 CCG 的 `user-configured` manifest 而丢失 CLP 来源语义，按现有格式调整必要字段。
- 列表继续从保存目录派生，聚合文件可重建，不另存一份可写模型清单。

移除不是可随时一键撤销的停用。自定义模型从备份或重新填写定义恢复；
CLP 通过显式更新和选择重新导入，CCG/OCG 通过已有导入或添加入口恢复。
不建立回收站，不承诺后续编辑后仍保存所有被删定义。

联网更新以当前启用集合为初始选择，新增或曾移除项须明确选择才加入；
程序升级和重启不自行补齐目录。现有更新入口若不满足，应在实现范围修正，
不新增禁用数据库补偿；恢复不能凭空推断已缺失的自定义能力。

## 生效、备份与恢复

保留 HTTP、Responses WS、Chat 桥和聚合下游已有目录复核，旧 ID 请求返回受控错误。
实现需观察实际调用，不能仅凭列表消失证明生效，也不承诺撤销已完成准入的全部在途请求。
目录展示和 App Server 能力刷新沿用原生命周期，分别报告“已保存”和“需要重启”，
保存不自动重启或终止共享 App Server。

共用目录的 Relay 会读取变更材料，当前修订变化可能撤销整个提供商旧租约，见
[材料发布](../runtime/model-relay-service.mjs)与[准入撤销](../src/model-relay/admission.ts)。
第一版如实提示，不增加按模型取消机制。

复用现有私有文件、备份、快照检查和适用的 pending/恢复机制，不改磁盘 Schema，
不新增初始化或迁移。现有多文件恢复不等于崩溃原子事务。
实施时核对新增 CLP 本地路径各写入点与回滚，失败保留原文件或恢复依据，结果不确定停止后续操作。
恢复前检查修订，不用整份旧目录盲目覆盖后续修改；缺少必要保护时局部补齐或暂不开放操作，
不扩展为全局事务系统。不清理历史备份和凭据，也不新增旧版本兼容承诺。

## 实施与验收

1. 整理目录能力和共享范围，补齐可预览、可复核的变更计划。
2. 复用自定义、CCG/OCG 保存能力，补充 CLP 本地移除和现有默认保护。
3. CLI/WebUI 接入同一流程，清理重复实现；保留账户隔离及不支持来源的明确边界。
4. 核对更新、实际出站、聚合、Relay、回读和恢复，再更新用户文档及模块索引。

实施使用真实操作与异常输入观察，不新增或修改测试文件、guard 或变相验证脚本：

- 两入口预览一致；默认模型、最后一个模型、错误 ID、过期预览和损坏目录拒绝且文件不变。
- 共享账户与同名独立模型的影响正确，本地移除不依赖上游网络、不改变凭据。
- CLP Flash 与其他模型移除后 manifest 一致，独立 Relay 目录保持原语义。
- 重新打开、重启、显式更新不意外加回模型，重新加入需明确选择。
- HTTP、WS、Chat 桥、固定/切换、聚合及共用目录的 Relay 执行原有拒绝规则。
- 旧会话和任务不自动换模型，Relay 保留授权及重新加入后的行为符合提示。

## 统一能力展示

WebUI 第三方目录与 OpenAI 共用一张表、一个表头和横向滚动容器，提供商以表内分组行区分，并复用能力列和详情分组。模型名称单行展示，不显示默认模型标签，共享账户范围和默认模型移除保护保留；输入类型、当前与最大上下文、上下文比例、思考等级、加速等级、审批声明和工具来自对应保存目录。仅模型名称列固定为 18rem，其他列自动布局，名称较长时省略显示。工具标签统一为「搜索」「编辑」，声明状态和类型通过悬浮提示展示；刷新与目录编辑入口保留在所属提供商标题中。
“上下文比例”表示 `effective_context_window_percent`，不使用全局窗口设置的 `windowPercent`。缺失能力显示未声明；目录声明不等于实际调用已启用或上游验证支持。

托管目录读取原始模型字段，自定义目录读取经过定义一致性校验的生成模型，并从同一快照的 definitions 投影思考、图片、文件编辑、工具搜索的声明状态，避免把未知能力的保守执行值显示成明确不支持。第三方官方共享目录仍读取 `providers/custom/official-models.json`。不借用 OpenAI 登录缓存，也不改变来源更新行为。
提示词通过独立管理 GET 按目录身份、精确模型 ID 和修订读取，使用共用白名单、数量上限及纯文本展示；目录变化后旧修订被拒绝。自定义模板关联和采样配置随该详情返回。

当前展示基于提供商共用目录；默认保护、本地移除、独立 CLP Relay 与原有生效要求继续保留。五类提供商的模板更新入口复用统一计划，能力声明仍不代表上游实测支持。

自定义模型新增由 CLI 与 WebUI 共用模板草稿生成：默认固定 OpenAI 底座，也可选择 DS 专用模板，随后填写平台 ID、名称、当前上下文并确认四项能力。模板能力仅作为建议，未知可保存且暂不启用；高级参数按需展开。新增不会覆盖已有模型，切换模板只影响下一次新增；已有模型更新继续使用明确来源、范围选择、差异预览和确认保存。编辑修订在规划前检查、预览后再次复核，避免并发追加模型被误报为普通输入错误。

早期共享目录版本的 Linux 隔离观察：两个自定义提供商的同名模型分别展示 272000 与 372000 Token、有效上下文比例均为 95%；当时两个 CCG 账户只展示一份目录，官方共享目录与 OpenAI 缓存均可展示 CLI 内置模型能力。浏览器已观察详情默认折叠、提示词纯文本、旧修订提示重新读取，以及 390px 页面内的表格横向滚动。旧修订和跨提供商复用修订返回 409，未知模型或额外参数返回 400，跨站请求返回 403，目录 pending 时提示词请求返回 503。未调用第三方上游，也未观察当时展示改动下的 CLP/DeepSeek/OCG 实际账户及 Windows/macOS 行为。
统一表格后，浏览器已观察同一表头下的 OpenAI 与两个自定义提供商分组、长名称省略及上下文编辑预设；OpenAI 缓存缺失时第三方分组仍展示。隔离目录中的本地移除已通过页面预览、确认写入和接口回读，目标提供商删除指定模型，另一提供商的同名模型保留。
