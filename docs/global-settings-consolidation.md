# 全局设置归纳实施记录

## 目标与边界

将 Codex 用户级低频配置集中管理，提供商和模型页面保留自身配置、来源提示与直达入口。用户级存储值、提供商启动覆盖、项目配置及已有会话实际值不得混为“全局已生效”。Gateway 配置仍独立保存。

本次不改变用户文件格式，不迁移或复制用户数据，不自动清除账户覆盖，不改变提供商启动参数、渠道 `/fast` 或 Hook 的既有作用范围。MCP 创建删除、子代理规则和 Hook 信任保留各自事务及授权流程。聚合入口目前关闭，不作为可用能力。

## 分步流程

每步遵循：确认关联合同 → 实现 → 隔离观察与失败挑战 → Astra 子代理关联审查 → 修复并核对 → 提交。提交检查是静态工作流证据，不替代实际观察。不新增或维护测试。

| 步骤 | 范围 | 完成条件 | 状态 |
| --- | --- | --- | --- |
| 1 | 用户配置读取、部分偏好编辑、写后核对、覆盖状态和确认范围 | CLI/WebUI 共享结果；普通偏好不依赖 OpenAI 模型；失败不冒充已确认 | 已提交 `e0a48694` |
| 2 | 全局设置页面、分组操作、导航与关联入口 | 模型和提供商直达相应全局分组；低频表单不重复平铺；保留取消、回读和草稿保护 | 已实现并经 Astra 审查修复；随本步提交 |
| 3 | 跨入口与文档收尾 | 核对 CLI、渠道、提供商和会话边界；完成浏览器路径、失败观察及全链路审查 | 待处理 |

## 配置归属

| 资源 | 字段或功能 | 处理原则 |
| --- | --- | --- |
| Codex 用户配置 | model、model_reasoning_effort、service_tier | 主配置默认值；不能覆盖账户选择或冒充会话实际值 |
| Codex 用户配置 | model_context_window、model_auto_compact_token_limit | 精确 Token 覆盖；比例仅为输入换算；保持模式约束 |
| Codex 用户配置 | web_search、tools.update_plan、tui.auto_recap、普通偏好 | 各自保存与继承合同；不因无关模型目录失败整体不可用 |
| Codex 用户配置 | 权限、审批、电脑、浏览器、已有 MCP 策略 | 保留组织策略、预览确认和相关合并配置核对 |
| 账户 Profile、模型目录 | 默认模型、搜索覆盖、模型窗口、能力与提示词 | 不复制全局值；按账户或共享目录范围编辑 |
| Gateway 配置 | 渠道默认模型、统计分组、工作区、服务与展示 | 独立入口和生效提示，不并入 Codex 文件 |
| 特殊资源 | MCP 创建删除、AGENTS.md 与子代理预设、hooks.state | 提供相关入口说明，保留独立操作边界 |

## 约束与审查基线

- 受管固定与普通自定义固定并非同一配置合同，不能按“第三方”统一开放全部主配置字段。
- 独立提供商通过启动参数覆盖部分字段；未覆盖部分仍参与原生配置归并。
- 当前配置 API 读取用户层，工具域另有合并投影；此投影不代表指定工作区或已有会话的实际值。
- 渠道 `/fast` 与选择 OpenAI 模型会修改主配置 service_tier；Hook 状态也属于共享用户配置，并有独立刷新协调。
- 保存结果、回读一致性、覆盖状态与新会话/新 TUI 生效需要分别表示；不自动重试未知写入。
- 上游版本保护不等于跨进程全局串行化，原生并发编辑仍可能产生竞争。

## 证据与进度

初始审查覆盖 WebUI、CLI、用户配置客户端、提供商启动和固定上游消费链。基线为 `a144cb27`；锁定上游为 `83086188ae0614bd882818ff1aa23f3194962012`。未读取真实凭据或修改服务。本节随每步审查、观察和提交更新，不以计划内容代替完成事实。

### 步骤 1：共享保存合同

已实现部分偏好编辑、缺省和不支持状态区分、可选能力降级、原生写状态投影、同连接回读，以及工具合并来源指纹。CLI 与 WebUI 共用结果，未知写入不自动重试。工具指纹包含插件默认启用策略，但无法证明配置 API 之外的插件清单或安装状态；上游也不提供合并来源到写入之间的原子锁。

隔离 Codex CLI 0.163.0 的实际观察：单字段保存及清除覆盖返回 `confirmed/ok`，其他偏好不变；同值返回 `unchanged` 且无需激活；旧用户修订拒绝；带点 MCP 标识正确回读；命令行覆盖返回 `okOverridden`；用户修订不变而工具合并来源变化时拒绝旧指纹。写响应后关闭自有客户端，返回 `updated/unknown`，独立重读仍看到已保存值。真实终端完成工具选项、预览、确认和保存。未调用模型或操作真实用户配置。

浏览器使用实际前端和隔离 API 响应观察：第三方模式仍能修改历史保存；请求仅包含 `kind=preferences` 与 `historyPersistence=none`；确认框只展示这一字段；模拟未知保存结果后显示未确认提示，只发出一次 PATCH 并刷新读取。此观察证明前端交互，不代表真实 HTTP 后端链路已验证。浏览器观察同时发现并修正旧的整组保存文案。

Astra 独立审查已指出加速能力失败提示、覆盖状态激活文案、不支持值确认投影、插件默认策略指纹四处关联遗漏；均在本阶段修复。插件默认策略变化的内存隔离挑战实际输出 `default-policy-change-detected true`、`old-confirmation stale-revision`。根类型检查、构建及文档检查通过；前端构建已通过，最终提交仍需执行仓库 Hook。真实 Thread/TUI 消费及模型目录、加速查询故障分支尚未运行观察。

阶段 1 提交 `e0a48694` 的 Hook 已通过根类型、版本和边界检查、变更 Lint、文档索引、WebUI 构建与 Lint、中英文键及占位符检查、Gateway 构建。后续跨入口核对发现 CLI 普通偏好目前仅有官方整组入口；第三步将补单字段入口，使第三方模式和恢复继承也有直接可操作入口。

补充观察：真实隔离 App Server 读取用户配置，同时在客户端注入模型目录及加速能力查询失败，实际返回 `modelsAvailable=false`、`accelerationAvailable=false`、`defaultsEditable=false`、`contextEditable=true`，历史保存与 12 个工具策略仍可读取。该观察覆盖局部能力降级，不声称上游原生故障已复现。

### 步骤 2：集中入口

新入口为 `#/settings/global`，通过 `section` 直达五个分组；模型目录、账户默认和 Gateway 配置保持原有归属。MCP 创建删除与子代理预设使用 `codexc config`，Hook 信任使用本地 Codex `/hooks`，不合并为一个保存事务。

实际前端配合隔离 API 的浏览器观察：行为与偏好深链打开对应弹窗和面包屑；八个选择器宽度均等于父列宽度；390px 窄屏无横向溢出，中文字体正常。上下文选择 128K 与 80% 得到 `131072/104857`；关闭询问丢弃，继续编辑保留输入，丢弃后返回分组列表且焦点回到对应“操作”。无效分组明确报错，不打开其他编辑器。截图位于任务证据目录 `output/playwright/global-settings/`，不提交浏览器产物。跨页面草稿阻止及最终整合仍待核对。

第二次 Astra 审查发现并修复：模型编辑器仍使用目录推导值初始化草稿、Data Router 默认错误页可能显示未知异常及堆栈，以及模块文档的旧入口描述。主代理复核并观察：目录有默认模型但用户未保存时，编辑器显示“未设置”且不自动提交；注入非法时钟导致布局失败后，只显示受控恢复提示和返回/重载操作，恢复响应后页面可重新加载。

路由入口使用现有依赖的 Data Router，以原生阻挡支持草稿保护；仍在查询令牌清理后创建路由，保留原页面懒加载及局部错误边界。模型页真实链接进入上下文，编辑后浏览器后退被阻止，继续编辑保留 `131072`，明确丢弃才返回模型页。手动修改 hash 形成的非路由历史不具备同样阻挡保证，不把这类路径列为已验证。最终全链路审查及真实 HTTP 联调边界在第三步收尾。
