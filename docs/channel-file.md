# 渠道普通文件发送

`codexc channel send-file` 将显式选择的本地文件交给 Gateway，通过已有 Thread 绑定发送。当前仅支持 QQ，源码已接线，尚未部署或客户端验收。

```bash
codexc channel send-file /absolute/path/report.pdf --thread <Thread ID>
codexc channel send-file --help
```

不指定 `--thread` 时，所有前后台绑定中必须只有一个目标，且为 QQ；不会从多个绑定中自动挑选 QQ。参数检查在读取配置前完成，重复选择、未知参数和相对路径拒绝。

- 文件须为非符号链接的普通文件，大小 1 至 5,000,000 字节。读取前后复核文件身份、长度和修改时间，变化时拒绝。
- 文件名最多 255 UTF-8 字节，保留中文及正常 emoji，拒绝路径分隔符、控制/格式控制字符和全空白名称。原名作为平台附件名称，不参与私有暂存路径。
- 命令不启动任务、不扫描模型回复中的路径、不压缩或执行文件。复制成功只表示请求已入队，不代表平台或客户端已经收到。

## 领取与结果

请求存入状态数据库所在目录的 `channel-file-outbox/pending/`。Gateway 配置和状态库 Schema 须有效；不兼容时拒绝，不修改数据库。

文件先有界读取并复制为随机 `.bin`，再原子发布同编号 version 1 manifest。Unix 目录/文件为 `0700/0600`，Windows 使用当前用户私有 ACL。Gateway 只消费同目录同编号普通文件，按原 Thread 绑定定位活动 QQ 渠道，发送时复核授权。

发送前将 manifest 领取为 `.sending`。只有平台返回合法消息 ID，完整发送获得确认后才将副本及 manifest 归档至 `done/`。失败或结果未知保留在 `failed/`，附受控原因；重启遗留 `.sending` 仅归档，不自动重发。人工决定重新提交前须先核对是否已收到，避免重复。

QQ 发送使用主动额度，与其他消息共用账号、收件人限速和顺序。平台确认不代替客户端下载确认；额度、权限或网络失败不会自动改成其他消息模式。

## 数据与回滚

本功能不修改 StateStore 或现有图片 `channel-outbox` manifest，不迁移或删除旧图片请求。新的文件目录独立保留，`done/failed/` 不自动清理。

回滚源码后新文件目录保留待人工核对，不重新解释为图片，不覆盖旧记录。已经领取的发送可能发生外部效果，取消或回滚不能撤回。备份和清理时按现有 Gateway 数据目录管理方式处理，勿在运行中移动待发送记录。

本机图片仍使用 [`send-image`](channel-image.md)，任务长正文转文本文件继续由渠道现有结果策略处理；它们与显式任意文件选择的用途不同。
