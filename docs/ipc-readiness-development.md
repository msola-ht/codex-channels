基线为 `c518eff4`。本记录维护本轮计划、关联审查和观察证据，不把待实施内容视为已支持功能。

## 实施与证据

观察日期为 2026-10-20，针对基线上的本轮未提交工作树。隔离数据同时指定 `CODEX_HOME`、`CODEX_CONNECT_HOME` 与 `CODEX_CONNECT_CONFIG_FILE`，未使用真实账户或重启既有服务。当前合同见 [WebUI](webui.md)、[Runtime](../runtime/README.md#私有-ipc-请求边界)、[Bootstrap](../src/bootstrap/README.md)。

### P1：本地展示与可写快照

新增鉴权管理 GET `/provider-model-catalogs`，直接复用原有本地投影；与完整管理读取处于同一进程，保留同一个目录修订密钥。完整 `/provider-settings` 预览、确认、写入及写后回读不使用本地目录替代资源版本。前端保留原管理组件及草稿，通过 Provider／目录修订一致性控制修改入口。

真实 Chromium 页面观察：无 App Server 时，本地 GET 返回 200，`cp-observation` 下 `Example Display` 行显示“只读”；能力和模型提示词弹窗均可打开。启动任务自有真实 App Server 后刷新，提供商错误消失，添加／编辑入口启用。把任务目录文件改成无效对象后 GET 返回 `503 provider_models_unavailable`，旧模型行仍在，修改锁定。对响应注入不同修订后出现不一致提示，模型行只读且无编辑按钮；移除注入后刷新，编辑重新启用。未知查询参数返回 `400 provider_models_invalid_input`。

临时环境没有官方 `models_cache.json`，官方目录独立报缺失；这与第三方目录和管理快照恢复分别呈现，未伪造官方缓存。首次空目录依照 loader 的空数组与前端空态分支审查，未另建完整浏览器场景。

### P2：取消、期限与所有权

只读请求从服务端进入开始有 20 秒取消期限，覆盖连接准备、初始化和读取。HTTP 断开及 WebUI 关闭触发同一读取信号；连接关闭会终止待回应 RPC，但不关闭共享服务。资源清理仍等待原生命周期确认，因此期限是取消工作的时点，不是强制遗弃清理的硬返回上限。关闭失败保留客户端，后续读取或关闭重试清理，失败时不创建替代客户端。写入与预览未接入此取消路径。

隔离 Unix WebSocket 完成真实初始化后故意不回答 `config/read`：Codex 与 Provider HTTP 在 212／202 ms 主动取消，分别观察到自有连接关闭，共享监听仍在；无取消的一次读取在 20030 ms 返回 `503 codex_settings_unavailable`，第三条连接也关闭，共享监听仍在。真实 App Server 正常读取已由 P1 恢复路径覆盖。

在真实客户端关闭边界注入一次失败，首次返回关闭错误、关闭计数为 1；下一次读取先重新关闭原客户端，计数变成 2，随后获得有效字符串版本。该观察验证保留和重试归属，不等于 Windows Proxy 无法退出的实机验证。

### P3：异步端点准备

账户刷新、Owner、Supervisor 单次操作及两类租约、Delivery 改用已有异步私有连接。复核了既有调用方的兼容参数、EOF 完成点、租约移交和离线回退；不以统一 JSON 行帮助函数替代不同协议合同。

真实 Unix IPC 观察包括 Owner 未就绪／就绪／撤销、账户刷新及重置券列表、Supervisor ensure／lease／release／settings、Delivery applied／stale／缺失端点。已取得 lease 后中止获取信号不会释放租约，显式且重复 `close()` 后才释放。Delivery 发送前拒绝连接返回 `null`，对端收到一次请求但丢失响应返回 `unconfirmed`。

用真实 libuv 队列延迟文件准备至约 2250 ms：取消在 17–19 ms 完成，1 秒 Owner／inspect 期限在 1001／1002 ms 完成，准备结束后四个端点接入数仍为 0。期间事件循环运行 223 ticks。四种端点改成 `0666` 均拒绝且无接入；写出 JSON 行而延迟 EOF 时，各单次读取未提前完成；在途账户及 settings 取消后服务端观察到取消信号。

### P4：指标入口发布

准备阶段执行材料首读并丢弃结果；每条样本仍读取当前授权材料。初始化失败不自动重试；关闭先取消 Reader，再等待启动退出并清理监听；监听完成后复核最新启用状态。

真实组合、Worker 和私有 IPC 观察：注入 1100 ms 准备延迟时，150 ms 无端点，1305 ms 后才发布；首条样本 5 ms 返回 `accepted`，入队收集端获得模型和 7 个 Token。撤销身份后下一条返回 `invalid_sample`，入队仍为一条；取消返回 `closing`，九条并发的第九条返回 `queue_full`。无效配置不发布，修正后同一准备失败不自动重试。真实 Worker 初始化期间关闭约 102 ms 完成；监听刚绑定时关闭、准备中停用与快速切换均未遗留端点。这里只观察入队收集端，未把它描述为数据库持久化证据。

运行中 Worker 退出仍保留原有重建恢复；触发重建的单条样本仍可能超过 1 秒传输期限而取消。本轮未扩展运行期恢复状态机或增加样本重试。

### P6：进程、临时客户端与最终退出

Unix stdio 创建独立进程组，Runtime 登记只在 Unix 执行；Windows 工厂保留已有树回收方式。包装器退出不清除资源引用，重连必须先取得旧组退出确认。用户配置读取、预览、修改和低层写入共用客户端清理：失败归属保留，后续操作先重试清理。写入已确认后清理失败输出固定告警，不把保存改判失败或自动重放。独立会话归档扫描也在 connect 前登记客户端，清理告警不覆盖已报告的归档结果。

材料 Reader 增加当前进程所有者登记、停止准入和物理退出等待；Gateway 正常、超时及初始失败路径消费材料 Reader／主线程 ACL 的关闭和退出句柄。两个封装也公开 `waitForExit`。独立 Relay 仍保留 Reader 的协作关闭归属；其服务命令没有另行强制 `process.exit`，不把 Reader 有界关闭失败视为成功退出。

实际 Linux 观察：

- 真实 Codex 0.163.0 npm 入口经项目客户端工厂完成 initialize、配置读取、版本保护写入和回读；`tools.update_plan.enabled=true` 保存且版本变化，正常关闭和重复关闭成功。
- 在真实客户端关闭边界注入失败：随后写入 `false` 已确认，出现 `CODEX_CONFIG_CLIENT_CLEANUP_UNCONFIRMED` 告警；下一读取被旧清理失败阻止，创建次数仍为 1。允许旧客户端清理后回读确为 `false`，没有重放写入。
- WebUI 客户端最终关闭新增准入门禁和在途操作等待。真实配置写入已经确认但结果暂缓返回时，关闭尚未完成、关闭次数为零，新操作被拒绝；释放结果后关闭完成，关闭次数为 1，磁盘值仍为 `true`。
- 自有包装器先退出、后代忽略 TERM：close 与 reconnect 均报告“自有进程组清理未确认，保留资源归属”，登记次数为 1；后代自行结束并由任务专有 subreaper 回收后，重试 close 成功，组查询为 `ESRCH`。
- 隔离 Provider Reader 读取成功；全局关闭并等待退出后，旧 Reader 和新 Reader 均拒绝读取。

限制：失去组长身份后不能安全保证旧 PGID 未被复用，因此不继续盲目发送信号；顽固后代不会自动保证回收，系统保留失败和归属。Windows helper 的实际协作退出、完整 Gateway 服务启停和会话归档实际提交未观察；归档仅复核连接与清理变化，不触碰真实会话。

### P7：取消前移与 Socket 校验

Delivery 在创建 Journal 之前及之后检查共享取消标记。预置取消的真实 Worker `exit=0`，只返回关闭确认，目标目录未创建；正常隔离 Journal 完成 ready → submit → next → pending/sending → acknowledge，正文一致、状态转换及确认均为 true，最终记录数为零，关闭等待到实际 Worker exit。

UA 改为复用正式跨平台 Transport，移除 Unix 独立连接实现。直接 Socket 和 rendezvous 目标都要求 `0600`；读取连接失败也进入 finally。Unix Transport 关闭超时保留引用，重连前清理旧连接。锁定官方提交 `83086188ae0614bd882818ff1aa23f3194962012` 的 initialize 实现和生成类型确认 `userAgent` 为必需字符串；缺失时明确不可用。

### P8：通知、Relay 与 UA 读取

通知改为异步准备，20 秒准备／连接期限与连接后的 35 秒空闲期限分开。SSE 关闭先禁入、取消并等待 watch；收尾前不释放八连接额度。Relay GET 断开传至私有查询；补齐服务端 EOF 关闭，避免 `allowHalfOpen` 留下无消费者查询。apply 不继承读取取消，仍按原确认和未知结果处理。

实际观察：

- HTTP → Relay 状态／队列返回 200；队列为空时 `requests=[]`，不可用指标保持 `usage=null`。HTTP 断开至 handler 取消从修复前 2001–2002 ms 降至队列 2 ms、状态 1 ms；原三参数 apply 返回 `applied` 且 digest 匹配。
- SSE 首次返回 changed，第九连接返回 `429 delivery_busy`，关闭后新订阅返回 503。真实文件准备队列拥塞时关闭等待 705 ms，准备结束后迟到连接数为零。
- 第 2048 次通知写入触发 HTTP 背压取消；预先取消、不安全端点、非法版本 999 均拒绝。21 秒时流仍存活，7 ms 收到 changed、15016 ms 收到 heartbeat，随后取消 5 ms 完成；未把 20 秒准备期限错误用于已建立流。
- UA HTTP 两个并发请求共用一条 IPC；单个取消后另一请求仍待回应，最终 200 并取得 UA，再读命中 5 秒缓存且没有新连接。全部等待者取消后连接关闭、pending 清空。100 ms 总读取期限在 103 ms 返回 `TimeoutError` 并关闭连接；WebUI 关闭收回在途连接，随后 UA 请求返回 503，无新接入。

UA 缓存键包含 Socket、binary 和客户端版本，按源码复核目标改变会取消旧读取并重新建立；显式配置 UA 不触发 IPC。失败清理保留 Transport，下一次读取或 WebUI 退出重试。20 秒通知准备超时、Windows ACL／命名管道和 macOS 的真实取消仍未观察。

### P9：本地 Chat 桥准入与身份

全部账户桥共享 64 MiB 最大正文保留额度；每请求在读取前固定预留 16 MiB，最多四个并发请求，生成和交付结束才释放。这是正文准入额度，不是 Node 进程总内存上限。每桥独立随机身份由现有 Runtime 组合通过 `proxyOptions` 交给统计代理；外部同名头被覆盖，通用头投影及 resolver 前移除私有头，上游 `Authorization` 不变。

隔离本机 HTTP 观察：缺失、伪造及跨桥身份均 401，上游调用为零；两个桥合计四个半上传请求后第五个 503，四个已完成上传且正在生成的请求仍占额度；完成、客户端取消和桥关闭后新请求分别恢复 200。16 MiB + 1 字节、无效 UTF-8、坏 JSON 和 gzip 各返回 400，随后合法请求 200。完整 ProviderProxy → ChatBridge → 本机上游 → Responses SSE 返回 200、答案和 `response.completed`；伪造私有头被覆盖，resolver／真实出站头均无内部身份，原 Authorization 保留。

未调用外部模型，没有计费。未另等 30 秒上传超时，未观察 Windows/macOS；现有阶段期限不变。休眠聚合路径没有重新启用，其 Guard 嵌套退出与代理准入仍是启用前必要工作，不能套用本节结果声称已解决。
