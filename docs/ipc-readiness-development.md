# IPC 读取与启动恢复改造

## 范围与基线

基线为 `c518eff4`。本记录维护本轮计划、关联审查和观察证据，不把待实施内容视为已支持功能。

目标是让本地展示不受无关进程启动影响，同时保留权威配置版本、单写入者、运行时所有权和私有端点校验。
不更改持久化格式，不迁移或删除用户数据，不替换会话 RPC，不增加浏览器持久配置缓存，不自动重试写入。

## 关联审查与验证计划

- P1：从模型页面、读取 Hook、管理 API、本地目录投影到原有预览／确认检查。观察无 App Server 的首次进入、成功恢复、已有快照失败、空目录、损坏目录和失效修订；只读展示不得生成可写版本或伪造默认值。
- P2：从 HTTP 关闭、总预算、连接／初始化、RPC、finally 清理到页面恢复。观察等待期间取消、期限到达、正常读回以及共享 App Server 存活；CLI 原有读取和写入路径保持原语义。
- P3：逐条核对账户、所有权、Supervisor 和 Delivery 的调用方、端点验证、发送边界与关闭。观察 Unix 正常读取、缺失端点、取消和无响应；Windows 代码审查不能替代真实 ACL／命名管道观察。
- P4：核对 Gateway 组合、材料读取器、接收器发布、首条样本、新鲜验证与关闭。观察冷启动准备、准备失败、准备期间关闭、已就绪收取及非法样本拒绝，不扩大授权缓存。
- 不创建或维护测试／探针脚本。使用现有静态检查、隔离临时数据、真实产品入口和交互工具；不操作现有服务、真实账户或用户配置。

## 实施与证据

观察日期为 2026-10-20，针对基线上的本轮未提交工作树。隔离数据同时指定 `CODEX_HOME`、`CODEX_CONNECT_HOME` 与 `CODEX_CONNECT_CONFIG_FILE`，未使用真实账户或重启既有服务。当前合同见 [WebUI](webui.md)、[Runtime](../runtime/README.md#私有-ipc-请求边界)、[Bootstrap](../src/bootstrap/README.md)。

### P1：本地展示与可写快照

新增鉴权管理 GET `/provider-model-catalogs`，直接复用原有本地投影；与完整管理读取处于同一进程，保留同一个目录修订密钥。完整 `/provider-settings` 预览、确认、写入及写后回读不使用本地目录替代资源版本。前端保留原管理组件及草稿，通过 Provider／目录修订一致性控制修改入口。

真实 Chromium 页面观察：无 App Server 时，本地 GET 返回 200，`cp-observation` 下 `Example Display` 行显示“只读”；能力和模型提示词弹窗均可打开。启动任务自有真实 App Server 后刷新，提供商错误消失，添加／编辑入口启用。把任务目录文件改成无效对象后 GET 返回 `503 provider_models_unavailable`，旧模型行仍在，修改锁定。对响应注入不同修订后出现不一致提示，模型行只读且无编辑按钮；移除注入后刷新，编辑重新启用。未知查询参数返回 `400 provider_models_invalid_input`。

临时环境没有官方 `models_cache.json`，官方目录独立报缺失；这与第三方目录和管理快照恢复分别呈现，未伪造官方缓存。首次空目录依照 loader 的空数组与前端空态分支审查，未另建完整浏览器场景。

### P2：取消、期限与所有权

只读请求从服务端进入开始有 20 秒取消期限，覆盖连接准备、初始化和读取。HTTP 断开及 WebUI 关闭触发同一读取信号；连接关闭会终止待回应 RPC，但不关闭共享服务。资源清理仍等待原生命周期确认，因此期限是取消工作的时点，不是强制遗弃清理的硬返回上限。关闭失败保留客户端，后续读取或关闭重试清理，失败时不创建替代客户端。写入与预览未接入此取消路径。

隔离 Unix WebSocket 完成真实初始化后故意不回答 `config/read`：Codex 与 Provider HTTP 在 212／202 ms 主动取消，分别观察到自有连接关闭，共享监听仍在；无取消的一次读取在 20030 ms 返回 `503 codex_settings_unavailable`，第三条连接也关闭，共享监听仍在。真实 App Server 正常读取已由 P1 恢复路径覆盖。

在真实客户端关闭边界注入一次失败，首次返回关闭错误、关闭计数为 1；下一次读取先重新关闭原客户端，计数变成 2，随后获得有效字符串版本。该观察验证保留和重试归属，不等于 Windows Proxy 无法退出的实机验证。

### P3：异步端点准备

账户刷新、Owner、Supervisor 单次操作及两类租约、Delivery 改用已有异步私有连接。复核了既有调用方的兼容参数、EOF 完成点、租约移交和离线回退；不以统一 JSON 行帮助函数替代不同协议合同。

真实 Unix IPC 观察包括 Owner 未就绪／就绪／撤销、账户刷新及重置券列表、Supervisor ensure／lease／release／settings、Delivery applied／stale／缺失端点。已取得 lease 后中止获取信号不会释放租约，显式且重复 `close()` 后才释放。Delivery 发送前拒绝连接返回 `null`，对端收到一次请求但丢失响应返回 `unconfirmed`。

用真实 libuv 队列延迟文件准备至约 2250 ms：取消在 17–19 ms 完成，1 秒 Owner／inspect 期限在 1001／1002 ms 完成，准备结束后四个端点接入数仍为 0。期间事件循环运行 223 ticks。四种端点改成 `0666` 均拒绝且无接入；写出 JSON 行而延迟 EOF 时，各单次读取未提前完成；在途账户及 settings 取消后服务端观察到取消信号。

### P4：指标入口发布

准备阶段执行材料首读并丢弃结果；每条样本仍读取当前授权材料。初始化失败不自动重试；关闭先取消 Reader，再等待启动退出并清理监听；监听完成后复核最新启用状态。

真实组合、Worker 和私有 IPC 观察：注入 1100 ms 准备延迟时，150 ms 无端点，1305 ms 后才发布；首条样本 5 ms 返回 `accepted`，入队收集端获得模型和 7 个 Token。撤销身份后下一条返回 `invalid_sample`，入队仍为一条；取消返回 `closing`，九条并发的第九条返回 `queue_full`。无效配置不发布，修正后同一准备失败不自动重试。真实 Worker 初始化期间关闭约 102 ms 完成；监听刚绑定时关闭、准备中停用与快速切换均未遗留端点。这里只观察入队收集端，未把它描述为数据库持久化证据。

运行中 Worker 退出仍保留原有重建恢复；触发重建的单条样本仍可能超过 1 秒传输期限而取消。本轮未扩展运行期恢复状态机或增加样本重试。
