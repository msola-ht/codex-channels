## 哪些应共享，哪些必须留在渠道

共同展示层维护命令标签、描述、静态操作参数前缀及由 Application 结果派生的展示数据，业务语义与执行由 Application 负责。渠道拥有信息分组、字面转义、截断、分页容量、按钮类型、填写方式及返回路径。相似标签不代表相同交互，当前不再仅为消除重复而增加抽象。

后续布局修改必须守住以下边界：

- **展示不授权。** 静态目录不是能力白名单；飞书仍只接受实际卡片中的动作，QQ 保留自身命令及参数准入，QQ Goal 仍只支持查询和清除。
- **身份不随布局变化。** 工作区使用原始 ID，模型使用 Provider/model 身份，会话保留权威 selector 和完整 ID；不得用标题、显示位置或截断文本代替执行身份。
- **交互仍由原链路管理。** Actor、Workspace、Thread、快照、令牌、有效期、一次性消费和提交前重读继续由原控制器与 Application 校验。
- **渠道能力允许不同。** 飞书卡片与表单、Telegram 命令与键盘、QQ 回调与填写按钮、微信文字入口分别设计；专有诊断和导航不强行合并。

本阶段已覆盖计划任务与 Plugin 清单，Queue 清单完成后隐藏菜单入口。状态快捷按钮、其余动态详情、审批／确认和独立导航未纳入本轮；后续确有布局需要时，再按各自的状态和确认合同确定范围。

## 下一步怎么做

第二阶段先统一信息分组、命名、操作方式和导航含义，再适配各渠道。统一不等于四端使用相同布局，更不意味着所有命令结果页一起变化。下面的飞书首页、更多页与会话正文结构已落实到源码，其他渠道仍为待实施草案；源码完成不代表已部署。

### 沿用现有命令

所有入口继续使用现有命令、别名、参数与执行链路，不新增独立命令来替代原命令，也不引入新的分类命令或参数语法。例如，不为了帮助分组新增 `/help <分类>`；QQ 已有的 `/help model 1` 等内部菜单路径保持原有支持范围，不向其他渠道直接复制。

菜单只改变已有能力的查找和呈现。点击后原本直接执行、打开选项、填写后发送或确认的行为保持不变，标签应准确反映实际行为。未来如需新增卡片内导航回调，应在后续批次明确其导航职责及允许动作，不借此建立另一套业务命令入口。

### 第二阶段允许改变的页面

飞书静态首页、更多卡、会话、模型设置、工作区、计划任务与 Plugin 清单已实现；其他渠道仍分批实施，飞书部署与客户端验收另行跟踪。

| 静态分类菜单 | 分组归属、呈现顺序和操作方式说明 | 原有执行、填写和确认链路；既有导航目标 |
| 帮助呈现 | 常用摘要、分段与阅读顺序 | 现有帮助入口和完整用法的可获取性；不新增分类语法 |

当前不改 `/status`、`/usage`、`/metrics` 等结果页，不改审批、表单与确认界面。状态快捷按钮、清单以外的扩展及计划任务详情保持原样；清单调整保留原业务命令及快照校验。

修改共享标签或帮助定义前，必须列出所有消费者及受影响页面；若会波及范围外页面，应在目标渠道或页面保留局部覆盖，不能让共享变更自动扩散成全局改版。

### 飞书会话正文与选择按钮

历史与归档卡正文使用 Markdown 列表，每项显示序号、标题、已有模型／思考／Provider 信息、短 ID、状态和可用轮数。当前与后台标记仅用于历史列表，当前优先；固定标记保留。序号优先使用原 selector，缺失时沿用页内序号且仅用于显示；短 ID 取原完整 ID 的前十二位，只作辅助辨识，不承诺跨列表唯一。按钮使用“12 · 会话标题”，保留编号并截断长标题，不加恢复前缀；整个按钮标签不超过既有 32 个 UTF-16 单元，截断不拆开码点。按钮使用纯文本，正文单独转义 Markdown，选中仍提交原完整 ID。

正文标题按 Unicode 码点限制为 32 字符，超过时保留前 31 字符并追加“…”；模型／Provider 各 80、状态／思考值各 40。显示前压平控制字符与换行，并转义 Markdown 和标签语法。正文与按钮由同一份会话投影生成，同名、相同标题前缀甚至短 ID 相同仍可通过编号区分。每页最多十个会话，加搜索及双向翻页最多十三个按钮，不触及现有十八项上限。按钮均为普通样式，不按位置强调第一项；标题原有回退规则与其他动态卡的通用布局保持原样。

| 观察输入 | 预期呈现及操作 |
| --- | --- |
| 同名同模型、不同完整 ID | 正文及按钮保留不同序号；点击分别提交对应完整 ID |
| 长标题前缀相同、中文或表情 | 正文标题有界截断，编号按钮不依赖标题辨识 |
| 当前与后台标记重叠 | 保留当前优先；不把标记差异作为唯一辨识依据 |
| 搜索、翻页、归档列表 | 沿用权威 selector、过滤条件与顺序；归档仍提交 `unarchive`，普通列表仍提交 `resume` |
| 缺失 selector、空标题、空列表 | 仅展示沿用既有回退；空列表保持原结果，不生成虚假可选会话 |

源码已实现上述结构；本地生产展示函数的观察与真实客户端验收分开记录，实机显示和点击仍待验收。

### 实施顺序与影响控制

提供商、模型、思考等级、Fast 和工作区选择卡采用“当前设置 + 候选清单 + 名称按钮”。模型每项用一段显示编号、名称、速度支持与已有不可用原因，项间留空行；工作区名称与目录各自成段、项间留白。两者不重复列出候选 ID，执行仍用原完整身份。思考等级保留目录说明；Fast 仅展示当前模型实际提供的速度候选，并区分已选与有效状态。字面字段限长并转义，按钮用纯文本，普通样式不暗示第一项已选。

模型设置与工作区的正文、实际按钮均限定在原前 18 项范围，完整 choices 保留供原渲染器生成超限提示和前 18 项模型快照。未新增分页；更多选项继续通过原聊天命令查看、选择。正文只投影共享结果，不重建身份、权限或模型状态。
