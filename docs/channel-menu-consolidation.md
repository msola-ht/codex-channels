## 入口与约束

| 入口 | 当前消费路径 | 必须保留 |
| --- | --- | --- |
| Telegram 命令菜单 | Application 命令名与共享描述 → 平台注册 | 规范命令顺序，别名由共享表注册，原授权中间件和参数提取 |
| 飞书、Telegram、微信文字帮助 | 共享帮助 → 平台格式化 | 原章节、分组、用法、换行和平台专有帮助 |
| 飞书首页及更多菜单 | CardKit 静态行 → 卡片动作集合 → 原处理器 | 标签、样式、行列、无参行为；仅允许原卡片中的动作 |
| QQ 首页及静态分类 | 固定键盘 → 回调或填入 → 原菜单与命令处理器 | 按钮 ID、文本、数据、行列和输入方式；Goal 仅查询/清除 |
| 动态菜单和确认 | 原结果与上下文 → 原控制器 | 完整目标 ID、快照、Actor、期限、一次性消费与提交守卫 |

静态目录仅描述呈现内容，不成为授权表或第二套命令解析器。渠道专有诊断和页面导航仍由渠道拥有；共同操作使用共享定义，各渠道保留既有标签覆盖和页面编排。

## 静态页面与能力差异

| 内容 | 共同定义 | 渠道保留部分 |
| --- | --- | --- |
| 会话、模型、工作区、用量与任务命令 | 全部规范命令的描述及默认标签 | Telegram 命令注册顺序；飞书首页和更多分类；QQ 首页和分类顺序；微信文字入口 |
| Review、MCP、Plugin、重置券 | 明确操作的标签与参数前缀 | QQ 的填写按钮与既有管理菜单，飞书既有表单处理器 |
| 计划任务创建 | QQ 已有六种创建入口的静态标签与前缀 | 原确认、自然语言输入、任务列表及动态 Run 页面 |
| Goal | 查询入口标签和共同文字帮助用法 | QQ 仍只允许查询和清除，不从共同帮助生成创建入口；其他渠道执行沿原合同 |
| 平台操作与导航 | 无新增共同能力 | 飞书状态/Doctor，微信 Doctor，身份入口，首页/返回/分类跳转仍本地定义 |

共同操作目录不枚举动态模型、会话或任务；这些选择必须继续绑定运行时目标。显示标签的渠道覆盖仅为保留已有文案，不改变操作身份。

## 第二阶段工作区选择

本轮接续第一阶段的工作树，只抽取工作区列表的共同展示数据。`workspace-selection-presentation.ts` 接收 Application 的 `workspaces` 结果，生成原始 ID、名称、目录、原顺序编号、当前标记和当前项。它不排序、清理、截断或选择工作区，不持有交互状态。

| 路径 | 已核对的合同 | 本轮处理 |
| --- | --- | --- |
| 文字 `/workspace`、`/work` | 统一命令服务；字符串选择仍由 Router 解析序号/ID/名称 | 只替换共同列表格式化的数据来源 |
| Telegram 工作区按钮 | 原始 ID 计算哈希，点击后查询登记目录再走精确 ID 选择 | 哈希及回调不变，标签读取共同当前标记 |
| 飞书工作区选择卡 | 完整 ID 作为 workspace-select 输入，原卡片动作集合与归属校验 | 文案、空列表回退与卡片布局不变 |
| QQ 工作区选择 | 9 条一页，原上下文与一次性选择，按钮固定完整 ID | 分页仍本地执行，编号来自全量列表原顺序 |
| 切换执行与回执 | Application 锁内检查空闲、后台任务、原生 Queue，再调用 Router 切换并返回 workspace.selected | 未修改；目录失效不自动回退或重试 |

各渠道保留原来的字面转义、长度限制和按钮编码；纯数字 ID、同名名称不能通过展示数据改变选择含义。当前 ID 不在列表中时保持原失效提示；空列表保持各自既有行为。

本地直接调用修改前后生产渲染函数：当前项、失效当前项和空列表三组输入的共同文字、Telegram 键盘、飞书选项和微信结果完全一致。输入包含纯数字 ID、同名、中文、Markdown/HTML 字符及换行。12 个同名项的投影第二页保留 ID/编号 10、11、12，当前项仍为完整 ID `10`；这不是 QQ 客户端翻页观察。

`npm run check`、本轮修改文件 ESLint、文档索引和 `git diff --check` 均通过。独立 Sol 子代理复审了投影及四处消费者、QQ 分页编号、Telegram 哈希、飞书卡片实际动作集合和 Application 到 Router 的选择链路，未发现需修复的问题；主代理核对最终差异，未扩大到其他动态菜单。

## 第二阶段模型选择

接续提交 `87598f0c`，只整理模型菜单的共同展示数据。`model-selection-presentation.ts` 从既有 ModelSelectionState 生成 Provider 顺序、浏览范围内条目及编号、Provider/model 共同身份、匹配当前目录项、可用当前模型和 Standard/Fast/Ultrafast 候选项。原始模型对象保持引用，未使用显示名或编号替代身份。

| 关联路径 | 本轮保留的合同 |
| --- | --- |
| Provider 浏览 | 沿用 Application listProviders 顺序及 providerFilter；浏览不修改当前设置 |
| 当前模型 | provider 缺省按既有 openai 合同匹配；同名模型必须同时匹配 Provider/model |
| 模型目录 | 不可用条目仍保留；QQ 不为其生成选择按钮，飞书和 Telegram 保留原显示方式 |
| 思考等级 | Telegram 仍读取匹配目录项，飞书/QQ及共享状态读取可用当前模型；QQ null effort 的默认高亮与其他渠道保持差异 |
| 速度 | Standard 始终列出，两个加速选项继续由当前可用模型的既有能力函数决定；未知选择不冒充 Standard |
| 点击执行 | 飞书/QQ仍在原位置构造 ModelSelectionSnapshot/Request，Telegram 原令牌和回调解析保持；Application 复核原 Thread、状态快照、授权和写入边界 |
| 格式及分页 | 共享文字继续字面清理，渠道保留转义、截断、行列、分页和原序号 |

Telegram 回调按查询结果序号取模型，Application selectionState 在指定 Provider 时返回已过滤目录；本轮不改变该共享合同，也不把呈现投影交给回调替代权威重读。

已完成共同文字及四渠道消费接线。主代理关联审查核对 Provider 过滤后的序号、原对象引用、可用性差异、快照创建顺序和回调到 Application 的选择路径，未发现本轮引入的行为缺陷；移除了投影中无消费者的返回字段。

本地生产函数观察覆盖五种状态乘 model/effort/fast 共 15 组：同名跨 Provider、浏览过滤、不可用当前项、空目录、未知速度，以及名称中的 Markdown/HTML 和换行。共享文字、微信结果和飞书选项与基线一致；Telegram 按钮比较只屏蔽每次随机生成的 43 字符令牌值，保留回调类型、序号及所有其他字段，结果一致。QQ 分页和精确选择经源码核对，未执行真实控制器交互。

反例观察中，跨 Provider 浏览仍保留原当前模型，缺失/不可用当前项只提供 Standard，未知浏览范围返回空候选；源状态、modelSelectionSnapshot 和同进程 Telegram 令牌不变。无加速、仅 Fast、仅 Ultrafast、两者都有的四种目录能力分别生成相应速度选项；选择未知时飞书未给任一档位添加当前标记。
