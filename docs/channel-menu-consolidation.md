## 哪些应共享，哪些必须留在渠道

共同展示层维护命令标签、描述、静态操作参数前缀及由 Application 结果派生的展示数据，业务语义与执行由 Application 负责。渠道拥有信息分组、字面转义、截断、分页容量、按钮类型、填写方式及返回路径。相似标签不代表相同交互，当前不再仅为消除重复而增加抽象。

后续布局修改必须守住以下边界：

- **展示不授权。** 静态目录不是能力白名单；飞书仍只接受实际卡片中的动作，QQ 保留自身命令及参数准入，QQ Goal 仍只支持查询和清除。
- **身份不随布局变化。** 工作区使用原始 ID，模型使用 Provider/model 身份，会话保留权威 selector 和完整 ID；不得用标题、显示位置或截断文本代替执行身份。
- **交互仍由原链路管理。** Actor、Workspace、Thread、快照、令牌、有效期、一次性消费和提交前重读继续由原控制器与 Application 校验。
- **渠道能力允许不同。** 飞书卡片与表单、Telegram 命令与键盘、QQ 回调与填写按钮、微信文字入口分别设计；专有诊断和导航不强行合并。

状态快捷按钮、Queue、扩展和计划任务的动态菜单尚未纳入本轮重构。它们不是本轮遗留缺陷；后续确有布局需要时，再按各自的状态和确认合同确定范围。

## 下一步怎么做

第二阶段先统一信息分组、命名、操作方式和导航含义，再适配各渠道。统一不等于四端使用相同布局，更不意味着所有命令结果页一起变化。下面的飞书首页与更多页结构已落实到源码，其余仍为待实施草案；源码完成不代表已部署。

### 沿用现有命令

所有入口继续使用现有命令、别名、参数与执行链路，不新增独立命令来替代原命令，也不引入新的分类命令或参数语法。例如，不为了帮助分组新增 `/help <分类>`；QQ 已有的 `/help model 1` 等内部菜单路径保持原有支持范围，不向其他渠道直接复制。

菜单只改变已有能力的查找和呈现。点击后原本直接执行、打开选项、填写后发送或确认的行为保持不变，标签应准确反映实际行为。未来如需新增卡片内导航回调，应在后续批次明确其导航职责及允许动作，不借此建立另一套业务命令入口。

### 第二阶段允许改变的页面

当前首批只实施飞书首页与更多静态卡；下表其余范围分批处理，会话列表单列后续批次。

| 范围 | 可以调整 | 保持不变 |
| --- | --- | --- |
| 首页 | 现有入口的分组、顺序、标签和说明 | 命令身份、参数、点击效果及能力范围 |
| 静态分类菜单 | 分组归属、呈现顺序和操作方式说明 | 原有执行、填写和确认链路；既有导航目标 |
| 帮助呈现 | 常用摘要、分段与阅读顺序 | 现有帮助入口和完整用法的可获取性；不新增分类语法 |
| 飞书历史／归档会话选项 | 补充序号、必要的短身份信息，让同名或截断后相同的标题可区分 | 完整 Session ID、权威 selector、查询、排序、分页及恢复动作 |

当前静态首批不改 `/status`、`/usage`、`/metrics` 等结果页，不改模型／思考／速度和工作区选择页，不改审批、表单与确认界面，也不改任何渠道的会话列表。状态快捷按钮、Queue、扩展和计划任务动态界面继续保持原样。飞书会话列表的展示调整在后续独立批次处理。

修改共享标签或帮助定义前，必须列出所有消费者及受影响页面；若会波及范围外页面，应在目标渠道或页面保留局部覆盖，不能让共享变更自动扩散成全局改版。

### 先交付布局对照，再实施

共同分组只用于组织入口，不生成新的命令，也不要求每端拥有同样的按钮。原命令及完整参数仍以用户指南和现有帮助为准。

| 信息分组 | 现有操作 | 飞书入口草案 | QQ 入口草案 | Telegram／微信入口草案 |
| --- | --- | --- | --- | --- |
| 当前任务 | `status`、`stop` | 首页首行 | 首页首行 | 帮助摘要最前；保留原命令 |
| 会话与工作区 | `new`、`resume`、`sessions`、`archived`、`archive`、`unarchive`、`rename`、`pin`、`unpin`、`compact`、`fork`、`workspace` | 首页保留新建、恢复、工作区；其余在更多页会话分组或原列表内 | 首页保留新建、历史、工作区；沿用会话操作分类与归档列表 | 摘要列新建、恢复、工作区；完整用法仍在后文 |
| 模型设置 | `model`、`effort`、`fast` | 首页放在同组 | 保留首页模型行 | 摘要列模型入口；保留原完整用法及键盘 |

| 用量与账户 | `usage`、`metrics`、`limits` | 首页同组 | 沿用首页用量、统计和账户工具 | 保留完整帮助和原命令 |
| 扩展能力 | `agents`、`skill`、`mcp`、`plugin`、`hooks` | 更多页能力分组 | 原能力集成分类 | 保留完整帮助和原调用参数 |
| 权限与渠道帮助 | `autoreview`、`permissions`、`release`；现有身份、诊断与帮助入口 | 更多页权限与诊断分组，渠道专有项单列 | 原偏好设置、会话操作、账户工具；不新增诊断能力 | 保留各自原有说明和专有命令 |

跨分组保留现有入口是为了避免新建导航合同，例如 QQ `revert` 和 `release` 继续位于会话操作。QQ Goal 只查询／清除；飞书 Goal 继续使用原操作选择卡。共同分组不意味着可把某端已有动作复制给其他端。

### 飞书：首页与更多页

两张静态卡的按钮统一使用 `default` 普通样式，不按位置或使用频率强调个别入口。Fast 是打开速度选择的入口，不以蓝色暗示当前已开启。名称不追加装饰性省略号，操作含义通过名称和必要说明表达。

首页从“常用 + 模型与工作区 + 更多”调整为下面五组，原 13 个业务入口加更多，改为 11 个业务入口加更多。停止从更多页移到首页，Goal、Plan、计划任务移入更多页；所有操作仍可从原命令进入。

| 首页分组与按钮顺序 | 原动作／输入 | 点击结果保持 |
| --- | --- | --- |
| 当前任务：当前状态 · 停止任务 · 新会话 | `status` / `stop` / `new`，空输入 | 状态查询／请求停止／原新会话流程，不新增确认或自动发任务 |
| 会话与工作区：恢复会话 · 工作区 | `resume` / `workspace`，空输入 | 原会话／工作区选择卡 |
| 模型设置：选择模型 · 思考等级 · Fast | `model` / `effort` / `fast`，空输入 | 原选择卡或原无选项回退；Fast 仍先查询模型，不直接开启加速 |

更多页继续使用现有一张分组卡，不增加点击分类后再开一层的新交互：

| 分组 | 按钮行（分号表示换行） |
| --- | --- |
| 会话管理 | 会话列表 · 已归档；归档当前 · 重命名 · 分叉会话；固定会话 · 取消固定 · 压缩上下文 |

行内标签只作本页覆盖，不修改共享目录以联动其他结果页。`rename` 仍打开原表单，`review`／`goal` 仍打开原目标选择；空输入 `plan` 会直接切换模式，故使用“切换 Plan 模式”，不能标成仅浏览的“Plan 设置”。其余动作和输入保持原值，完整用法不缩减。更多页不在首批新增首页按钮，可继续发送原 `/help` 打开首页。飞书静态行的实际允许动作随生成卡片核对，首页新增的 `stop` 仍走原 Actor、消息、令牌及权限校验。

### 飞书会话标签草案

历史与归档列表都使用“序号 · 短 ID · 标记／标题”的顺序，例如 `12 · a1b2c3 · 当前／修复菜单…`。序号优先使用原 selector，缺失时沿用页内序号且仅用于显示；短 ID 取原完整 ID 的前六位，只作辅助辨识，不承诺跨列表唯一。选中仍提交原完整 ID。

截断时先保留序号、短 ID 和当前／后台标记的空间，再截标题，总标签仍遵守现有 32 个 UTF-16 字符预算；不能先拼完整长标题再整体截掉辨识信息。同名同模型、相同长标题前缀甚至短 ID 相同时，列表序号仍帮助区分。模型信息只在剩余空间足够时显示，不依赖它判定身份；不修改当前／后台优先级、标题原有回退规则或其他卡片的通用截断函数。

| 观察输入 | 预期呈现及操作 |
| --- | --- |
| 同名同模型、不同完整 ID | 标签保留不同序号和短 ID；点击分别提交对应完整 ID |
| 长标题前缀相同、中文或表情 | 辨识前缀不被截掉，标题不出现孤立代理项；卡片标签满足预算 |
| 当前与后台标记重叠 | 保留当前优先；不把标记差异作为唯一辨识依据 |
| 搜索、翻页、归档列表 | 沿用权威 selector、过滤条件与顺序；归档仍提交 `unarchive`，普通列表仍提交 `resume` |
| 缺失 selector、空标题、空列表 | 仅展示沿用既有回退；空列表保持原结果，不生成虚假可选会话 |

以上为设计预期，尚未通过界面实现或实机观察确认。

### 实施顺序与影响控制

先实施飞书静态首页／更多页，再单独实施飞书会话标签，最后适配 QQ 静态首页与 Telegram／微信帮助。每批核对原动作输入集合及页面差异；不将所有渠道改动放进一次难以回退的提交。

飞书静态布局改动限定在 `command-center.ts` 的两张静态卡片及相关 README；会话标签限定在 `command-center-presentation.ts` 的历史／归档分支。QQ 首页限定在 `command-menu.ts`，Telegram／微信摘要分别放在各自帮助出口。优先复用现有共享定义，首批不修改共享命令标签、完整帮助用法、模型／工作区投影或通用选择卡截断与布局函数。实现前仍须按引用确认这些边界，不把文件名当成覆盖证明。

### 返回导航与长列表另列一批

样式语义也需在动态页面批次单独核对：目前 Markdown 选择卡将第一个选项自动设为 `primary`，并不代表当前项。本批不改这些选择页；后续应取消基于位置的强调，当前状态用明确文字或勾选标记表示。`primary` 应留给页面明确的主提交动作，`danger` 用于需要突出后果的拒绝或危险动作；审批与确认界面需结合其业务合同单独评审，不从静态菜单修改中连带调整。

后续再设计飞书更多页返回首页、飞书／Telegram 模型返回提供商，以及飞书模型和工作区长列表的完整浏览路径。QQ 已有首页、模型返回提供商和动态分页，飞书会话列表也已有业务分页，应复用，不重复建设。

飞书选择卡的前 18 项限制同时关联模型快照和实际允许动作，不能只增加翻页按钮或取消截断；卡片 `help` 动作当前打开更多页，不能直接改名为首页。返回提供商只能改变浏览范围，不能修改当前模型设置。这批需单独审查导航回调、身份、快照与失效规则，并继续沿用原业务命令。

### 每批完成条件
