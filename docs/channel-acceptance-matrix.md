# 通讯渠道验收矩阵

本表是 Telegram、飞书和微信功能验收状态的统一入口，只记录外部行为是否经过真实平台验证，
不重复各模块的实现、协议与测试细节。实现范围以根目录
[`README.md`](../README.md) 为准；模块边界与离线验证入口分别见
[`src/surfaces/telegram/README.md`](../src/surfaces/telegram/README.md)、
[`src/surfaces/feishu/README.md`](../src/surfaces/feishu/README.md) 和
[`src/surfaces/weixin/README.md`](../src/surfaces/weixin/README.md)。

## 状态定义

- **实机通过**：操作者已经在真实平台客户端观察到完整生产链路结果。
- **部分实机**：主路径已有真实结果，但组合、故障或边界场景仍需集中复验。
- **合同通过**：真实上游接口探针已经成功，但尚未验证完整生产 Surface。
- **离线通过**：源码、Mock 或本地合同测试通过，尚无真实平台结论。
- **未支持**：当前公开范围明确不提供；不能通过宽松回退伪装为支持。

合同探针只证明对应上游请求和响应形状，不自动升级为生产链路“实机通过”。真实平台验收也只
覆盖表中明确写出的主路径，不代表限流、断线、重投或超限边界已经通过。

## 能力边界

- 本表只验收 [`docs/index.md`](index.md) 当前支持矩阵已经接入的 Codex CLI/App Server 能力，
  以及明确标记的渠道运维或呈现能力；不能因为某个平台能够实现就扩展 Codex 语义。
- Codex 能力必须同时有当前锁定协议依据、受控类型、本地实现和验证。生成类型中存在但尚未接入
  的方法继续视为未支持。
- Setup、Doctor、菜单、输入状态、连接健康和平台媒体传输属于渠道能力，不产生新的 Thread、
  Turn、Item、工具、审批或历史事实。
- 不实现假流式、平行会话状态、平台私有工具或静默扩大的审批语义。平台无法准确承载某项能力时，
  使用受约束降级或明确标记为未支持。
