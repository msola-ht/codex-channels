后续补证说明（2026-10-22）：本文保留早期基线与当时的未观察限制。
`8232b2ed` 的成功历史冷恢复、Provider 设置重连、完整 Gateway 队列挑战及仍开放边界，
见[当前 Debian 与 macOS 验收记录](../thread-execution-context-acceptance.md)，不回写为本次早期审查已观察。
该记录另补录 Debian 验收、关联修复与独立审查，分别保留各平台的证据范围。

目标是将登记 Workspace 与 App Server 返回的 Thread 执行目录分开投影，
补齐生命周期、通知和诊断链路。保持现有精确目录准入，不开放递归子目录互通。
不改变 Turn/resume/fork 请求、计划任务目录、Hooks 管理范围或数据库格式；
不自动回传 runtimeWorkspaceRoots，不读取 Codex 内部会话文件。

上游冷恢复可继承 roots 并按显式 cwd 重定位；已加载恢复可能忽略覆盖。
fork 有独立配置加载逻辑。响应实际值不能由请求值替代。
设置通知有 cwd，但没有 runtimeWorkspaceRoots；roots 只能标为最近生命周期快照。
本地锁或版本检查不构成跨原生客户端的原子提交保证。

## 开发与审查流程

每批按以下顺序完成，提交后再进入下一批：

1. 追踪入口、共享契约、读写消费者、失败补偿和清理路径。
2. 实现该批完整行为并更新对应模块和协议文档。
3. 用既有静态检查核对工程状态；进行人工 Hack 与隔离真实用户路径观察。
   不新增或修改测试、探针、守卫脚本；不操作用户真实 Thread、服务或发送外部消息。
4. 启动一个新的 Astra 子代理，独立审查该批完整关联链路；子代理只读、不提交、不得委派。
5. 主代理处理发现，复核受影响路径，记录真实输出与未观测边界；提交中文说明。

## 第一批：权威上下文投影与生命周期

状态：已提交 `b802d264`，提交 hook 全部通过。

- Client 校验并保留生命周期响应中的 cwd、runtimeWorkspaceRoots。
- Router 为已绑定 Thread 保存内存诊断投影，区分最近确认 cwd 与生命周期 roots 快照。
- 设置通知更新 cwd；不将缺失 roots 转为空数组，不伪造实时 roots。
- 覆盖新建、自动接续、显式恢复、后台新建、fork、恢复补偿；
  关闭、断线、待恢复、解绑时不得把旧投影当作当前状态。
- 目录变化使正在路由的审批归属失效；不扩大原有准入范围或父子关系。
- 验收关注：畸形 roots、空列表、未绑定通知、关闭后迟到通知、恢复和补偿，
  原生设置变化；无法观测的路径逐项说明。

## 后续边界

递归子目录发现、放宽恢复目录、跨目录子代理审批及执行请求继承策略不在本轮实现。
需另行明确授权范围、精确目录列表策略、跨客户端竞态和公开行为后推进。
当前协议 cwd 列表是精确匹配，不提供目录前缀过滤。
