# 本机管理接口安全设计

## 适用范围

本文定义把 Setup、Config、服务安装和更新接入本机可视化管理入口时必须满足的安全边界。
当前 WebUI 已开放低风险设置读写，以及经过一次性确认和白名单任务保护的部分高风险操作；指标读取和这些
设置写入复用同一个 WebUI Bearer Token，不建立第二套浏览器登录。

这是当前架构的稳定约束：后续扩展不能恢复独立管理凭据、管理登录/登出接口、管理 Cookie 或第二套浏览器
会话；高风险能力若未来接入，只能在同一 Bearer 鉴权上增加操作级安全门槛。

管理能力必须继续调用 `scripts/` 中不依赖终端的结构化接口。HTTP 层只负责认证、请求约束、预览确认、
任务生命周期和结果映射，不复制配置、Provider、渠道 Setup、服务安装或更新语义。

## 监听与认证

- 管理写接口只接受来自回环地址的连接。WebUI 即使绑定 `0.0.0.0` 提供指标直连，公网连接也不能调用
  管理写接口；远程管理通过 SSH 隧道访问服务器回环地址。非回环管理在单独完成 TLS、可信反向代理和
  来源配置前保持关闭。
- WebUI 的 `webui.token` 同时保护指标读取和管理读写；高风险写入另需一次性确认令牌。未配置令牌时管理路由失败关闭，
  不提供独立的管理凭据、登录或登出接口。
- 浏览器令牌只保存在当前标签页的 `sessionStorage`，通过 `Authorization: Bearer` 发送；服务端不把令牌
  写入 Cookie、响应正文或日志。绑定非回环地址时仍必须配置令牌。
- 管理请求使用常数时间 Bearer 比较，并按令牌指纹进行分类限速；审计只记录脱敏主体指纹。

## Origin 与浏览器边界

- 管理请求不开放 CORS。所有修改状态的请求必须携带与配置完全匹配的 `Origin`；同源 GET 读取仍受
  回环地址和 WebUI Bearer 令牌保护，不得从 `Host`、`X-Forwarded-Host` 或任意转发头自动扩展可信来源。
- Bearer 令牌不通过 Cookie 自动附带，因此跨站请求无法获得管理权限；Origin 检查仍作为第二道边界。
- 管理响应统一设置 `Cache-Control: no-store`、严格 CSP、`frame-ancestors 'none'`、
  `X-Content-Type-Options: nosniff` 和禁止 Referrer 泄露的策略。
- 不接受表单编码、跨站简单请求或通过 GET 触发修改；管理 API 只接受明确的 JSON Content-Type。

## 修订、防重放与确认

- 所有配置读取返回基于当前原始文件内容计算的修订值。修改必须携带读取时修订，并在写入前再次复核；
  修订缺失或变化返回稳定的冲突错误，不自动合并或覆盖。
- 普通可逆设置返回变更摘要与生效动作。它们不在写入时自动重启服务，因此无需机械增加二次确认。
- Provider 删除、固定模式切换、渠道凭据替换、服务安装、源码更新、数据库维护等高风险操作必须先生成
  脱敏预览。执行时使用不可预测、一次性、短期确认令牌；令牌绑定管理令牌主体、操作类型、输入指纹、资源
  修订和预览结果，不能跨会话、跨操作或修改输入后复用。
- 确认令牌在开始执行前原子消费。重复提交只返回已消费或过期，不重放写入；需要重试时重新读取状态并
  生成预览。普通请求另接受唯一请求 ID，用于返回同一次已完成结果，不用它绕过修订或确认。
- 预览必须明确显示将修改的资源、是否写入凭据、是否中断服务、预计执行阶段、失败恢复方式和生效动作；
  不返回已有 Key、Token、Secret、代理值、配置正文或备份内容。

## 请求与任务限制

- 请求行、Header、JSON Body 和单字段分别设置上限；普通管理 JSON Body 默认不超过 64 KiB，凭据字段
  使用各领域已有的更小上限。超限在解析完整正文前拒绝，上传文件另行设计，不能复用 JSON 写入口。
- 只读检查、普通修改和高风险任务分别限速；单个管理令牌同时只允许一个会停止服务或替换源码的
  任务，同类任务全局串行。队列必须有界，拒绝不能静默变成后台执行。
- 渠道扫码、OAuth、等待消息、服务安装和更新作为有所有者、期限、取消路径与关闭等待上限的任务运行。
  会停止或替换当前程序的步骤继续由独立子进程执行，Web Server 只跟踪脱敏进度和最终状态。
- 客户端断开不自动批准、取消或重试高风险写入；任务的取消语义由对应管理接口明确声明。

## 审计与错误

- 管理审计记录时间、令牌主体、来源类别、操作类型、目标标识、输入指纹、预览/确认标识、修订、完成阶段、
  结果码和恢复状态。不得记录请求正文、凭据、代理值、配置内容、上游响应或备份内容。
- 审计文件与凭据分离，使用 `0600` 权限、有界轮转和稳定事件版本；审计写入失败时，高风险操作在开始
  前失败关闭，运行中任务则保留主结果并明确记录审计降级状态。
- 外部错误只使用稳定代码、字段、阶段、是否可重试和修复动作。内部异常保留在脱敏日志中，不原样返回
  堆栈、路径之外的敏感上下文或子进程完整输出。

## 接入门槛

开始增加新的管理写路由（尤其是高风险操作）前必须同时满足：

1. 所有拟暴露修改项已具备脱敏读取、明确输入、修订保护和稳定生效动作。
2. 所有高风险操作已具备预览、一次性确认、阶段进度、取消或恢复路径。
3. WebUI Bearer 认证、Origin、限速、请求上限与审计由共享层实现并有失败关闭测试。
4. 指标 API 与管理 API 明确分路由；同一 WebUI Token 的写权限仅限受控设置和已具备确认/任务契约的白名单操作。
5. 真实服务中断、源码替换和凭据事务继续在现有管理模块或独立任务中执行，HTTP 层不直接操作文件、
   服务管理器、数据库或 App Server Transport。

## 当前实现映射

- `management-access.mjs`：精确 Origin、分类限速、请求元数据上限和安全响应头；WebUI Bearer 认证在
  `webui-server.mjs` 与普通 API 共用常数时间比较。
- `management-confirmations.mjs`：稳定 JSON 指纹与绑定令牌主体、操作、输入、修订和预览的一次性确认令牌。
- `management-audit.mjs`：固定事件版本、固定脱敏字段、`0600` 私有 JSONL 与有界轮转。
- `management-security.mjs` / `management-security.d.mts`：本机管理适配器唯一应导入的共享入口。

这些模块只提供组合原语，不会自行监听端口、执行配置修改或启动后台任务。新增管理路由时，路由必须在
调用现有结构化管理接口之前依次完成请求约束、认证、限速、修订或确认检查，
并按操作风险落实审计失败策略；不能因为共享原语已经存在而默认开放任何写能力。
