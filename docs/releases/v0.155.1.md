# v0.155.1 正式版

> 历史发行记录：项目现已停止 npm 发行。本页保留当时的版本与流程，后续安装和更新请使用[源码安装指南](../source-install.md)。

本页为 `v0.155.1` 的正式发布准备说明。Gateway、生成协议与配套 Codex CLI 统一到 `0.155.1`，
本次集中调整配置入口、推理摘要默认行为、源码安装同步和网关时区。

## 发布状态

- 当前阶段：发布准备；本页不表示 npm 包或 GitHub Release 已发布。
- 发布类型：正式版
- Gateway 与 npm 包：`@hegenai/codexc@0.155.1`
- Codex CLI 与 App Server 协议：精确锁定 `0.155.1`
- 目标 Git Tag：`v0.155.1`
- 目标 npm 标签：`latest`
- 目标 GitHub Release：正式 Release

## 新增

- 启动卡分别显示 App Server 时区配置和网关实际时区，便于核对运行环境。
- `codexc timezone --gateway` 与系统设置菜单支持网关时区：未设置时跟随 App Server，
  也可选择系统时区或自定义 IANA 时区。

## 修复

- 修复源码与 npm 全局安装之间的 Codex CLI 版本同步，避免 Gateway 与配套 CLI 版本不一致。
- 首次执行本版 `codexc update` 时将用户主配置的推理摘要设为关闭；记录完成后，后续更新保留
  用户重新选择的值，独立 Profile 不变。
- 无效的已保存网关时区可以通过命令或菜单替换；新值写入和网关启动继续严格校验。
- 网关使用独立时区时，修改 App Server 时区仍会触发网关重启以刷新启动卡；CLI 和 WebUI
  同步提示 App Server、网关及 WebUI 的重启要求。

## 改动

- 精确协议基线升级至 `codex-cli 0.155.1`，同步生成类型、CI、支持矩阵与上游资料索引。
- 日常 Codex 用户偏好与 Gateway 设置集中到 `codexc config`，`codexc setup` 保留 Provider、
  渠道和项目技能接入；设置结果区分新会话读取、新启动 TUI 读取和服务重启。
- 推理摘要与渠道思考状态默认关闭；两者分别由 Codex 用户设置和 Gateway 展示设置控制。
- 删除旧 `/responses/compact` 代理路由，旧端点请求明确返回 404；压缩沿当前 Responses 通路
  执行，并继续按压缩请求类型记录指标。
- 随配套 App Server 获得压缩失败保留输入、MCP 认证与取消、Thread 恢复与 Revert 设置保留、
  Goal 空续跑阻塞等上游修复。完整采用与不采用范围见
  [升级决策记录](../codex-cli-upgrade-decisions.md#01551)。

## 兼容与升级

发布完成后，使用精确配套版本安装或升级，并重启服务：

```bash
npm install -g @openai/codex@0.155.1
npm install -g @hegenai/codexc@0.155.1
codexc service restart all
codexc doctor
```

- 源码安装使用 `codexc update`；首次更新会覆盖主配置原有的推理摘要选项为 `none`，需要摘要的
  用户可更新后在 `codexc config` 中重新开启，后续更新保留该选择。
- 网关默认跟随 `codex.timezone` 配置，不查询 App Server 进程的实际时区；启动卡的 App Server
  字段明确标注为配置值。选择系统时区时沿用网关运行环境的时区。
- 修改 App Server 时区后，App Server、网关与 WebUI 均需重启；托管网关通过配置监听自动重启，
  直接运行的网关需重新执行原启动命令。WebUI 独立运行时使用 `codexc service restart webui`。
- 新增上游协议类型不代表已接入业务能力；本次不新增实时语音、设备用户验证、Thread attachment、
  memory v2 管理或官方 daemon 生命周期入口。

## 发布边界

README 与安装文档已为目标版本准备。按[正式发布流程](../codex-cli-upgrade.md#5-正式发布)，
先合并至 CI 通过的 `main`，再在该提交创建并推送 `v0.155.1`。Tag 触发的 `publish.yml` 会执行
版本校验、完整提交门禁与干净源码安装冒烟，通过后发布 npm `latest`。

npm 发布成功并核验目标版本后，使用同一 Tag 创建 GitHub Release。准备发布文档、推送普通分支
或合并 PR 均不会触发 npm 发布；不得移动已有 Tag 或覆盖同版本 npm 包。本流程不自动安装本机包、
重启服务或部署。
