# v0.148.0-fix1 修复预览版

`v0.148.0-fix1` 是 Codex Connect Gateway 基于 `v0.148.0` 的 npm 修复预览版。
它不升级 OpenAI Codex CLI 或 App Server 协议，仍要求精确的 `codex-cli 0.148.0`。

## 发行渠道

- npm 包：`@hegenai/codexc@0.148.0-fix1`
- npm 标签：`fix`
- Git Tag：`v0.148.0-fix1`
- `latest`：发布预览版时仍保持 `0.148.0`；验证完成后可把同一包提升为 `latest`，无需重新发布。

## 新增

- `codexc setup` 新增统一的“Codex 用户设置”入口，可集中查看和写入默认模型、思考等级、
  Fast、沙盒权限、审批策略和 Workspace 网络权限。
- 支持一次确认后批量写入全部用户级设置；批量写入沿用 App Server 配置版本检查，不覆盖并发修改。

## 修复

- 修复 `codexc remote --profile <第三方 Provider>` 在部分调用形式下回退到 OpenAI 主实例的问题。
  规范 Profile 名称和 `sf-` 配置文件前缀现在会解析到同一个第三方 Provider 实例。
- 修复第三方 Provider Remote 启动时无显式权限参数便覆盖 Workspace 权限的问题。Remote 现在按
  “命令行显式参数 → Workspace 显式权限 → Codex 主配置或 Provider 配置”的顺序继承权限。
- 修复 Gateway 修复版与 Codex CLI 版本长期共用一个版本号造成的发行阻塞。Gateway 可使用与
  锁定协议相同基础版本的 `-fixN` 后缀，同时安装器、Doctor 和升级检查继续以协议文件中的
  `codex-cli 0.148.0` 为准。

## 改动

- Gateway 包版本和运行时版本更新为 `0.148.0-fix1`；协议生成版本保持 `codex-cli 0.148.0`。
- npm 发布工作流对 `-fixN` 版本使用 `fix` 标签，正式版本继续使用 `latest`。
- README 分开显示正式版与修复预览版，避免把预览包误写为正式版或误导用户安装不存在的
  `@openai/codex@0.148.0-fix1`。

## 安装与验证

先确保 OpenAI Codex CLI 保持正式基础版本，再安装修复预览版：

```bash
npm install -g @openai/codex@0.148.0
npm install -g @hegenai/codexc@0.148.0-fix1
codexc doctor
```

发布完成后也可以通过 npm 标签安装：

```bash
npm install -g @hegenai/codexc@fix
```

建议重点验证：

1. `codexc remote --profile custom-<Provider ID>` 和对应 `sf-custom-<Provider ID>` 配置能进入同一
   Provider App Server，并在 `/status` 中显示正确的模型提供商。
2. 在已配置 Workspace 中启动 Remote，确认 `/status` 的 Directory、Permissions 和网络设置符合
   Workspace 或用户配置。
3. 运行 `codexc setup`，确认“Codex 用户设置”可以分别保存单项设置，也可以一次写入全部设置。

## 兼容与回滚

- 不包含数据库 Schema 迁移，不需要单独执行数据库升级命令。
- 不改变现有 Provider 凭据文件、Workspace Registry 或渠道配置格式。
- 如需回滚，只需重新安装正式版；用户配置和业务数据无需回退：

```bash
npm install -g @hegenai/codexc@0.148.0
codexc service restart all
```
