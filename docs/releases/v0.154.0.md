# v0.154.0 正式版

`v0.154.0` 是 Codex Connect Gateway 对应 `codex-cli 0.154.0` 的正式版。它把 Gateway、生成协议、
App Server 合同与 npm 包统一到同一正式版本，并收录本地指标、Provider 生命周期、WebUI 和渠道展示的
一轮收口与修复。

## 发布状态

- 发布类型：正式版
- Gateway 版本：`0.154.0`
- Codex CLI 与 App Server 协议：精确锁定 `0.154.0`
- Git Tag：`v0.154.0`
- npm 包：`@hegenai/codexc@0.154.0`
- npm 标签：`latest`
- GitHub Release：正式 Release

## 新增

- 接入符合官方账户权益的 Luna Reserve 自动回退：普通用量耗尽后可在当前 Session 切换到
  `gpt-reserve`，普通用量明确恢复且用户未手工改模时安全切回原模型。
- WebUI 增加本地 Token 活动热力图、用量趋势图和账户手动刷新，并补全 Gateway、App Server、
  Workspace 与本地数据的设置入口。
- 支持配置 App Server 客户端身份与模型上游 `User-Agent`，并在 Doctor、WebUI 和逐请求指标中展示
  实际生效来源；默认身份与官方 TUI 行为保持一致。
- 全局空闲释放可停止受服务管理的主 App Server 和 Provider 隔离实例，下一次消息、Remote 或恢复
  会话时按需拉起。

## 修复

- 修复 OpenCode Go 五小时滚动窗口因重置时间漂移导致本地 Token 漏计的问题，并统一五小时、七天、
  月度额度窗口在渠道完成卡、账户状态和 WebUI 中的归属口径。
- 修复完成卡片会话累计模型请求数、Token 和缓存命中率缺失，以及 Telegram 会话自动解除通知中的
  恢复命令和排版问题。
- 修复 Fork 的 Workspace 权限继承、主 Provider 切换确认范围、删除最后一个 OpenCode Go 账户后的
  配置恢复，以及旧空 `api_providers` 配置阻断源码更新的问题。
- 修复 WebUI 本地指标写入失败阻断完成事件、账户刷新互相覆盖、范围切换混用新旧数据和设置确认状态
  不一致的问题。
- 飞书 Node SDK 更新到 `1.73.3`，纳入应用取消、WebSocket 关闭与重连、端口保留和畸形入站帧处理修复。

## 改动

- 自定义 Provider 统一使用 Codex 官方模型目录；DeepSeek 与 OpenCode Go 改为目录驱动的模型和上下文
  窗口管理，不再写入 Gateway 自定义自动压缩阈值。
- 删除本地模型价格、费用、均价、峰谷档位和币种换算展示，保留官方额度、余额、Credits 与本机 Token
  统计；OpenCode Go 用量不再显示金额。
- 删除远程指标中心、Cloudflare 示例和同步链路，统计数据只保存在本机；指标数据库升级到 Schema v14，
  删除价格、成本、旧计时列和派生 View。
- 删除直接 API Provider 预留管理链路、账户快照查询服务和已结束迁移期的 `/section` 命令；非空旧
  Provider 配置继续失败关闭，不做隐式迁移。
- 收窄 Application 会话合同，并拆分 Bootstrap 组合、Provider Runtime、管理路由、Surface 格式器、
  Provider Proxy 指标观察和指标 Store 端口；跨模块行为与公开命令保持由既有合同约束。
- npm 发布内容改为显式列出运行时所需脚本，减少不参与安装运行的源码进入 tarball。

## 兼容与升级

- 必须使用精确的 `codex-cli 0.154.0`；旧 CLI 不受支持。
- 从 npm 安装或升级后，必须重启 Gateway 与全部 Provider App Server：

```bash
npm install -g @openai/codex@0.154.0
npm install -g @hegenai/codexc@0.154.0
codexc service restart all
codexc doctor
```

- 源码安装用户运行 `codexc update` 时，更新流程会处理旧远程指标中心配置、可重建的会话展示缓存和
  自动生成的空 `api_providers = []`；非空 `[[api_providers]]` 仍需先备份并手工删除。
- 旧指标库必须通过 `codexc metrics upgrade` 在停机、检查点和私有备份后事务重建为 Schema v14；
  不支持的 Schema 不会隐式迁移。
- 监管协议已升级，更新后必须执行 `codexc service restart all`；旧 DeepSeek 模型名不再存在时会按
  受控升级路径回到当前官方目录中的可用模型，升级后应重新确认模型选择。
- Luna Reserve 失败消息不会自动重放，Reserve 期间重启也不会猜测原模型；需要时重新发送消息或手工选模。

## 发布边界

正式版必须在已合并且 CI 通过的 `main` 上按
[`Codex CLI 升级流程`](../codex-cli-upgrade.md#5-正式发布)执行：README 先同步正式安装命令，
再创建新的 `v0.154.0` Tag。npm Trusted Publishing 成功后才能创建同版本 GitHub Release；不得移动
或覆盖已有版本的 Tag 与 npm 包。
